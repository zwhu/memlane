# 连续场景验收

把需求、当前候选和证据对应起来，减少反复准备环境；不同问题仍独立判定，不因共享场景合并失败计数。

## 确定要证明的范围

读取需求、影响说明、候选输入摘要和已有验收／缺陷记录。列出本轮需要证明的完整用户操作及受影响回归，复用未受影响且版本条件仍成立的证据。尚无影响分析时，只补本轮必要的依赖判断，不自行扩展为全项目审查。

选择相关正常、拒绝、取消、恢复、返回、撤权、迟到回执或重启路径，不机械展开所有组合。明确数据变化与不变量。检查上游是否有真实产物可供下游验证；夹具可以验证交互，不能替代自动采集、实际处理或知识质量。

## 先检查前提，再执行场景

发现并复用项目的测试、IPC、实际窗口和采证入口。已有编排工具时调用它；没有时使用现有命令，不为了应用本Skill另建框架。

进入重型虚拟机或真机验收前遵循分层前置原则（具体命令与退出码从项目工程规范读取）：
- **本地无 Mock 契约冒烟前置**：纯 CLI 协议、状态机、锁竞争与迁移逻辑，先在隔离临时目录用真实二进制/本地服务快速拦截，不拖到重型 VM 阶段暴露。
- **秒级 Fail-Fast 探针与白名单保护**：任何 VM/真机驱动执行前，先在数秒内探测网络/DNS/代理、磁盘余量与宿主登录态；环境前置不通立即以专用环境码退出，不盲等长超时，也不计入同一产品缺陷失败计数。严格遵守宿主登录目录与业务数据不可触碰白名单，任何清理或截图脚本严禁误删登录态。
- **非交互与实窗分层（Level 1 / Level 2a / Level 2b）**：纯协议与恢复路径走非交互 CLI 验收；实窗验收严格区分「未初始化空库下的首装向导与重启复用（2a，严禁用已初始化热库跳过向导制造假绿）」与「复用隔离热后台的常规实窗及真实宿主会话（2b）」，同版本多场景在版本指纹一致前提下复用隔离热环境，全部完成后统一幂等收尾。

按当前场景核对：环境／数据根和所属标记、实际可执行文件与完整依赖、源及包版本、服务身份、授权代次、夹具实际数据状态及有效滚动点。前置不成立就阻断依赖步骤，记录为准备／方法问题；不要清空、重种或换根冒充原问题已修复。

合并相关场景的环境准备、候选构建与证据采集，步骤仍保留独立结果。运行前明确所属资源和幂等收尾，使用项目规定的资源门禁；不操作其他任务或日常服务。仅执行已授权范围，既有授权不重复询问。

失败、超时或写入结果未知时保留原操作、部分结果与证据，不静默重试或改换执行者。先核对任务真实状态和项目重试／停止规则，再决定下一步。任务句柄缺失不单独证明后台退出。

## 审阅证据与失败归属

- 命令退出0只证明命令完成。实际打开需要视觉判定的截图，核对数据、来源及操作回执；证据必须对应当前候选和本轮真实条件。
- 分开记录源码测试、协议夹具、实际服务／模型、实际窗口和发布包；有限样本不外推整体质量，来源标记不自动证明真实生成。
- 对失败记录触发条件、现象、验收标准、版本和证据，关联已有具体缺陷。页面、测试命令或功能名称不能作为同源依据；根因未知也不意味着全部同源。
- 方法错误、独立回归分别追踪；新ID或新版本不清零同一缺陷次数。同一轮多个断言不重复计次。纠正归类保留原记录及依据。
- 从项目规则读取停止阈值；达到阈值后停止该问题及确实依赖它的步骤，整理证据、必要收尾并汇报，不以诊断或换路径继续尝试。

## 收尾与交付结论

检查本轮所属进程、服务和资源的实际退出／保留状态；构建产物保护到后续消费结束。中断或硬杀留下的未知要明确记录，不能宣称收尾已完成。

在现有账本按要求更新“未实现／已实现待验／已验证”（或项目等价状态），附证据、偏差、未证明范围和下一步。功能、视觉、完整包分别判定，全部必要条件满足后才交用户验收。
