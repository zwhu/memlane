# UI 优化产品方案：知识阅读

日期：2026-11-13。状态：本 session 的阅读优化提案，未实施。配套：[规格](reading-ui-spec-20261113.md)、[技术方案](reading-ui-technical-plan-20261113.md)。

## 问题与目标

用户截图中，列表和详情标题直接显示 `text_<hash>`，正文顶部显示 dataset／document UUID，知识正文包含 `Lesson-Type`、`State-Key` 和 `Session learning (...)`，出处直接显示 session ID。用户需要辨认知识内容，这些技术信息占据了主要阅读位置。

目标是用最低实现成本让列表可区分、正文易读、出处可理解。沿用浅蓝侧栏、紧凑三栏和最小1200×820；不重做页面结构或图谱，不扩大到另一 session 的总览开发。

## 对话依据与本版方案

用户询问最低成本方案；讨论过“先显示知识＋日期，点击后才生成标题”的限制。**本版采用当前页自动读取缺标题正文的提案**，避免要求用户逐条点击。这个选择是在对话建议基础上形成的规格，不写成已经实施或已经逐项验收。

| 内容 | 产品行为 |
| --- | --- |
| 列表标题 | 官方有可读标题就使用；缺失时自动从当前页正文提取第一段首句，不调用 AI |
| 加载过程 | 先显示“知识 · 日期”，后台逐条补齐标题；用户不需点击；单条失败不挡其他条目 |
| 详情标题 | 与列表采用同一规则，完整知识留在正文；截取的标题不称 AI 摘要 |
| 正文 | 只隐藏已识别的官方固定包装，保留实际内容、Markdown、代码和语言 |
| 技术信息 | UUID、生成文件名、Lesson-Type、State-Key、完整session ID 收进默认折叠的“技术详情” |
| 出处 | 显示“来源会话”及可靠日期，保留“查看原始记录”；不知道会话标题就不编造 |
| 复制 | “复制知识内容”复制当前可见的清理后正文；“复制原文”在技术详情中保留原始文本 |

英文内容保持英文，不额外翻译或润色。自动读取仅限当前页及当前屏幕已有最近知识，不遍历整个知识库，不写回官方名称、不持久化正文副本。

## 示例

原来列表：`text_5d0ae455...`。改善后可显示正文首句截取：`docs/development.md documents config/daily-runtime...`。该例说明规则所得结果，**不承诺自动变成“开发环境启动与配置说明”这样的中文概括标题**。

详情的阅读区域保留标题、时间和知识正文；来源卡片显示“来源会话 · 11月12日”。用户需要排查时再展开技术详情查看原始ID与机器字段，来源跳转仍使用真实官方身份。

## 成本与范围

全部在 Go/MyGo 展示层完成，复用官方列表和 raw读取，不增加模型调用、额外索引、数据迁移或官方插件改动。新增成本为没有标题的当前页条目的只读请求，采用有限并发、进程内缓存和切页取消。

失败和未知格式保留可读占位／原文，不凭正则误删用户内容。后台补标题不改变顺序、选择、滚动、分页或知识数量，不将访问失败显示成空知识。

## 与其他工作关系

[项目权限管理](project-access-product-plan-20261113.md)负责访问和内容操作；本部分只改善已获准读取内容的呈现，不能因优化标题扩展读取范围。[总览方案](overview-product-plan-20261113.md)独立拥有统计、热力图与动态；其最近知识可消费同一标题结果，但本 session 不改其布局或算法。

当前截图和设计稿仅作为问题与视觉基线；本文没有制作新原型或通过实际 Native 验收，也不恢复开发。
