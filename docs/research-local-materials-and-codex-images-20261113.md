# 本地材料导入与 Codex 会话图片保留调研

日期：2026-11-13。状态：官方文档调研、当前插件与模型端点静态核查，以及本机一条含图会话的结构检查；未实施新功能，未进行图片采集到 Native 展示的端到端验收。

## 结论

Cognee 支持主动导入文件、文本和网页 URL，包含文档、表格、源代码、图片及音视频；具体能力取决于版本、已安装的 loader 和模型配置。引擎支持不代表当前 Memlane 已开放对应入口。

Codex 自身的原始会话可以包含图片数据。本次在本机一个真实用户消息中确认 `input_image` 块及 `image_url` Data URL，因此不能将“当前未同步到 Cognee”解释为“Codex 原始记录没有图片或地址”。

当前官方 Cognee 插件 1.8.0 的对话提取逻辑主要保留文字，没有将用户图片块作为独立附件同步。Memlane 的“原始记录”来自 Cognee 实际保留的内容，不是 Codex 原始 JSONL 的完整副本。原图保留、图片解析和图片展示需要分别核实，不能因其中一项存在就推导全链路已具备。

## Cognee 官方材料支持范围

依据本轮查看的 [Loaders 官方文档](https://docs.cognee.ai/core-concepts/further-concepts/loaders)、[多媒体处理说明](https://docs.cognee.ai/guides/multimedia-audio-image-processing)及 [API 文档](https://docs.cognee.ai/api-reference/introduction)：

| 类别 | 常见输入 | 处理边界 |
| --- | --- | --- |
| 文本与笔记 | 粘贴文字、TXT、Markdown、JSON、XML、YAML、LOG | 读取文字；不是所有结构化文件都会自动转成业务模型 |
| 文档 | PDF、DOC/DOCX、ODT、RTF | 依赖对应 PDF/文档解析组件；扫描件效果需另验 |
| 表格 | CSV、XLS/XLSX、ODS | CSV 与 Office loader 的处理路线可能不同；不等于保留电子表格全部行为 |
| 演示文稿 | PPT/PPTX、ODP | 提取内容，不等于还原版式和播放效果 |
| 网页、邮件、电子书 | 网页 URL、HTML、EML/MSG、EPUB | 需要对应抓取或文档组件；URL 支持不代表能读取任意需登录站点 |
| 源代码 | TS/JS、Python、Go、Rust、Java、Vue 等 | 当前官方文档提供代码 loader；本机固定版本能力须单独核对 |
| 图片 | PNG、JPEG、WebP、GIF、TIFF、HEIC 等 | 视觉模型转写；可选本地 OCR 补充识别文字 |
| 音频 | MP3、WAV、M4A、FLAC、AAC、OGG 等 | 需要支持转写的模型端点 |
| 视频 | MP4、WebM、MOV、MKV、AVI 等 | 文档描述的是音轨转写并附时间戳，不等于理解视频画面；部分容器需 ffmpeg |

Office 等格式通常需要 `cognee[docs]` 或 `cognee[docling]` 等可选依赖。以上是查询时的官方文档范围，没有据此安装组件、下载模型或验证本机全部格式。

低层处理链可表述为 `add → cognify → search`：材料接收、知识处理和检索是不同环节，不能把上传成功直接计为知识生成成功。当前文档也提供 `remember/recall` 高层入口，后续接入按本机固定版本核对，不因文档演进自行切换接口。

## Codex 图片实际保留情况

### 原始会话：确认存在内嵌图片数据

本轮只读扫描了本机 2026-11-13 的最多 13 个会话 JSONL，仅输出字段结构，不输出聊天正文、图片字节或 URL 内容。在其中一个用户消息中发现：

```json
{
  "type": "input_image",
  "image_url": "data:<省略图片数据>",
  "detail": "<省略>"
}
```

上例是脱敏结构示意，不是可用图片。`image_url` 在该样本中为 Data URL，即图片数据内嵌于记录，不是普通 HTTP 地址，也不是本地文件路径。私有原件保留在本机 Codex 会话目录；未将原件、完整文件名、图片内容或聊天内容复制到仓库。

该证据只证明至少一个真实会话如此存储，不能推导所有 Codex 客户端、版本、贴图方式和历史记录都使用同样结构，也没有执行图片解码及显示验证。

### 官方插件：文字提取没有保留图片块

核查对象为本机已安装的官方插件：`~/.codex/plugins/cache/cognee-local/cognee/1.8.0/`。关键代码如下：

| 代码位置 | 本轮观察 |
| --- | --- |
| `scripts/_coding_memory.py::_block_text` | 列表内容只拼接 `text`、`input_text`、`Text` 块或字符串；没有提取 `input_image/image_url` |
| `scripts/_coding_memory.py::parse_codex` | 读取 `event_msg` 中的用户/Agent 消息，以 `_block_text` 提取正文；跳过本次发现图片的 `response_item` 记录类型 |
| `scripts/store-user-prompt.py::main/_store` | 从 hook payload 的 `prompt` 保存文字；普通模式的 context 包含 cwd、model、turn_id、transcript_path，没有附件字段 |
| `scripts/store-to-session.py::_store_assistant_stop` | 普通模式保存问题、最终文字回答和 context；这不是完整原始会话复制 |
| `scripts/store-to-session.py::_store_tool_call` | 可保存经过策略过滤、脱敏和截断的工具输入输出；工具参数中的图片路径可能作为文字留下，但不等于保存原图 |

因此，即使 Codex 原始文件有图片，当前对话提取路径也没有把这些图片块转换为 Cognee 图片附件。上述是源码判断，未逐项核对本轮含图样本最终写入的 Cognee 对象。

图片地址若恰好出现于提示文字、工具输入或回答中，可能作为文字进入记录；不能因此承诺所有图片都有可用地址。`transcript_path` 只表示会话文件位置，也不等于附件本身已经同步或能够长期访问。

### Memlane 模型端点：当前只接收文字

仓库代码：[codex_completion_endpoint.py](../engine/python/codex_completion_endpoint.py)。请求转换逻辑只接受字符串或 `type=text` 的内容块；非文字内容块返回 `codex_messages_invalid`。向 app-server 发起 `turn/start` 时也只构造文字输入。

因此还存在独立的模型能力缺口：即使将图片交给 Cognee，也不能直接认定当前 Memlane 的 Codex completion 适配已能承担官方 ImageLoader 的视觉请求。需核对官方图片请求协议、模型配置及适配范围后再做方案。

## 对用户体验的影响

例如用户贴报错截图，Codex 回答错误原因并给出修复方案。当前链路可以从被保存的文字中提炼经验，但截图里没有被文字描述的错误码、布局或其他细节不能保证留下；当前也不能承诺从 Memlane 原始记录直接重看该截图。

需要清楚区分三个对象：

1. Codex 自己保留的原始会话及图片块。
2. 官方插件抽取后写入 Cognee 的会话内容。
3. Memlane 从 Cognee 读取并展示的原始记录与知识。

本次纠正此前表述：“自动采集未保留原图”不等于“源会话没有原图”。后续应先研究能否通过官方采集方案补齐附件，不要求用户为同一张已有图片再次上传，也不直接新增并行采集器。

## 本地材料导入的交互候选

以下为对话中的初步建议，尚未成为产品规格：

- 在项目页拖入文件，或通过“添加材料”选择文件、粘贴文字/图片、输入链接；默认归属当前项目。
- 提交前显示材料清单、归属和处理提示；实际可用格式由已安装能力决定。
- 材料归入原始记录，提炼结果归入知识，并建立可靠的双向来源关系；文件页码、图片位置等只在有真实证据时展示。
- 后台逐项呈现接收、读取、提炼和可检索状态；部分失败不遮蔽已成功项。
- 明确相同材料去重、内容变化和更新行为；复用官方能力，缺口先说明，不自动建设第二套内容存储或索引。
- Codex 会话图片与手动图片使用一致的材料语义，分别保留原图、来源会话和派生文字/知识的关联。

“添加后自动提炼”与“仅保存、稍后处理”仍待决定。原图保留周期、更新/删除传播、批量行为、费用提示和支持格式也尚未定稿。

## 下一步研究与验证问题

1. 固定官方版本是否已有会话附件采集、附件对象和来源关联能力；优先核对官方方案及可上游修复的位置。
2. Codex 各输入路径的图片结构：剪贴板、文件附件、本地路径、工具读图、纯图片提问；是否存在内嵌数据、外部 URL 或临时文件。
3. 从原始记录找到图片后，能否可靠关联到具体 turn、项目和 Cognee 会话；不可只凭顺序或相似文字拼接。
4. Cognee 当前固定服务的图片存储、去重、原件读取及删除行为，是否足以支撑客户端直接预览。
5. 官方 ImageLoader 的实际请求与当前 Codex 模型端点之间的协议缺口，以及视觉解析是否需要单独配置。
6. 完整验收应覆盖：贴图/添加材料 → 官方采集/入库 → 原图可读 → 文字提炼 → 来源回跳 → 重启后仍可访问，并保留重复提交、附件失效和部分失败场景。

本轮没有执行以上新实验、服务启停、索引或模型调用，也没有增加产品验收失败轮次。历史暂停范围、运行依赖保护及同一问题停止计数继续有效。
