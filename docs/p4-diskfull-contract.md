# F1d 受限磁盘真实故障验收契约

2026-11-08，真实App磁盘写入故障、释放后的当前检索、长文展示恢复及最新完整包独立复验通过，完整状态见 [F1d验证](p4-diskfull-validation.md)。基线为F1c1/F1c2本机恢复链路与schema14，见 [恢复验证](p4-restore-validation.md)。本切片覆盖真实文件系统空间耗尽，不用SQL触发器、返回ENOSPC的函数夹具或全机磁盘写满替代。

## 输入与授权路径

只使用新建 `memlane-p3-code-app-*` 标记合成根和新App身份。受信本机服务根为该目录的 `client/data`；在此位置挂载自己创建的128MiB APFS磁盘映像，组件/模型仍在同一合成根的 `client/runtime`，占用的宿主磁盘不随测试无限增长。映像文件、mountpoint、设备节点和卷名先写入本切片manifest，校验实际mountpoint仍为明确的合成data根；不修改已有用户库、日常Agent配置或其他卷。

App仍使用完整helper/LaunchAgent/Agent桥与真实Rust0.0.3、本机模型；不调用云模型或升级Agent。所有项目原文/编辑与故障填充文件均为本轮合成材料。填充文件只写 `client/data/explicit-diskfull-filler.bin`，明确不是知识、独立出处或组件。

## 操作与完成标准

正常准备后在真实App内保存/编辑并检索合成当前版本，再保存一致性备份。记录SQLite完整性、当前版本、历史、索引状态和文件系统可用块。逐块写入受限卷的唯一填充文件，直到真实系统调用返回空间不足；必须记录errno及实际挂载设备、statvfs，不能根据写入数量猜测已满。

空间不足下，App保存、索引和备份按实际发生的阶段分别判断：没有持久回执不显示保存成功；持久原文成功而索引失败时保留原文并明确索引状态；备份不发布不完整目录为完成记录。不能要求每次小写入必失败，SQLite/WAL已有分配块可能被重用；要以真实请求/回执及当前版本作判定。负例核对具体错误和继续操作，不把任意错误当作磁盘满证明。

只删除明确的填充文件释放空间，有限等待APFS可用块回收。解除后核对原文/来源/版本/历史与完整性；App重试使用原草稿，不重复产生同一成功版本；索引重试与当前Rust检索闭合，备份与正常服务仍可用。源库和旧备份始终保留。跨App退出的草稿及未完成UI操作ID不持久化，不将重启后新建备份描述为同ID重放。

大编辑只用于迫使实际SQLite/WAL增加分配；若正文未在既有索引窗口内完成，保留失败报告和已接受版本，另外显式编辑较短当前版本以验证正常检索。不能把较短版本的检索通过写成大正文索引通过；大版本必须留在历史中并核对SHA。单独的实际私有IPC备份请求用于获取具体系统错误，报告须明确它与App操作的区别。

列表预览仅显示前240字符；详情、原始出处、历史、恢复预览与差异长文按UTF-8边界分段，每段约8192bytes。分段仅影响阅读，复制全文、编辑、恢复及存储继续使用完整正文；来源、版本和有效知识不因阅读分页改变。普通短正文保持原显示。

## 清理与限制

失败也先删除本切片填充文件，让停止状态能够写入；通过真实停服等待worker和两层owner退出，再关闭App。检查无设备使用者后卸载manifest记录的本切片设备，核对mountpoint已不再指向该卷。卸载或停服失败使验收failed；不卸载未知设备、不使用强制全局清理。报告保存fixture、映像/设备/mountpoint、异常阶段、回执、恢复、清理与真实窗口证据，只引用产物，不复制用户知识或认证。

本机脏环境/ad-hoc包及受限APFS卷只证明本切片的真实空间故障。后台许可撤销、其他worker/服务崩溃、App移动/同身份更新、正式签名/公证/渠道及干净macOS15+arm64仍独立验收；不将本测试称为正式分发或真实宿主磁盘满通过。
