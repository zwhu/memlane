# 第一版实施清单

执行依据：[技术方案](technical-plan.md)、[产品定义](product.md)、[设计决策](design.md)。当前 P0 核心工程流程已通过真实合成数据验证；尚无真实 Agent 接入或记忆管理 UI。2026-11-07 用户明确要求停止旁白等旁支验证，以主流程走通为本轮标准；VoiceOver未通过，移到后续增强，不伪称通过。证据见 [P0 验证记录](p0-validation.md)。

先完成 P0 的运行与打包验证，再实现界面与真实数据；首个使用里程碑是 **Codex 写入项目经验 → App 查看/编辑 → pi 在同项目检索到当前版本**。阶段是依赖顺序，不是工期承诺。

### P1.2：补齐界面所需的数据与服务接口

- [ ] 复用现有 `store.Apply/Current/MarkIndexed/Resolve`、持久任务和 worker，不重做已经通过的原文索引链路。

- [ ] 为服务增加分页列表、历史版本、索引状态与活动查询；保留 `apply/get/search` 的既有语义，UI 通过类型化 IPC 调用，不直接读 SQLite。
- [ ] 用户可在 App 中登记项目或选择全局范围。dataset UUID 由服务映射，页面切换使用对应范围；真实 Agent 的连接授权与工作区识别留到 P2。

**通过标准**：UI 能读到真实列表、正文、来源和状态，分页不重复或漏项；迁移前后的已有正文与版本保持一致。尚未保存或未索引不能显示成成功。

### P1.3：打通 App 内记忆管理

- [ ] 新增和编辑接入真实服务，提交预期 revision；保存成功后展示最新正文，索引进度独立显示，失败有可用的重试入口。
- [ ] 搜索接入真实检索，按当前项目与允许的全局范围返回可追溯当前版本；索引中、无结果与服务故障分别展示。
- [ ] 右栏提供历史与修改差异，恢复旧版使用栏内确认并追加新 revision；旧页面的保存遇到冲突时不能静默覆盖。
- [ ] 使用合成数据在真实 App 完成“新增→详情→编辑→搜索→历史→恢复→重启读取”；补齐服务中断时草稿保留与错误状态的关键路径。

**通过标准**：用户不借助验证脚本即可完成该闭环；正文、历史与搜索一致；关闭重开不丢已保存内容；恢复不会改写历史版本。

### P1.4：首页接入真实活动并收口

- [ ] 从首次可用事件生成每日热力图和最近新增，点击日期进入对应列表；保持原始输入、初始化导入与新增知识的统计区别。
- [ ] 编辑、恢复、重复回执和重试不重复计数；删除或归档后保留历史活动事实，并在详情体现当前状态。
- [ ] 未实现的整理建议区显示真实空态/不可用说明，不用示例建议冒充结果；建议生成和处理仍在 P3 完成。
- [ ] 核对数据为空、有数据、准备中、索引失败四类界面，更新实际截图与 P1 验证记录；执行受影响测试和完整客户端构建。

**通过标准**：首页数值与活动记录一致，视觉与选定设计一致；主包、组件下载量与磁盘占用继续分别报告。P0 已通过且未受改动影响的更新、生命周期和系统输入法检查不整套重跑；VoiceOver 等已移出的旁支不重新加入本阶段门槛。

**通过标准**：同一条记忆连续编辑和恢复后，列表、详情、搜索一致；重启后正文与历史仍在；索引失败不丢保存内容。

- [ ] 统一 MCP/CLI 契约；连接 ID、工作区绑定、范围白名单、来源和错误类型。

- [ ] 项目/worktree 映射，默认检索当前项目＋全局；其他项目显式授权。

## P3：整理、审核与后台执行

- [ ] 后台 Agent 适配，先验证 Codex 的结构化任务，再验证 pi RPC；独立会话、受限工具、取消、超时、认证/额度失败。
- [ ] Cognee 所需模型请求桥接；显式本地 embedding，防止调用链递归或意外切换云模型。
- [ ] 立即整理 → 新摘要/标签与提案 → 右栏差异 → 确认/拒绝/过期；任务、attempt 和应用结果完整记录。
- [ ] 项目经验原文复制到全局、AI 提炼预览后保存；原始来源保留。
- [ ] 定期整理计划、休眠补跑去重、单并发与异常恢复；退出 App 后仍可执行。

**通过标准**：未确认的修改不会改变有效知识；旧 revision 的提案不能覆盖新编辑；取消后的结果不应用；重复回执不重复新增或计数。
