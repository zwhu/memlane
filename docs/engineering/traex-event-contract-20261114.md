# TraeX 事件时间与解释器契约

MA-TRAE-TIME01：新增定向契约检查首次发现prompt_time为空，修复后通过；此前尚未执行真实CLI问答验收，不虚增CLI失败轮次。

官方remember_pending_prompt把时间写入内部ts，但pop_pending_prompt只返回prompt与context。旧薄适配从pop结果读取ts，得到空字符串；固定SDK的QAEntry只接受有效时区时间或null，且没有turn_id时旧answer事件键还会退化成固定值。

修复继续复用官方pending存储：在其context中保存本次提交时间及宿主turn_id（缺省用本次时间作事件标识），取出后恢复；QA与trace分别记录hook收到事件的UTC时间，不把缺失的旧时间编造为历史时间。覆盖无turn_id的连续两轮、唯一事件键和有效时区时间；缺回答不读transcript的规则保持。

另补两项源码缺口：TraeX hooks使用准备时已绑定的绝对Python路径并按shell规则引用，不依赖用户默认python3；PI与TraeX/helper在明确的处理会话标记下提前跳过，不产生采集或召回。pi只采集正常stop的最终回答，toolUse中间说明、截断与错误不冒充最终问答。

来源元数据复用官方git_root/git_head/git_branch：提示开始记start_commit，回答记录end_commit、cwd、日期和分支，不读取历史transcript；拒绝采集时撤下该轮元数据。新增真实Git前后提交边界检查，不声称commit包含尚未提交的工作区修改。原Codex插件和用户默认Python环境均未修改。
