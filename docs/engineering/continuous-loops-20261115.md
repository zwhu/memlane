## 共同执行契约

- 开始前读 AGENTS.md、product/design、当前精简版错误索引及同版JSON、workflow、当前相关交付记录。跨模块实施使用 plan-change-impact；集成验收使用 verify-continuous-scenarios；缺陷诊断使用 diagnosing-bugs。首次使用时通知用户。按现有模板记录连续用例、影响、证据及失败次数。
- 先核对 git status 和活跃任务。共享工作区已有大量未提交代码，不覆盖、还原或提交他人改动，不全仓快照。变更共享文件先通过线程消息取得当前所有者交接；无法确认时只读并推进独立部分。禁止调用 sys-ai-retro。
- 三个循环共用原子目录锁 `.local/continuous-loops/action.lock`：任何生产源码/共享账本修改、重型测试、模型任务、服务启停前以 mkdir 原子获取；成功后写 owner.json（loop、thread、时间、动作），动作期间持有，结束仅由持有者删除。读取到存在锁即退让，绝不按超时强删。锁只协调这三个任务，不能替代其他会话的所有权交接。各自独立记录无需锁；读取共享账本并更新必须在锁内。必要时仅向已明确参与本需求的循环线程发送协调消息，不向其他人发消息。
- 改动前固定候选摘要与文件所有权。必要的生产清理前检查点只包含本任务明确拥有的相关代码，按现有技术方案创建本地提交及注释tag；存在混合所有权时先交接，禁止夹带他人代码、私有配置、真实数据或凭据。
- 三个循环保留同一个具体问题编号及历史累计失败次数。发现跨循环同一问题，指向原负责循环，不重复修复或验收。累计第4次同一问题验收失败即停止该问题实现、实验和重跑，完整报告；其他独立问题继续。已有达到阈值问题仅整理证据，未经用户明确恢复不试探。
- 只用同一套当前日常官方存储；不另建/切换运行库，不自动迁移、补采、重放历史，不伪造知识、召回或统计。未知写入/模型提交只核对原操作，不盲目重发。真实集成尽量使用已有已授权材料及自然新增数据；不得为了循环而反复产生无业务意义的知识或模型请求。
- 复用当前环境和脚本。检查/验收经 scripts/task.py，Go使用 scripts/go.sh；启动、重开、停止经 scripts/dev.py。先核实运行配置、所有者和在途任务，未取得服务所有者交接不重启。保护完整包及其运行依赖。至少100 GiB空闲、运行门禁105 GiB，不足停止重型动作；不打包、不release、不下载新模型、不切换模型/供应商。
- 不以源码测试代替真实集成、知识质量或实际Native验收。UI工作先打开当前设计图，在用户指定外接显示器实际对照。不能看图/操作窗口则注明未验，不调整已认可设计范围。
- 无新增证据不重复刷报告。每轮记录候选版本、范围、耗时、发现/修复/待验、原问题次数、进程及临时资源收尾。严重问题、阈值停止及影响用户的数据风险及时在所属任务汇报。临时资源仅清理本任务确知无消费者的部分。
