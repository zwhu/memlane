# App 对齐巡检与侧栏收口

用户要求：“你把整个App都点一遍看看，哪些没对齐的”；随后指定“这个边框全部去掉，项目旁边的... 要放到项目中，浮动上去才会展示”。本轮沿用verify-continuous-scenarios，检查日常dev实例实际页面，结合当前源码核对内边距，不改后台、模型、ACL或真实内容。

## 侧栏最新行为

“全部数量”“＋”“⋯”改为透明、无边框控件。“⋯”追加到官方SidebarItem内部，原有图标和项目名继续由官方组件构造，选中背景覆盖整行。无悬停时Opacity=0并IgnoreInput，保留布局空间；行悬停或按钮获得键盘焦点时显示。菜单内容及项目身份保持，菜单弹出后仍可选择编辑／项目设置。

CUA已核对默认静止状态没有独立按钮边框、没有常驻“⋯”，项目名与原有导航左边界一致。工具没有独立指针Move接口，真实Native悬停展示未单独作结论；SDK Tester通过真实指针Move进入行后点击菜单，原项目设置及返回用例覆盖交互。

## 验证与缺陷留痕

- 原项目列表多边距问题按用户本次触发记1轮，与此前侧栏右边界问题分开；统一修正后实际Native确认页签文字、数量、列表文字和底栏均在32线上。
- 侧栏新布局首次实现误在已初始化SidebarItem后改Key，SDK panic；改用Context.Key，保留为SDK使用准备错误。
- 随后的旧菜单测试直接点击未悬停的隐藏按钮而失败；按新交互先Move再点击后通过，属于旧夹具与新要求不匹配，未放宽隐藏行为。
- 实窗发现SidebarItem.Children为追加而非替换，额外空标题Grow导致图标和项目名偏到中间；该独立回归失败1轮。恢复官方图标／标题，仅追加菜单后实窗确认恢复正常，不与原右边界问题合并。
- `sh scripts/go.sh test ./internal/simpledesktop -count=1 -timeout=120s`在上述修正后通过。后台服务所有者复核仍为原61088；只关闭了无配置的额外GUI窗口，未启停服务。巡检过程中其他源码热重载多次使窗口状态重置，已按最新AX重新定位，没有把失效元素ID视为业务缺陷。
