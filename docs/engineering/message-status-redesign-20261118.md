## 产品规则与 UI

项目设置的原“待处理内容”改为“消息与处理状态”，宽度沿用900px。两个垂直分区：

1. **需要你处理**：仅已证实的权限拒绝、用户主动暂停后有明确未发送消息等，显示对象、影响和可执行入口。权限同步结果未知、插件变更不凭空推为需授权／重新登录；归属冲突没有安全选择接口时显示系统异常，不伪造选择按钮。
2. **状态与异常提示**：按会话展示待保存和保存结果未收到的数量、状态读取失败、后台故障与记忆整理状态。标题旁明确“无需确认保存结果”；异常持续显示，不用归档抵消计数。历史归档文件保留作证据，同一条未知仍在当前异常里显示。正常空状态不显示0份文档卡。

行内布局：单色图标、标题与状态tag同行，下面是来源Agent／会话、原因、系统实际处理和紧邻文字的操作。禁止右边遥远的独立操作列。任务累计数字仅作诊断，不代替当前消息数。不把任务完成说成全部消息保存完成。不以整批任务运行推断某条旧未知正在确认。

明确处理：checking才显示正在查询；original_receipt_unavailable说明旧记录缺少唯一保存凭证，目前不能自动核实，也不会重发，属于Memlane缺陷。网络原因没有结构化证据不猜。读取失败不等于未保存。仅在已有自动保存运行证据时说后台继续发送。

详情按需展开：会话完整标识、上次检查时间、原因与已知消息标识；Python插件支持只读按需查看前20条本机待保存消息摘要（每条最多240字符），不落盘、不写日志；常规轮询仍只读计数和hash。没有正文支持的宿主明确显示缺口，不伪造内容。

## 影响与连续验收

- 纯状态投影：队列／检查／后台任务／实际权限 -> 分组、文案和操作；不通过Agent实时判断，不新增第二状态库。
- Native：项目设置、侧栏异常点同一口径；保留原文阅读、权限编辑、后台任务及迟到回调身份校验。
- 保存引擎幂等重试仍是独立未解决缺陷；本轮不假称已修复、不执行未知重投。
- 用例：正常空；积压；无权限；权限同步未知；主动暂停；未知等待/检查中/服务读取失败/旧回执缺失；已归档但未解决；整理失败/等待；900px和宽屏紧凑排列；状态恢复自动移除；详情读取不发送内容。
- 源码分类测试、UI交互及几何测试 -> 全量Go test/vet -> 当前dev真实窗口只读检查。日常服务与UI watcher复用，不打release包，不重新运行模型/整理/存量补交。
