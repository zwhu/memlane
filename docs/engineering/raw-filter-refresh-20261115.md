# 原始记录筛选缓存不一致

2026-11-15，问题编号 RAW-FILTER-REFRESH01。用户反馈同一条今天的会话在“会话”中出现，在“全部”中未出现，随后又恢复显示。本次反馈计1轮；没有把历史闪烁、标题或后台保存缺陷合并计数。

## 目标与已证原因

“全部”应包含同项目的会话和原始文档，切换筛选后应重新核对官方列表，保留有效阅读位置。

客户端 `routeKey` 包含 kind，各筛选持有独立 pane。`switchProjectKind` 原先仅在目标 pane 尚未 Loaded 时调用 load，因此旧“全部”快照可能长期保留，而首次进入的“会话”已读取新内容。两种筛选的会话均来自同一官方 sessions 接口，使用同一时间排序逻辑。

定向测试通过实际 switchProjectKind → load → projectRecords 路径复现：预先缓存只含昨日记录的“全部”，官方接口已有今日记录 → 切至“会话”能读取今日记录 → 切回“全部”没有刷新，测试报 `all filter reused stale cache after session filter saw today's session`。此复现不依赖后台保存延迟或系统时钟偏差。

原始截图瞬间的请求与缓存时间没有被记录，因此不能证明当时后台同步时延为零，也无法断言用户后来通过哪一个动作让条目恢复出现。

## 修复与检查

- 切换至已缓存筛选时也调用现有 load 重新核对官方元数据；刷新期间保留已有内容、选择和滚动，沿用取消、epoch及request代次保护。
- 没有增加周期轮询、修改时间戳、补采或重放会话、写入官方数据，也没有启动模型或索引。
- 新增 `TestRawFilterReturnRefreshesCachedAllWithoutDroppingReading`，修复前红、修复后绿；同时通过原切换取消／保留pane、合并排序分页、刷新失败保留阅读检查。
- `sh scripts/go.sh test ./internal/simpledesktop -count=1` 通过（3.969秒）；`sh scripts/go.sh vet ./internal/simpledesktop` 通过。检查均经现有task门禁，可用空间约109 GiB。
- 实际窗口已能读取，但观察期间页面在非本次操作序列内切到图谱，未建立受控的完整筛选往返证据；不将源码检查写成Native验收通过。窗口变更来源未确认，本次不启停共享服务或争用窗口。

修复限于筛选重新进入时的刷新，持续停留在一个列表中不新增自动刷新。首次定位运行中新增记录可使用现有刷新按钮。

## 防复发

独立筛选可以分别保存选择与滚动，但“曾经载入”不能代表内容仍然新鲜。切回筛选时需要重新核对数据；回归场景必须覆盖旧筛选缓存 → 外部新增 → 新筛选可见 → 返回旧筛选。
