# 待整理文档查看与返回回归

场景ID：`QUEUE-DOCUMENT-READ-RETURN`。需求基线：用户2026-11-15要求修复并保留可重复回归能力。根因、实际修复与历史失败计数见[原始账本](settings-density-and-dcim-sync-20261115.md#daily-cli待整理查看连续路径分析仅分析)。

## 一条命令运行

```sh
sh scripts/regress-project-queue.sh
```

复用现有Go/MyGo测试及`scripts/go.sh`的资源门禁。每次生成独立的`.local/regressions/project-queue/<UTC时间>-<PID>/`，保留测试JSON事件、stderr、源码SHA256、基线提交和合成界面截图；不覆盖上轮证据。退出0表示下列自动断言通过，非0需查看该轮证据，不自动重试。

使用临时HTTP服务及合成数据；不读取日常库、不启停日常服务、不修改Agent配置、不调用模型，不生成或删除真实知识。

## 实际Native连续核对

需要验证真实服务或视觉时，使用已有dev窗口；先核对日常运行配置及数据根，不由测试脚本打开额外GUI。窗口最小1200×820。

1. 进入目标项目设置，滚动到待整理区域，记录项目、条目数量和滚动位置。
2. 确认会话中间材料不会作为独立文档待办出现。历史daily-cli误报对象属于`user_sessions_from_cache`；数据保留不变，修复后待整理0份是分类纠正，不表示它完成了一次新整理。
3. 如果有真实独立待整理文档，点击“查看”：仍在该项目设置内，显示原文、状态和项目近期处理；不得出现普通文档列表0条或“不在当前页面”。
4. 检查复制原文、刷新状态和读取失败的重读入口。复制必须保留完整原文；刷新只读，不触发保存或整理。项目级任务成功不得被当成本文档完成。
5. 返回待处理内容，确认同一项目、分页和滚动位置保持，再次进入仍是同一文档。
6. 根据变更范围补查切换项目、身份/权限变化时撤下正文、网络失败及清单变化。当前专用自动用例未覆盖所有这些故障注入，不能只凭Q01–Q04将其标为通过。

真实环境没有独立待整理文档时，不创建真实材料来凑验收；记录“分类已验证、详情用合成UI验证”的边界。2026-11-15修复验收即采用此边界。

## 缺陷与停止规则

沿用`QUEUE-READ-CATALOG01`、`QUEUE-READ-CONTEXT01`、`QUEUE-RETURN-SCROLL01`，既有失败各1轮，不因本脚本或新运行目录清零。夹具身份、布局不足或HTTP准备失败单独记录。出现失败时保存本轮目录，按触发条件与预期关联具体缺陷；同一缺陷累计第4次仍失败即停止并汇报，不自动开始第5次。
