# 项目持续异常通知与知识未读

2026-11-16。用户：“1. 如果一直无法处理的消息才需要通知 2. 项目中产生的未读知识可以展示吗”。按plan-change-impact/verify-continuous-scenarios实施，dev阶段，保留所有历史数据、归档标记与失败计数，不触发模型或图谱。

## 范围与验收

短暂读取失败先后台重试；同一具体问题连续失败至少3次且持续至少2分钟才显示侧栏异常点，恢复成功撤下。按文档状态/具体宿主会话分别计时，不将不同失败混成持续故障。普通待保存/待整理数量仍可在项目设置查看，但不主动作为侧栏通知。

未读知识用独立数字提示，不与待处理数量相加。已成功读取正文的人工选择才标为已读，列表标题预取、后台轮询、Agent召回不改变未读；返回/重开保持。首轮旧知识基线通过可选问题征询，默认启用后新增才提示；历史阅读动作没有可靠记录，不反推旧知识是否已读。只存知识ID/已读状态，按服务身份/project/dataset隔离。

复用项目状态轮询已获取的官方完整文档目录，不另加全库轮询或重复索引。需验证：首次基线、知识新增、点击查看、已读减少、后台预取不清除、未读持久化、删除/撤权、切换项目迟到结果、读取/持久化失败不伪造已读，以及持续失败/恢复/不同问题轮换/正常后台积压不通知。夹具不制造真实知识或未知写入。

当前共享所有权：来源阅读线程正在滚动加载Native验收，暂不编辑Go触发热重载。它已允许badge/nav区、overview.go和queue结果接线，来源文件保持。拟以publishOverviewTitle的选中正文成功路径接入已读，等待其来源文件/Native交接。
