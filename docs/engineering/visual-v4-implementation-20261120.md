# 视觉 V4 Native 实施记录

2026-11-20 建立。依据：[视觉规范 V4](../ui-redesign/visual-standards-v4-20261120.md)，以及[可交互原型](../ui-redesign/visual-v4-prototype/)。本文是实施账本，按阶段更新进度和证据。

## 1. 目标、验收与不做范围

- **目标**：Native 全部页面按 V4 的令牌、布局和动效重做；支持浅色和深色两套外观，跟随系统；项目页由瀑布流卡片改为三栏，带「分类／仅未读／排序」筛选和「本次召回」筛选条。
- **验收**：
  - 在实际 Native 窗口（1200×820）中，浅色和深色两套外观都与原型对照，结构一致、令牌值偏差在 2 DIP 以内；
  - 「减少动态效果」打开后，所有动效都直接到终态；
  - 下面这条连续流程在真实数据上走通：首页 → 点一条记忆 → 进入三栏并选中这条 → 筛选 → 读完后未读数减少 → 回到首页 → 点召回动态 → 显示「本次召回」筛选条。
  - `sh scripts/go.sh test ./...` 和 `python3 scripts/task.py -- python3 scripts/lint.py` 通过。
- **不做**：
  - 不改数据、接口、采集链路或 Cognee；
  - 不做 release 打包；
  - 不内嵌字体；
  - 不跟随系统强调色。

## 3. 关键未知与第一步

最可能导致方案不成立的，是**深色加半透明侧栏在真实窗口里的表现**：根主题能否切换、自定义主题能否重建、透明页面加不透明内容能否做到、`Antialiased` 补丁在深色下的表现。令牌模块的结构取决于这一步的结果，所以先做最小探测：

1. 外观来源改为可配置。默认跟随系统；开发时可以用环境变量 `MEMLANE_APPEARANCE=light|dark` 强制指定外观，方便在不改系统设置的情况下验收两套外观。
2. 新建令牌模块：按 `c.Theme().Dark` 返回浅色或深色调色板；先只接入外壳，也就是侧栏、标题栏和内容区底色。
3. 窗口开启 `VibrancySidebar`，去掉浮起的白色面板。
4. 在实际窗口中截取浅色和深色两张图，核对上面三项。

探测通过后再全面铺开；如果失败，就在本文记录具体缺口，再改用其他方案（例如侧栏改用不透明的 sidebar 令牌色）。

## 4. 开发顺序与回归

1. **P0 探测**（见第 3 节）。
2. **P1 令牌与基础组件**：字体 6 级、颜色、间距和圆角；列表行、分类标签、召回标签、未读点、下拉菜单、开关、标签栏、空态。逐文件替换 `ui.Hex`。
3. **P2 外壳**：侧栏的结构和行为（「全部 N」「＋」、点未读进入时打开「仅未读」）、标题栏（页面操作和全局搜索）。
4. **P3 首页**。
5. **P4 项目三栏**：替换瀑布流，加入筛选工具条、召回筛选条和键盘切换；首页点记忆时直接定位到这一条。
6. **P5 其余页面**：通用记忆、用户画像、设置、搜索结果、首次启动、弹窗。
7. **P6 动效**：选中块、页面和列表入场、热力图生长、落入、角标跳动、空态视差，并核对「减少动态效果」。
8. **统一验收**：按 [verify-continuous-scenarios](../../.agents/skills/verify-continuous-scenarios/SKILL.md)，在真实窗口中走完第 1 节的连续流程，两套外观都要截图留证。

需要回归的既有行为：
- 未读状态的读写和侧栏角标；
- 召回次数尚未确认时，「按召回次数」不可选；
- 召回筛选里出现「暂不可用」条目时的提示；
- 项目设置入口；
- 按 dataset 路由项目，不按名称；
- 设置页的 `Segmented`／`Modal` 契约；
- lint 规则 ML001–ML007。

## 5. 需要保留的内容与停止边界

- **不改的部分**：数据、存储，以及 `.local/daily/official-store`；
- **测试**：会断言视觉参数的旧测试，必须随新令牌一起更新，不得删除断言了事；
- **停止规则**：同一个具体缺陷累计 4 次验收不通过，就停止该缺陷，按[停止规则](workflow.md)汇报；
- **dev 窗口**：dev 窗口会热重载，它连接的是日常库，所以只改界面层，不在验收中执行写入操作。
