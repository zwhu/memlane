# 消息提醒的操作与黄点闭环

2026-11-19，用户明确要求每项提醒给出可操作按钮，包括确认、刷新、知道了或不处理，并说明如何消除黄点。本次要求覆盖此前“不让归档抵消提醒”的展示限制；保存结果与异常事实仍保留，旧归档不自动等同本次知晓。

## 目标、影响与连续用例

限定项目设置的消息提示和侧栏黄点。明确未发、已获写入许可且后台状态已成功读取、无运行或未明原因的暂停任务时提供“开始保存”，沿用项目保存任务范围；已有恢复、补交、权限入口沿用。读取／后台异常提供“重新读取状态”。每项系统提示提供“知道了，不再提醒”，用户事项提供“暂不处理”；点击后保留整项并标注“不再提醒”，可“恢复提醒”。刷新只以实际读取结果更新异常；启动接受不等于保存完成。

知晓只写客户端状态，按服务身份、项目和dataset隔离，仅存散列、时间及用户选择，不含正文或会话ID，不改官方存储、消息队列、任务、绑定、权限或模型配置。只结束当前具体异常提醒：同数量的新消息标识、新任务或新原因需重新提醒。一次知晓不能清除其他独立问题；全部当前异常已恢复或知晓才撤下黄点。读取失败保留之前已知未知写入并提供对应按钮；存储失败保留提醒且明确反馈。旧历史归档不自动迁移。

连续验收：黄点→逐项知晓→仍有独立异常保留黄点→全部知晓撤下→刷新同一问题不再亮→重建UI加载仍不亮→同数量不同消息/不同任务再次亮→恢复提醒重新亮。另核对刷新失败不清除、客户端写失败不清除、服务及dataset隔离、原材料与操作回执保留、正常待保存的安全按钮、真实Native布局和行内反馈。

实现接线：message_status.go、project_queue_ui.go、project_queue_badge.go、project_queue.go及新的message_acknowledgement.go。复用既有后台保存API和原子本机写入方式，不新增内容库。开发磁盘78GiB满足50/55GiB门禁；不启动模型、整理或日常补存验收，不更改其他会话的设置页修改。已有MSG-KEY01、MSG-RECEIPT01及旧无凭证问题计数保留；本次仅处理提醒语义，不恢复旧具体停止问题。
