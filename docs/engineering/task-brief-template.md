# 任务影响与验证说明

方法见 [plan-change-impact](../../.agents/skills/plan-change-impact/SKILL.md)。本文件仅作Memlane填写适配，直接写入现有任务／交付账本；小改动可简化。设计基线引用当前已认可交接，命令沿用task.py与项目驱动，失败轮次引用既有缺陷记录。

## 目标与影响

- 用户最终完成的连续流程、验收标准与明确不做的范围：
- 产品／设计基线；需要保留的已有行为及数据：

| 要求 | 受影响页面／模块／数据／授权／运行组件 | 上下游依赖及已证／未知 | 证明完成所需证据 | 状态与证据位置 |
| --- | --- | --- | --- | --- |
| | | | | 未实现／已实现待验／已验证 |

## 执行顺序

- 最可能使方案无法成立的未知，以及优先验证它的最小步骤：
- 为什么优先做此步骤（接口／运行时、整页结构、迁移等按实际风险选择）：
- 连续场景与前置检查，复用的环境、入口和采证工具：
- 需要用户参与的依赖及可独立推进部分（已有授权不重复询问）：
- 已有具体缺陷、累计失败轮次、停止范围与关联账本：
- 产物／进程／合成根的所有者、后续消费者、保留方式与允许清理时点：

新证据推翻依赖或影响判断时更新本说明，再调整顺序；不要每轮重复改写工程规范。
