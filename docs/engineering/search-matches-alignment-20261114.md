# 搜索结果类型与页面对齐

用户反馈：搜索“测试看看”时列表出现会话ID、脚本等内容，要求核对查询与结果，并明确“两种都需要，标注出来”；随后要求侧栏与正文统一对齐。

## 搜索核对与实现

官方CHUNKS为语义召回；本次只读重查指定项目得到29个片段，其中0个包含“测试看看”。这不能解释为关键词命中。固定官方CHUNKS_LEXICAL也会保留零分top-k，直接使用其返回条数仍会误标关键词结果。

当前搜索弹框复用官方CHUNKS_LEXICAL及CHUNKS两路；仅可见标题／正文包含全部输入词的结果标为“关键词匹配”，语义通道其余结果标为“语义相关”。同一官方片段去重，保留dataset、chunk及source document身份，不写入新知识或索引。顶部显示当前内容分类下两类数量，每条显示匹配类型及实际返回片段；关键词摘要截取实际命中附近。会话ID和固定学习头只在展示层去除，原文不改。

已证独立缺陷：输入新查询后旧Rows保留，而Submitted在发起请求时便变为新签名；旧结果可能被展示为新查询结果。现在防抖或请求中不显示旧Rows，查询签名不同也不展示。未修改Agent召回模式。

实窗已核对“测试看看”：界面显示“关键词匹配0 · 语义相关34”，每条可见语义标注与实际片段；此数量为当时Native全部关联范围，不是前述单项目重查数量。没有证明这些语义候选的相关性质量提升，本次修正的是来源、匹配类型及呈现准确性。

## 对齐

正文统一32 DIP内边距；顶栏原先在projectHeader末尾被12／18覆盖，删除覆盖，沿用统一32。侧栏品牌与状态原为26，导航及项目图标原为22；通过Sidebar外侧18加官方条目内侧8统一到26附近，设置入口同步调整。保留官方组件与现有功能。

`TestOverviewHeaderUsesContentInsets`直接检查顶栏标题左边与搜索框右边均为32；现有两尺寸列表顶底对齐与独立滚动检查保留。最后实窗用户正在操作项目设置，只读核对了共享顶栏及侧栏，没有打断处理任务；最终首页标题的32 DIP对齐由实际UI布局测试证明，未额外宣称最终首页截图验收。

## 侧栏右侧操作列补验

用户再次指出“这就是对齐了？”：原项目分组头左右各8内边距，而项目行没有外侧内边距，导致“＋”比“⋯”向内缩8 DIP。前次“已统一”的结论遗漏了操作列，不能保留为完整通过。该右边界问题按原对齐反馈累计2轮失败；不重置计数，也不合并其他空态或搜索问题。

分组头保留左8、右改0，“＋”和每项“⋯”明确统一28×28，采用同一右侧操作列。新增`TestOverviewSidebarActionsShareRightEdge`对可见项目菜单与新增按钮作右边界及宽度检查（SDK将被滚动裁掉的项置为零尺寸，不用于几何比较）。实际Native截图确认加号和两个项目菜单的按钮左右边缘一致；顶部选中导航也使用同一右边界。本轮未操作权限、保存队列或后台服务。

该用例初次将被裁掉的零尺寸菜单也作边界比较而失败，已排除无可视几何的项，属于夹具方法修正，不增加产品失败计数。
