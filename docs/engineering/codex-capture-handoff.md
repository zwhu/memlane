# Codex 日常采集与开发入口交接

更新：2026-11-12。本文汇总当前状态；历史尝试、首次失败和逐阶段证据继续保留在[实施账本](codex-daily-capture-20261111.md)，不以本摘要覆盖。

## 当前行为

- 电脑级连接与明确采集授权后，通过 UserPromptSubmit / Stop 保存用户及助手原文，不依赖模型主动调用保存工具，不自动启动整理。
- 接受本机已观察的 Codex CLI 与 Work / Codex Desktop 来源。两者可能共用配置、以 source=vscode 上报，但 originator 不同；不能仅靠界面外观、品牌或版本判断覆盖范围。版本仅诊断，能力与真实协议决定可用性。
- 未登记仓库的材料先本地保留。总览发现仓库后，用户可添加项目并关联原始记录，或暂缓；确认只建立当前授权下该仓库原文的自动归属，不增加 Agent 知识读取权限。
- 原事件、原文队列、保存回执分开记录。来源未经核实的辅助标题/自动建议事件不进入项目；原文保留不等于已保存，索引状态单列。未知来源修复后可按原身份恢复，不扫描历史或要求重说。
- 后台补送与窗口共享队列锁。窗口列表、原文及归属预览遇 delivery_busy 时有限等待（最多1秒、间隔25ms），随视图生命周期取消；其他错误继续显示，不绕过锁或授权。

## 开发与用户验证

```sh
python3 scripts/dev.py --daily-agents
```

首次复用已有索引组件时，可加 `--worker-config /绝对路径/已有服务配置.json`；后续入口复用自身保存的组件路径，索引始终位于独立开发库。需保留引用的组件及完整运行包。默认不带 `--daily-agents` 则使用隔离 Agent 配置目录，见[开发说明](../development.md)。源码改动自动重载 GUI；daemon/CLI 修改需重启自有dev入口。当前日常接入指向开发服务，不能把关闭开发服务后尚在暂存的材料视为已入库。

blog 首次确认入口：总览 → 发现 zwhu.github.io → 添加项目 → 阅读原文及范围 → 添加项目并关联原始记录。无需重发已保留测试。此操作由用户在 App 确认。
