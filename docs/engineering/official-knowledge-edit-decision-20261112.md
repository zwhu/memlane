# 官方知识编辑与历史：最小决策项

当前Goal要求官方数据为主，并在编辑／历史缺口影响产品承诺前提交最小决策，不能静默删功能或另造镜像库。本页只提出决策，不执行内容写入、迁移或能力删减。

## 已证事实

- 当前运行服务的OpenAPI提供`PATCH /api/v1/update`，但未提供文档逐版全文历史或恢复接口。名称含history的现有路由是搜索历史删除和Slack导入／同步，与知识编辑历史不同。证据：`build/conversation-official-20261112/official-document-contract-001/write-history-routes.json`。
- DataDTO有当前ID、正文下载、更新时间和内容hash，没有客户端可用的文档版本序列。官方直接读取已用合成材料验证；未验证官方编辑后的完整版本恢复。
- 旧Memlane实现已有编辑、历史和恢复；相关旧内容和版本均保留，不能因新读取接口接通就覆盖或删除。旧库盘点仅覆盖报告所列数据库，不能外推整台电脑没有编辑历史。
- 官方知识与原始材料继续由官方存储管理。新增客户端全文历史库不是本轮默认方案。

## 三个可选边界

1. **新官方知识暂只读，旧知识保留完整编辑／历史**：先接通官方浏览与出处，在界面明确新来源尚不能编辑；不伪造可用的编辑／历史按钮，不隐藏旧数据及其有效版本。后续另行完成官方写入与版本方案。这需要用户明确接受新官方知识的暂时限制。
2. **新官方知识可更新，明确没有逐版恢复**：使用官方update更新当前正文，每次编辑明确其覆盖语义；旧历史继续保留，新内容不承诺服务没有的版本恢复能力。需要用户接受此产品能力差异；本页不授权自动更新任何已有内容。
3. **先评审基于官方存储的完整版本方案**：在新知识编辑交付前，明确版本／恢复如何由官方数据承担、如何避免重复索引，以及旧版本如何核对迁移；不先建客户端镜像库。方案和实际验收未完成前不宣称完整版本能力。

当前尚未选择任何方案；旧读取、编辑及历史保持。真实Codex隔离登录与hooks信任为另一独立待办，不因本决策自动获准或完成。
