## MA-UI-CONNECT-UNKNOWN01

验收标准：准备／启用请求丢失响应后，原操作编号在窗口重开后保留；只能核对原回执，不隐式安装第二次。批量取消保留已完成项，仅停止尚未开始项；已连接、未检测到、准备中、冲突及需核对项不能因陈旧选中状态再次准备。

失败累计1轮：定向 httptest 让 prepare 返回503，原 Native 只保留内存错误；新 App 无任何待核对操作。日志 `connection-journal-initial-20261114.log`。此缺陷与既有 Provider 未知写入问题分别记录，不合并旧停止计数。

实现：准备／启用发送前复用0700目录、0600文件的原 UI 回执持久化与fsync，内容限原编号、类别和实例标识；不存key、表单、消息正文。类别隔离后，同名 Agent ID 与 Provider profile 也不会相互阻塞。原响应成功并核对实例身份才清理回执；GET `/v1/connections/operations/{id}` 只返回保存的原回执，管理身份以外拒绝。缺失／unknown保留，不能把“没有记录”推断为请求从未到达。原安装状态核对仍沿已有独立入口，不把文件存在改写成原请求成功。

连接页与实际发送前共用同一资格判断。已准备项只能显式启用；未知／冲突项先核对。每个批次按最新服务目录核对，取消在当前项结束后停止，不撤销成功项。卡片显示原宿主名称，不展示内部实例hash作为主文案。

定向复验覆盖 prepare/activate 丢失响应、重开、缺失回执保留、成功回执只读恢复、请求前已写持久编号、批量取消及陈旧选中状态，并通过 race。既有 Provider 回执格式保留。

实际1200×820 Native：多选 pi／TraeX／Claude；pi后台真实完成不可变产物准备后丢弃成功响应，TraeX当前项完成后取消，Claude尚未开始。窗口重开仍显示pi原操作；核对后准备POST仍为2次。只选剩余Claude后总POST为3次，三个产物摘要均核对通过，待核对本机记录归零。使用实际控制代码／Registry／GenerationStore及真实文件系统准备，但主体、凭据、内容服务为合成，不等于新增真实宿主信任、采集或模型验收。全程未启用宿主插件、未调用模型。CUA实际截图及AX已观察，未导出仓库PNG。[脱敏证据](evidence/multi-agent-development-20261114/native-batch-recovery.json)。

第一轮Native夹具缺少存在的绝对host HOME，两次准备均在安装前拒绝；保留两个unknown操作，取消后第三项未执行。这是1轮方法前置错误，不作为产品成功，也不增加本产品缺陷计数。补全HOME的新独立夹具继续成功路径；原轮目录、回执及证据未清除或重发。
