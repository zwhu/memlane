## 优先问题

以下按对首次任务的影响和修改成本排序。阻塞指阻塞对应已确认流程的验收，不等于所有已有功能不可用；可延后项不阻塞当前手动记忆链路。此次没有仅凭个人审美提出阻塞项。

### DES-01｜首启完成后仍强制引向项目，缺少 Agent 优先与跳过入口

- **类型／结论：可用性问题，同时偏离已确认流程；阻塞 Q1–Q3 首次使用验收；高置信度。**
- **现象与位置：** 04 的标题说明、三步指引和主按钮都要求先选项目，主按钮为“选择项目并开始记录”；05 点击后直接打开“添加本地项目”表单，没有先选 Agent 或跳过项目的动作。07 即使从导航进入 Agent，也需选择本地项目且连接按钮不可用。
- **用户影响：** 用户完成本机准备后仍须理解和登记仓库，才能继续接入；与用户明确提出的“第一步不知道做什么”问题相同。无法按已确认的“先选 Agent、项目可跳过”完成首次业务选择。
- **设计原理：** 首次流程主按钮应承接用户眼下的决定。前置条件只在需要它时出现，不能把后续范围管理作为第一个必答题。
- **修改方向：** 将 ready 页的主要动作和承接页面统一为选择 Agent；后续项目选择明确提供跳过路径，并继续展示必要授权与验证。首任务完成后才以实际记忆及出处给完成反馈。不能只改按钮文字，连接流程也须能承接无既有项目的状态。具体授权规则沿用已确认契约，不在本报告新增设计。
- **依据与定位：** `docs/product-questions.md:16`、`:26`、`:32`；快照 `internal/desktop/first_launch_presentation.go:346` 的 ready 页面和后续 footer 路由。02 中“准备完成后选择真实项目”的说明也应同步。

### DES-02｜项目页辅助信息占据首屏，正文来源和列表扫描空间不足

- **类型／结论：规范偏差，伴随阅读效率问题；可延后；高置信度。**
- **现象与位置：** 09 中项目标题在全宽项目头和中栏再次以大标题出现；“立即整理”独占整行，排序选择和解释再各占一行。右栏短正文后立即展开“使用记录”的覆盖时间、四类统计、两段解释与标记动作，范围和原始出处被推到更下方，原始出处正文在首屏底缘已经不可完整阅读。
- **用户影响：** 打开一条短记忆，用户仍需往下寻找可信来源；中栏真正的知识列表开始较晚。新功能累加到了同一阅读路径上，削弱了紧凑工具界面的扫描效率。
- **设计原理：** 空间分配应随当前阅读任务排序；正文、范围和出处是判断知识是否适用所需的信息，使用统计属于后续管理信息。
- **修改方向：** 项目头保留一次主标题；列表头把数量、紧凑的整理入口和筛选合并为少量行，排序规则按需解释。详情先排列正文、范围／版本／索引状态和出处，将详细使用统计降为摘要加展开入口或移到出处之后，保留真实统计和口径。
- **定位：** 快照 `internal/desktop/browsing.go:193`、`internal/desktop/app.go:492`、`:709`；`internal/desktop/usage.go:91`。调整布局后需同时复看短正文、长正文与带多个实体的条目；本轮没有执行修改。

### DES-03｜设置页中栏缺少设置内容，右栏入口列表挤压主要设置

- **类型／结论：可用性问题和信息架构偏差；可延后；高置信度。**
- **现象与位置：** 20 的中栏只有“设置”、一句概述和“从列表选择记忆查看正文、来源与历史，或新增一条记忆”，与设置任务不符；大块中栏空置。右栏顶部五个居中文字入口逐行排列，使“本地组件与更新”到右栏接近中部才出现。
- **用户影响：** 想找服务控制、组件或退出选项的用户先看到记忆操作提示，再从右侧若干相近文字入口向下找。三栏占用了空间，却没有提供有效的设置导航。
- **设计原理：** 栏位应承担稳定、可理解的职责。沿用三栏时，中栏应帮助选择设置范围，右栏承接相应内容。
- **修改方向：** 以现有设置内容组织中栏分类，将接入、初始化记录、整理计划、本机环境等已有入口合并为清楚的导航项，右栏展示当前分类。移除设置页的记忆空态提示；保持服务启停和退出选项在对应分类内直接可见，不增加新设置功能。
- **定位：** 快照 `internal/desktop/app.go:993` 的通用空态提示与 `:996` 的设置内容。

### DES-04｜小号次要文字与可点击文本过浅，状态和操作不易辨认

- **类型／结论：可访问性与可用性问题；可延后，但不是单纯审美；高置信度。**
- **现象与位置：** 01 的 Agent 状态、02 的返回／查看检查详情、10 的查看全部／管理计划、13 的返回详情／恢复 v1、20 的设置入口均使用浅灰小字。多个可点击动作与说明文字视觉接近。
- **证据：** 快照 `internal/desktop/design.go:12` 定义常用小字 11 DIP、次要文字 `#8a9098`，`quietButton` 同用该颜色。按 sRGB 相对亮度计算，它与白底约为 **3.22:1**，与浅蓝侧栏 `#e8f0fa` 约为 **2.80:1**；这只是具体颜色对的对比度测量，不代表已做完整可访问性认证。
- **用户影响：** 在常规窗口尺寸下，状态解释和弱样式按钮容易被当作不可操作的辅助文字；较低视力或低对比显示环境中的阅读负担更大。
- **设计原理：** “次要”由字号、位置和权重共同表达，不能主要依赖降低可读性。单色也能清晰区分动作、说明与禁用。
- **修改方向：** 普通小字及可点击文本使用更深的中性色，按常规小字 4.5:1 的可读性参考复核；禁用、注释和次级操作分别设定样式。维持现有浅色和单色风格，不必引入彩色按钮。

### DES-05｜过滤结果为空时保留的详情缺少上下文说明

- **类型／结论：状态反馈问题；可延后；中高置信度，仅针对已采集画面。**
- **现象与位置：** 15 恢复后搜索标题显示“0 条当前版本”，下面仍写“1 条知识”，列表提示无结果，但右栏继续显示恢复后的条目。18 切到原始记录后显示“0 条原始记录”和空列表，右栏仍是手动新增的知识正文与编辑动作，页面没有解释它为何留在原始记录列表旁。
- **用户影响：** 用户难以判断右栏是当前查询结果、原始记录，还是之前保留的条目；两个数量也容易被理解为数据不同步。实际内容未必错误，但界面的范围说明不完整。
- **设计原理：** 保留选择上下文需要同时表达其与当前列表的关系。列表为空不应使旧详情看起来属于空结果集。
- **修改方向：** 搜索数量统一口径；若另显示全库数量，应明确命名。过滤后保留正在查看的条目时，标注“当前条目不在此筛选结果中”并提供返回知识入口；也可在用户主动切换记录类型时清空不匹配的详情。两种方案择一保持一致，不能静默混用。
- **证据边界：** QA 说明 15 在等待恢复为 v3 且 indexed 后才采集，未另做延时重复采样；本报告不据此断言该计数错位永久存在。18 提供另一种范围变化下的同类画面证据。修复前应补一次稳定态复核。

## 补充交付边界

### DES-06｜普通包缺少可执行的环境准备下一步

- **类型／结论：可用性阻断，背后涉及交付配置；阻塞普通包首次使用验收；高置信度。** 该项单列交付边界，不与上述五项视觉与交互问题混为风格问题。
- **现象与位置：** 普通包首页显示“等待本地记忆服务”和“服务未连接”；普通包设置显示“本地引擎：待准备”“当前尚无可安装的组件版本”，没有隔离配置包 20 中的本机环境准备、准备／重试和服务启停操作。用户无法从该状态继续自动准备。
- **用户影响：** 普通包能打开主窗口，但新用户无法仅依靠可见动作完成组件准备并开始使用；验收配置包的准备成功不能证明普通交付包已满足首次使用。
- **设计原理：** 未就绪状态必须回答“下一步能做什么”。只陈述不可用原因，无法形成可完成的引导。
- **修改方向／关闭条件：** 交付构建补齐真实可用的组件来源及准备路径，再用没有验收 runtime config 的普通包，从隔离空环境确认能看到准备入口、明确确认、真实进度和就绪后的下一步；失败时也要有真实可用的重试或诊断。设计报告只判定当前可见阻断，不从截图推断配置缺失的全部工程根因。

## 审美判断与本次设计原则

当前浅蓝侧栏、白色内容区、细分隔线与单色图标属于已经成立的视觉方向，应保留。本轮不要求额外装饰、扩大留白或更换风格；上述问题均有任务、规范或可读性依据。图标具体造型与轻微圆角差异可作为之后的审美微调，本次没有足够理由单列修改要求。

本次最值得掌握的原则是：**视觉层级按用户当前要回答的问题安排。** 用 09 做对照：当前是“正文 → 大段使用统计 → 范围／版本 → 出处”；调整为“正文 → 范围／版本 → 出处 → 使用统计摘要”，就能在不删功能的情况下优先回答“这是什么、适不适合我、从哪里来”。同样的原则可以用于 20：先帮助选择设置分类，再呈现服务与组件操作，减少与当前任务无关的文字。代价是详细统计多一次展开或更靠下，应通过真实窗口复核确认这个取舍。
