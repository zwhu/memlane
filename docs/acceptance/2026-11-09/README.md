## 证据与判定规则

1. 最新产品确认优先于旧计划、旧设计图与历史验收。原型、规则确认、源码实现、自动化检查和真实运行分开记录。
2. 历史证据注明其版本、环境和边界；不能仅因文档写“通过”就判当前快照通过。
3. 新运行只用本轮隔离合成库及独立 App 身份。真实 App/helper/Rust 与合成数据分别说明，不把协议夹具冒充真实 Agent。
4. 截图用于外观与可见状态；保存、当前版本和持久化需要运行断言或服务实际读回。
5. 每项问题标明影响、证据、建议与关闭条件。发布阻塞、本机使用阻塞、可延后项和未验证项分别归类。
6. 主包大小、首次准备下载量与最终占用分别报告。重用本地组件不算重新测量首次联网下载。
7. 验收过程中发现问题先保留，避免边验边改造成对象漂移。本轮不自动修复产品、改写已有验收记录或提交其他工作。
