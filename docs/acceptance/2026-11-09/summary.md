准备就绪主按钮仍为“选择项目并开始记录”，点击进入添加项目页；无项目时已发现的 Codex 也不能连接。官方任务入口同样要求已登记项目 UUID。证据为 [04 就绪](../../../build/acceptance/2026-11-09-001/testing/screenshots/04-preparation-terminal.png)、[05 项目表单](../../../build/acceptance/2026-11-09-001/testing/screenshots/05-start-use-project.png)、[07 无项目连接](../../../build/acceptance/2026-11-09-001/testing/screenshots/07-agent-without-project.png)；源码 `internal/desktop/first_launch_presentation.go:397`、`agents.go:374`、`internal/official/agent.go:41`。

关闭责任：产品明确并维护契约，交互/设计审查连续流程，客户端/接入实现，测试执行同包闭环。关闭必须证明：空根完成准备 → 选择 Agent → 跳过项目 → 明确接入授权和真实验证 → 正常首任务 → 有效材料受信建立/复用项目 → 回看本次知识与出处。连接本身无空项目，重复送达不重复创建，歧义不默认全局。首任务局部能力已有历史证据，不要求重做所有已有能力。

### B02 · P1 · 停止回执断线后，已写停止标记但服务继续存在

**证据：本轮真实 daemon 3/3＋负责人真实 daemon/Rust 组合复现。** 对应 ARCH-01。

`internal/daemon/server.go:762–786` 先持久写入停止；`:366–368` 写回执失败直接返回，跳过后续 `s.stop()`。向隔离 Unix socket 发送 stop 后立即断开，持久状态已经 `stopped=true`，daemon 仍接受 health；真实组合中 worker 仍存活、health 仍 ready。

原始证据：[架构复现](../../../build/acceptance/2026-11-09-001/architecture/stop-disconnect-report.json)、[负责人组合复现](../../../build/acceptance/2026-11-09-001/manager-daemon-limit/report.json)。架构师单层实验 worker 路径故意缺失；负责人补足真实 Rust，但组合 worker 此时已触发 B03，所以不宣称仍能成功检索或仍在执行收费任务。

关闭责任：服务所有者实现，架构审查，测试故障复验。停止意图一旦持久接受，不得依赖调用者仍在线；正常回执、EPIPE、取消、超时都要有界回收监听、worker/活动执行者和锁。补 stop/quiesce 断线回归、真实活动任务清理、重开不自动恢复；停止标记写入失败仍须明确失败。

### B03 · P1 · 引擎请求预算耗尽，服务健康状态仍返回 ready

**证据：本轮真实 Rust 0.0.3＋真实 daemon/Rust 组合。** 对应 ARCH-03、TEST-13。

worker 累计 10,000 个唯一请求 ID 后，后续 health/search/shutdown 都返回 `duplicate_id`，进程不会自行换代。daemon health 忽略该错误并返回缓存 ready。组合实测搜索错误：`search unavailable: duplicate_id: request IDs must be unique; reconnect after 10000 requests`，随后 health 仍 `ok=true,state=ready`。

证据：[组件反例](../../../build/acceptance/2026-11-09-001/manager-worker-limit/report.json)、[组合反例](../../../build/acceptance/2026-11-09-001/manager-daemon-limit/report.json)；源码 `engine/rust/worker.rs:99`、`internal/daemon/server.go:616`。App 每两秒轮询一次，按持续轮询推算约 5.56 小时即可耗尽；**没有进行五小时连续窗口实测，窗口假 ready 是源码推导，daemon 假 ready 已实证**。

关闭责任：引擎/服务实现，架构审查，测试跨限验证。消除进程寿命内必然耗尽的去重契约，或由所有者安全换代且不消费故障预算；传播真实健康错误。新 worker 归档＋新包跨越旧上限后必须仍可 health、保存索引、当前检索、取消和 shutdown，并验证 App 不误报可用。
