这里只记录已提出的后续方向，不作为当前版本的实施或验收要求。首版继续按 [产品定义](product.md) 和 [实施清单](implementation-plan.md) 完成本机记忆闭环。

## 桌面端管理其他主机的记忆

- **记录日期**：2026-11-07，用户明确提出。
- **目标**：未来可在 Memlane 桌面端查看和管理其他主机上的记忆。
- **状态**：已记录，未设计、未排期；不纳入本次工程搭建和首版实现。
- **届时再确定**：主机连接方式、身份与权限、主机和项目的展示关系、离线/断连行为、可执行的远程管理操作。
- **范围说明**：远程管理不自动包含主机之间的数据同步、合并或复制；是否需要这些能力另行讨论。

当前不为此增加远程端口、连接界面、认证协议或多主机数据模型。本机 UI 与业务服务继续按现有职责分离实现，未来在该边界上评估远程接入。

- **记录日期**：2026-11-11，用户明确提出「这些其实都是基础配置，记个配置文件会比较好」。

- **边界**：基础配置与采集授权、路由授权、运行回执及原文数据分开保存；记录路径不代表获得采集或写入授权。

## ChatGPT 普通对话采集

- **记录日期**：2026-11-12，用户明确要求「先记录todo吧」，先试现有开发模式。
- [ ] 评估并接入 ChatGPT 普通聊天的原文采集，覆盖用户消息与助手回复；与 Codex 编程任务的 hook 采集分开验证。
- **范围纠正**：此前截图仅凭外观被误判为普通聊天；随后已定位本机 Work / Codex Desktop 的真实 hook，按现有适配兼容修复处理，见[交接摘要](engineering/codex-capture-handoff.md)。本待办及下列估算仅保留为普通聊天另行接入的初步讨论，不套用到该本机编码任务。
- **第一步**：接入可行性验证，确认真实可用入口、消息身份与完成状态、授权范围及桌面 App / 网页覆盖边界；验证后重新估算工期。不得将外部应用向 ChatGPT 发送事件的能力视为聊天导出能力。
- **后续范围**：复用原文队列、去重、离线重试、索引及 pi 整理；明确会话与 Memlane 项目的关联，ChatGPT 中同名项目不自动等同于本机仓库；处理流式回复、编辑、重新生成、中断、重开及撤权。
- **讨论估算**：手动导入1–2人日；网页自动记录4–7人日；桌面 App 先验证0.5–1人日，入口可行后暂估另需5–10人日。以上是初步估算，不是已确认排期，不包含最终签名、安装包和旧 helper 迁移。
- **状态**：TODO，尚未接通或验收；用户本轮仅授权记录，不继续实施或让用户追加测试。既有 Codex CLI 开发链路保持供用户试用，不因本待办恢复旧 helper / 图谱等已停止问题。
