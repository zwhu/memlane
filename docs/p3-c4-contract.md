# P3-C4 修改建议与逐项审核契约

本切片已实现并通过真实验收，证据及限制见 [C4 验证](p3-c4-validation.md)。复用 C3 的稳定任务/attempt、冻结材料、隔离 traex、逐项结果和 C1 applyTx；不将 C3 摘要/标签正常验收扩写为修改审核通过。

## 模型输入与允许动作

新增 `memlane-organization-v2`；v1 原有字节和只接受 summary/add_tags 的规则保留。用户在 App 选择项目材料、启用修改建议，并明确勾选可建议移入的其他登记项目；默认没有跨项目目的地。快照冻结源 revision/正文/出处/原始依据与目的地 ID/路径身份。目的地授权不允许读取该项目知识，只允许提出移动；其他项目材料不进入模型输入。

v2 允许新增摘要/标签以及 merge、overwrite、delete、move、duplicate、conflict；后六类全部待审核，不产生知识副作用。每项有解释和具体引用。duplicate/conflict 只登记发现；确认仅标记“已核对”，不隐式删除、裁决或合并；用户可另选有明确目标/建议正文的 merge/overwrite/delete 建议，或重新生成。模型不得将冲突双方写成已经确定的一方规则。

- merge 引用至少两条有效知识并以全部引用知识作为归档目标；生成新知识和全部来源归档版本，用户确认前展示目标与正文。raw 不能作为被归档知识。
- overwrite 引用并指定一条有效知识目标，有非空新正文；目标和依据全量重验，保存新 revision、旧正文与出处。
- delete 指定所引有效知识目标和理由；逻辑删除追加 revision，旧索引排除，历史保留。恢复为新的 revision。
- move 指定所引有效知识目标和快照内明确授权目的地，保留正文、原项目和新项目关联。确认后同条知识追加新范围 revision，原范围立即排除；目的地身份变化即过期。
- duplicate/conflict 至少引用两条材料，展示双方具体版本和发现理由；不以排名/频率推断真伪或自动升级。

## 决定、回执与恢复

每个审核项保存固定 item_id、action/输入/结果 digest、pending/rejected/expired/applied/failed/cancelled 状态；确认/拒绝 receipt 全局唯一并绑定决定与 item digest。同 ID 异内容/决定返回冲突；重放已提交回执返回原事实，不重复正文、历史、活动或来源。来源失效不能撤销已确认的事实，但必须使未确认建议过期。

可信 App 的 typed private IPC 是唯一批准入口，日常 Agent 工具不提供批准。确认事务先重验全部来源 revision/项目/有效性、目标与目的地，再完整应用该项正文/版本/范围/出处/回执/索引队列；SQL 中途失败整项回滚，可重试同回执。网络/模型不持有写事务。取消只阻止尚未提交项，已提交保留；服务中断/重启沿用 C3 attempt 栅栏，恢复不重跑已持久结果。

自动项沿用 v1 表；新增实际审核项、决定与范围历史使用增量 schema v5 表，不重建或改写 v4 原表。迁移前由 Store 唯一拥有者一致性备份；临时 v4 库证明全部旧表、已提交 WAL、原回执与恢复合同保留。默认检索和日常读取继续检查当前范围和派生状态。

## 验收与证据

先验证结构/范围/动作拒绝、确认前不变、确认/拒绝/过期/回执冲突/SQL原子与重启恢复，再在真实 App/traex/Rust 中验证选取、生成、逐项差异与确认拒绝、跨项目授权/移动后检索、归档/历史恢复。故障/质量样本独立标注；摘要/标签旧 v1 必须保持已通过合同。证据目录 `build/p3-c4/`，验证通过后才更新实施勾选和阶段提交。

移入项目的授权只包含当前正文与当前知识身份，不包含任意原范围历史正文。受信 App 保留本机历史；日常 Agent get/status/search/保存回执以及再次整理（含原两条合并）的冻结 prompt，只有显式请求也授权初始范围时才保留 Original/SourceDetail，否则删去旧片段并标明原范围出处未授权。图谱、其他项目读取和旧正文权限不会由移动动作隐式扩大。

v2 结构化输出的所有声明字段均列入 required，非 move 项 destination 为空字符串。结果序列化在 v2 保留空字段以满足实际 provider；v1 的零值字段继续省略，既有摘要/标签字节与digest合同不变。

保存幂等请求在知识移出原范围后重放时，服务保留首次保存事实，但不能把 Current 新范围正文装入原范围回执；当前范围不在此次请求时明确返回 scope_denied。该规则同样约束未来全局复制/提炼后的当前版本输出。
