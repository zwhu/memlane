# 首屏检测与方块灯泡修正

2026-11-10。用户指出「应该是在第一个动画的时候去做各种检验」「第一个动画的还原度也不行」，本轮优先修正检查时机和动效。C 项目阅读、历史弹框与项目整理仍按对应已认可交接继续，不因本轮修正标为完成。

## 检查发生在首屏

新环境检测和恢复已保存的 Agent／记忆处理步骤，都先显示白底检测画面。在这段时间读取签名组件清单、校验已有组件与引擎／模型配方、读取系统注册和许可、检查本机 Agent，确认本机记忆服务与 Cognee 数据服务的当前健康；取得结果后才显示结果页或恢复原步骤。

就绪同时要求必要组件已校验、后台服务为实际 Enabled、本机 worker 的健康版本兼容、Cognee 图／向量／关系库健康通过。Agent 未找到或能力未知仍可随后处理，不作为环境就绪的模型／项目前置条件。已主动停止的服务不因检查自动启动；已完成环境的正常恢复仍复用既有准备拥有者。

只读 Cognee 检查调用 `GET /health`，不做 Agent 登录或 LLM 推理。检查失败停留在首屏，具体错误可重试或稍后继续；检查与正在进行的准备／停止使用同一生命周期门禁。安装后的校验与启动验证仍保留，这与首次查看已存在服务是两个阶段，不能把未安装服务写成已验证。

用户继续指出进入首页后还在检测。追查发现旧实现有两个重复入口：页面数据刷新每两秒先请求一次 `health`，独立于启动与后台可用性拥有者；进入设置时，超过15秒的环境结果又自动重新读取组件清单与文件。旧版已保存的后续初始化步骤还会先打开页面，以 `checking_availability` 等待后台回执。首屏前移后，前两个重复入口也须一并消除。

现在先配置首屏门禁，再安排页面数据读取；首屏期间不轮询页面数据，进入首页直接采用已取得的服务回执。页面读取从业务数据请求开始，不再额外检测服务，也不以数据库读取失败覆盖服务健康或调度故障诊断。后台可用性观察统一更新服务状态与调度诊断，首屏进行中拒绝其回执。

进入设置直接复用本次启动的环境结果，不因经过15秒而自动重查。新的准备过程使旧组件证据失效；「重新检查」仍明确重新读取。运行期间的后台监测继续发现停止、许可撤销和服务故障，不呈现第二轮初始化检测画面。首次缺少组件时，用户确认安装后的启动验证仍在同一准备页反馈。

## 动效还原

固定来源为 A revision 13 `e27a49e35020972d6aea4ab070ec898fb6c9c22e` 的 `a-environment.html`。Native 改用原型的51个方块空心灯泡 mask、154 DIP 画布、11 DIP 网格、7 DIP 方块、1 DIP 圆角，以及三档蓝色。

方块使用固定散开偏移 `(i*29)%91-45`、`(i*37)%91-45`，4.5秒周期和每块25ms错开，CSS ease-in-out 对应 `(0.42,0,0.58,1)`。检测期间循环散开→归整为灯泡→散开，标题与检查阶段在下方。检测完成立即离开首屏，不为了播完动画拖延真实结果。延迟开始的方块也从固定散开位置显示，避免开场闪出完整灯泡。

几何只准备一次，Key、序号与起点稳定，单个检查阶段文字变化不重播整个动画。Painter只读取标量快照，用float64计算周期，不创建任务或计费。系统／App减少动态效果和失败使用静态灯泡并停帧。Escape在窗口级处理，可以从无焦点首屏取消。

## 验证与证据

产物为 `build/ui-fidelity-20261110-002/`。控制源在组件清单响应中增加6秒真实等待，仅供采集检测阶段；生产没有人为延时。采完整灯泡时的等待也只在驱动中，既不推进检查，也不延缓生产结果。

- `environment-runtime-001/report.json`：解锁后补齐上一批最终环境卡片、窄窗口设置、组件复用、真实服务与清理检查，全部通过；业务记忆为0，不复制旧业务库或 Agent 配置。
- `detection-runtime-001/report.json`：真实首屏检测、服务准备、普通／窄窗口、保持后台重开 App、先检测再恢复 Agent 页，以及重开不重复下载通过。重开只检查当前组件与服务，不重新选模型或创建知识。
- `detection-runtime-002/report.json`：保留原始失败。自动化树滞后导致等待超时；后续驱动先采帧再读取树，未修改此失败产物。
- `detection-runtime-003/report.json` 与 `detection-runtime-004/report.json`：系统注册／许可门禁、Escape与重启失败清理修后通过；004补齐最新驱动的完整采帧。业务记忆为0，socket与两把锁释放。
- `detection-runtime-005/report.json`：移除页面重复健康请求后的实际包通过；重开先检测双服务，进入首页显示「服务运行中」，等待16秒后进入设置仍未增加组件清单请求。普通／窄窗口与停止通过，业务记忆为0，socket与两把锁释放。实际首页见 `detection-runtime-005/screenshots/06c-home-system.png`。

全仓 Go 测试、vet、desktop／official race、Python语法及 diff 检查执行；状态／帧检查覆盖必需组件、双服务、系统许可、生命周期占用、保存步骤恢复、失败、取消、Escape、减少动态效果与大时钟相位。
