## 环境正文与状态

初始化和「设置 → 环境与组件」复用 `environmentContent`、同一 RuntimeController 和逐组件回执。三张卡片保持「记忆数据库／向量数据库／向量模型」的产品、用途与状态层级。普通窗口横排，窄窗口纵排，中部滚动而底部操作固定。

「安装并继续」在同一页开始真实准备，原位显示对应组件的下载量、校验与安装阶段。取消、失败、继续准备和重试保留卡片；移除旧确认正文、检查详情及组件外的总进度。SQLite 随 helper 提供，不显示虚构下载；LanceDB 随 Rust 引擎准备，Cognee 服务／官方插件与 BGE 作为实际依赖分别显示。E5 与 BGE 保持各自配方及索引边界。

SQLite 和 LanceDB 官方 SVG 从固定原型归档提取，来源保存在 `internal/desktop/assets/sources.json`。SQLite 使用 Native SVG 图像的灰度显示保留完整标志，避免 Icon 单色遮罩把原 SVG 背景也填成实心矩形。

进度回调保留组件 ID、phase、downloaded 与 total；UI 不从总体比例猜每张卡片状态。每次发送独立的回执切片，新准备清空旧回执，失败或取消保留已取得回执。设置重新检测为只读操作，不创建另一个下载拥有者；准备启动后的较旧检查结果不覆盖新任务。

下载压缩量与预计解包量来自签名清单，实际安装文件大小由后台测量，未取得结果显示未知。页面「已安装组件」只汇总当前已校验组件文件，含其 metadata 和链接本身，不跟随下载剩余量清零，不包含 App、业务数据库、临时文件或其他旧组件。完整客户端及业务根的最终磁盘占用另行测量，不能把卡片合计作为全盘占用。

「更多维护选项」保留索引恢复、备份、更新、缩放及原有管理入口。后台运行选项与停止／启动服务仍在固定底栏；服务运行时发现组件缺失或损坏，仍可直接「准备缺失组件」，不要求先停服。

## 首页动效与真实终态

固定 B revision 5 的 9 个方块保持稳定编号、散开偏移及完成目标。悬停／键盘聚焦为 760ms＋每块 22ms 归整，运行循环 1.7s、每块相位 140ms，完成归整 460ms＋22ms，反馈在 1.4s 收起。使用 Native Go Painter，不解析逐帧 SVG，不扫描磁盘或查询业务。

运行仅读取实际 running／applying。活跃任务消失后，按原任务 ID 获取 daemon 终态，只有此前观察过且真实 completed 才显示完成反馈；失败、取消、读取失败和历史 completed 不猜成功、不重复播放。动效不启动任务、不改变收费、保存或任务完成。系统或 App 的减少动态效果关闭运动循环，有限刷新仅用于收起完成文字；离开首页清理悬停与完成表现，保留真实任务生命周期。

运行周期先在 float64 中取余再转 float32，避免 Unix 时间丢失相位后图形静止却持续请求帧。Native 系统窗口已验证悬停单次归整及停止；运行、完成、失败、取消和减少动态效果另有独立状态／帧测试。本轮未用真实模型整理任务在实际包中覆盖全部动效阶段，也未完成帧耗时及 CPU 性能测量。
