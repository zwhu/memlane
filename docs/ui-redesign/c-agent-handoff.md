## 2. 用户可见术语

用户可见界面统一使用「整理」，不再把这一操作称为「分析」。内部历史状态名、旧证据文件名和既有协议字段可以保留，但不得重新暴露为界面文案。

| 场景 | 选定文案 |
| --- | --- |
| 空知识主入口 | 整理项目 |
| 右栏标题 | 项目知识整理 |
| 启动操作 | 使用 Codex 整理，按实际绑定 Agent 显示名称 |
| 运行状态 | 项目整理中 |
| 恢复任务 | 查看整理进度 |

「记忆」是整体产品概念，项目内容分为「知识／原始记录」；详情使用「知识详情」。知识与原始记录不因保存、索引或界面位置互换类型。完整定义见 [内容分层](content-model.md)。

## 3. 入口、范围与连续性

- Agent 连接位于「设置 → Agent 连接」，是电脑级接入；项目绑定、任务范围与材料授权在项目操作中确定，不能把项目或首个任务作为连接前置条件。
- 只有真实知识列表为空时显示「整理项目」主入口。筛选结果为空、读取中或读取失败都不是空库；已有缓存读取失败时保留旧内容并显示错误。
- 已有知识后隐藏空态主入口，从项目「⋯」菜单使用「补充项目知识」。未完成任务仍可通过「查看整理进度」恢复，不创建重复任务。
- 项目整理始终可跳过，不阻塞 Agent 日常明确提交知识或原始记录。已连接不等于自动采集所有会话，Agent 说“记住了”也不等于已经持久化。
- 进入「查看知识」只离开任务画面，不停止后台任务。返回进度时读取同一任务与尝试快照，不重新启动、不重播成新任务。
- 运行时固定项目、绑定 Agent、仓库范围、历史会话选择和尝试标识。重复点击、切换栏位或收到迟到回执不得扩大范围或覆盖新尝试。

## 4. Agent、Token 与历史会话

启动前必须存在一个已连接、适配支持且获准访问当前项目的绑定 Agent。发现其他 Agent 不自动替换绑定；设置列表中当前选中的 Agent 也不能直接推断为项目执行者。

「同时整理历史会话」默认关闭。开启时只包含当前绑定 Agent、当前项目可可靠归属且已授权的会话；切换绑定 Agent 后清除选择并重新确认。Agent 不支持历史读取时禁用并说明原因；读取失败、无法确认归属或来源不可用时明确报告未完成范围，不能静默跳过后显示全部成功。

启动操作旁提示会消耗绑定 Agent 当前模型的 Token；选中历史会话后额外提示会增加用量。不编造 Token 数、价格、时长或会话数量，也不把 Token 消耗等同于一定产生额外付费。

整理复用 Agent 的正常模型、工具与项目上下文，通过 Memlane 的正式保存规则提交带出处的知识。它不应默默切换「记忆处理」的当前 Provider、Agent 或 Magpie 配置。编码会话与整理执行必须隔离采集，避免整理输出再次被采集形成循环。

## 5. 任务阶段与动效

右栏阶段为：待开始 → 启动 Agent → 整理项目／历史会话 → 保存知识 → 建立索引 → 完成。失败、取消中和已停止为独立终态。具体几何、时序、减少动态效果和 MyGo 映射见 [动效实施与复用](motion-implementation.md)。

- 动画只读取真实任务状态，不推进任务、不计费、不写数据。原型的「播放完整动效」不进入生产。
- 运行中显示固定范围与实际阶段，不用虚构百分比、文件数、知识数或剩余时间。
- 取消先进入取消中，收到真实终态后显示已停止。已提交的有效结果按真实回执保留；旧尝试的迟到回执不能覆盖新尝试。
- 失败或取消后停止循环与扫光，不出现完成书或完成勾。减少动态效果时使用当前阶段静态目标和文字。
- 保存成功与索引成功分开：知识已保存但索引失败时仍可阅读正文，并提供真实索引恢复；不能回滚为“没有知识”。

## 6. 数据与生产边界

revision 7 的项目、知识、Agent、会话、Token 提示和任务结果全部是浏览器夹具。60项核验、截图、GIF和散列只证明固定原型的状态、布局与交互，没有证明以下能力：

- 真实 Agent 已启动或能够在后台完成整理；
- 能读取 Codex／pi 等真实历史会话并可靠归属到项目；
- Cognee 自动产生首页建议或把图谱结果写回 Memlane 当前知识；
- 新知识、原始记录、来源、索引或 Token 用量已真实写入；
- MyGo Native 页面、完整包、性能、减少动态效果和视觉一致性已经通过。

生产必须使用现有正式记录、来源、任务和配置所有者。Cognee 可以参与提炼候选，但建议审核状态、当前有效知识和用户决定由 Memlane 持久化；在有真实闭环证据前，不把 Cognee 图谱持久化描述为自动写回首页待审核建议。

AI 提出的合并、覆盖、删除或跨项目移动在用户确认前不得改变已有有效知识；新增摘要、标签与带来源的新知识按既有整理契约验收。恢复旧版本产生新版本，不覆盖历史。

## 7. 实施顺序与验收

1. 在现有 MyGo 三栏项目页接入知识／原始记录真实列表、空态判断和稳定项目身份，先完成静态窗口与窄窗口对照。
2. 接入电脑级 Agent 状态、项目绑定、历史会话能力说明和固定任务范围；无绑定、不支持与权限不足均使用真实状态。
3. 接入后台任务的启动、防重复、快照恢复、取消、失败、尝试隔离，以及保存与索引分阶段回执。
4. 按动效契约实现 Native 方块舞台；用真实任务状态驱动，核对减少动态效果、隐藏后停帧、快速阶段切换和失败／取消。
5. 构建包含 helper 的实际包，分别验证仓库整理、历史会话、无新增、部分保存、索引失败、来源读取失败和知识质量；保留完整原始证据。

验收至少证明：空态不会把读取失败当空库；重复操作不启动第二个任务；查看知识后能回到同一任务；范围与 Token 提示在启动前明确且运行中不变；取消与新尝试隔离；保存与索引状态准确；新增知识有可核对出处；既有知识未被未确认建议改写；实际窗口与固定原型在普通／窄窗口和减少动态效果下完成对照。

实施不得提交密钥、真实会话、真实记忆库或本机 Agent 配置，并保留用户无关修改。
