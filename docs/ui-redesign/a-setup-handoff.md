## 3. 只有三步的初始配置

```mermaid
flowchart LR
    E[准备环境] --> A[连接 Agent\n多选批量，可稍后设置]
    A --> M[配置记忆处理\n可保存多种，启用一种]
    M --> H[完成配置，进入日常首页]
    H --> S[设置：环境与组件／记忆处理]
```

- 环境未就绪时，展示真实组件状态与准备操作。组件确认、进度和结果同页更新。
- Agent 连接不要求项目、仓库、任务、提炼模型或云模型 Key。可以稍后连接，Provider 与 Magpie 不依赖先连接编码 Agent。
- 记忆处理只需一种有效方式；允许另外两种配置同时保留。没有有效且已启用方式时，不把「完成配置」当成可执行的正常完成操作。
- 「完成配置」持久记录已完成设置，进入日常首页。它不执行编码任务，不采集聊天，不等待知识生成，也不显示记忆结果。
- 「稍后设置」允许推迟配置，保存真实待完成阶段；不将其伪记为已完成、已连接或已验证。后续通过设置恢复，日常首页不重复首次使用教学。
- 「初始配置」与可选的项目知识导入是不同功能。既有导入、具体任务授权及出处阅读仍遵循原契约，在日常操作中承接。

原型的完成动作仅标记演示状态，并说明正式出口；不包含 B 新首页。这不授权开发 Agent再设计首页，也不要求将旧 `task`、`result` HTML 函数移植到初始化。

## 5. 环境页：共享内容，真实任务

环境卡片沿用已认可的「标题 → 产品小字 → 用途」层级：记忆数据库、向量数据库、向量模型。SQLite 随 helper 提供，不是另装数据库服务器；LanceDB 随引擎提供，不假造单独下载包。当前 App 的 E5 与官方 Cognee 的 BGE 配方、维度和索引保持分开。

统一初始化还须准备真实采集所需的 Cognee 服务、运行依赖、固定插件与 BGE。按实际组件 manifest/依赖任务归入环境准备，不因为历史三卡片未画出全部依赖而省略组件，也不在 Agent 连接页再准备一套环境。实际组件数量与聚合映射由运行版本决定，按专项环境契约核对，不把原型反推为新技术选型。

| 状态 | 内容与操作 |
| --- | --- |
| 检测中 | 实际检测阶段；动效与系统减少动态效果规则沿用已认可稿 |
| 缺失/部分兼容可复用 | 只计算缺失项；初始化「安装并继续」，设置「准备缺失组件」 |
| 下载/校验/安装/验证 | 在对应卡片内显示实际阶段、字节/进度；取消按实际任务能力反馈 |
| 失败/未知 | 对应项显示可行动原因；重试或重新检查，不把未知当兼容或缺失 |
| 取消/中断 | 保留已完成组件与恢复位置；继续前核对完整性和当前任务 |
| 全部就绪 | 初始化进入 Agent 连接；设置留在本页并提供「重新检查」 |

已安装兼容资源不重复下载；打开设置不重建数据库、不清空知识、不重置模型配置。窗口离开与重开后读取同一后台任务，而不是另起一个下载所有者。下载剩余量归零不意味着磁盘占用归零。交付分别报告主包大小、首次下载量、最终占用。

## 6. Agent 批量连接

### 6.1 选择规则

- 默认不选中，单击独立勾选或取消；提供「全选可连接」与「重新检测」。
- 主按钮「连接所选 Agent（N）」，N 仅包括已发现、适配支持且尚未连接的选中项。没有待连接项时禁用。
- 已连接项只读显示成功；不支持版本/渠道和未发现项禁用并解释原因。原型 TRAE 的不支持状态不代表永久不支持，正式版按实际能力决定。
- 点击开始后冻结目标集合，每项使用稳定安装/连接身份与自己的任务、attempt/代次；进行中防止重复提交。不能仅按名称识别同一 Agent。
- 连接内容按对应适配器使用官方 skill、hooks、插件、Extension 等；不能统一简化成写一行 MCP 配置。环境、项目和处理执行者均是独立配置。

### 6.2 同页逐项状态

| 状态 | 卡片反馈 | 按钮/结果规则 |
| --- | --- | --- |
| 已发现、待连接 | 安装信息与多选勾选 | 加入待连接集合 |
| 正在连接 | 该 Agent 实际安装接入阶段 | 不允许重复提交；整批可取消 |
| 待重载 | 告知重新打开/重载该工具 | 逐项「验证连接」或「已重载，验证连接」 |
| 验证中 | 实际连接验证进度 | 不将安装成功当成连接成功 |
| 已连接 | 当前版本、身份/代次下有有效接入回执 | 不重复提交，可继续配置记忆处理 |
| 失败 | 该项的实际可行动原因 | 卡片「重试」或底部「重试失败项（N）」 |
| 结果未知 | 未取得有效回执 | 保持待验证，不以历史 session 或缓存成功替代 |
| 取消请求中/已取消 | 根据真实任务分别反馈 | 确认终态再记取消，保留其他成功项 |

一款完成不等于整批完成。逐项重载验证后仍有其他项待重载，整批仍等待剩余项；部分成功只重试失败项，成功身份及已有配置保留。重开后从后台逐项状态恢复，不全量重装。断开或取消不删除知识，也不动用户其他插件、hooks 或模型配置。

完成后使用「继续配置记忆处理」；连接其他 Agent 留在同一页继续选择。即使部分失败，也可选择独立 Provider/Magpie 或已成功的 pi/Codex。采集范围和材料授权在日常任务里处理，连接不自动扫描历史聊天或创建项目。

## 7. 三份处理配置与一个当前使用

### 7.1 四类状态的所有权

以下是逻辑对象，实际字段、IPC 与迁移应对齐现有实现后定义，不是新接口已经存在的声明。

| 对象 | 保存位置与作用 | 关键约束 |
| --- | --- | --- |
| 当前查看方式 | UI 导航状态 | 点页签只查看/编辑，不启用 |
| 每种方式的草稿 | UI 内存 | 切页签保留；取消恢复该方式的已保存配置 |
| 三种已保存配置及供应商配置 | 正式私有配置存储 | Provider、Agent、Magpie 分别保留；供应商供多个模型复用 |
| 当前有效配置 | 一个明确的持久选择及配置修订/快照 | 只有明确启用才改变；已有任务绑定启动快照 |

至少必须表达：模式、真实供应商/模型 ID 或稳定连接身份、配置修订、必要连接信息及验证依据。密钥放既有安全存储，不把真实密钥、用户 Agent 配置、会话或记忆库写进 Git。新 schema 和接口需实现阶段明确归属、迁移和验证。

**保存同一模式的新模型，也不能悄悄替换该模式正在使用的旧配置。** 当前有效配置与待保存/已保存候选用修订或不可变快照区分，直到用户点击启用。不能仅保存一个 `mode` 字符串却原地覆盖其所指内容。

### 7.2 按钮的条件与结果

| 操作 | 可执行条件 | 成功后 |
| --- | --- | --- |
| 验证配置 | 必要选择/字段有效，所需服务或 Agent 当前可用 | 检验实际推理、完整结构化输出及隔离；不保存或启用候选，不产生业务知识 |
| 保存配置 | 当前候选验证通过且有未保存更改 | 持久保存这一份；另外两份和当前使用保持不变 |
| 设为当前使用 | 当前候选已经保存、验证依据匹配且尚未生效 | 原子记录生效选择；留在本页，更新当前使用行和状态栏 |
| 取消修改 | 设置中有草稿/候选 | 恢复当前查看方式已保存内容；不切换到另一个页签，不改变当前使用 |
| 完成配置 | 正常完成所需的环境与当前有效处理配置均满足条件 | 持久记录完成并进入日常首页，不执行首任务 |
| 稍后设置 | 当前步骤可以推迟，操作中按真实取消/离开能力处理 | 保存待完成状态，后续通过设置继续；不假造成功 |

验证与保存供应商配置是两件事：供应商配置可以先保存供多个模型复用；它不代表某个模型已通过记忆处理验证。更改端点须重新提供对应密钥，不将旧服务密钥发给新地址。

更改模型、供应商端点/凭据、Agent 版本/登录/连接代次、Magpie 地址或返回目录的相关能力后，验证失效。失败、取消或迟到回执不启用任何候选；当前方式不可用时准确报错，保留材料，**不自动改用另外两种方式**。进行中任务继续使用启动时快照，后续任务才使用新启用配置。

### 7.3 Provider

- 搜索名称/实际模型 ID、供应商筛选、分组模型行、常用、勾选高亮；显示模型与供应商的归属，不推断为一供应商只能选一个模型。
- 供应商目录与模型来自真实适配目录/返回值和用户配置；展示名称不用于拼接路由。DeepSeek/Kimi/GLM/OpenAI 的示例名和九条模型不是已验证支持列表；DSH 也不能被直接等同于 DeepSeek Provider。
- 未配置供应商的模型，先进入对应供应商编辑；保存后回到模型列表并保留候选。已有配置可编辑，密码不显示原文。
- 手动添加真实供应商提供的模型 ID，按供应商命名空间去重；输入与模型展示进行正确转义。
- 保存/启用与 Agent 接入独立。供应商错误、额度不足、超时和 Schema 失败分别反馈，不将任何 HTTP 200 当成能力通过。

### 7.4 已连接 Agent

- 候选只有实际已连接、适配支持的 pi/Codex，版本、登录和后台处理能力分别核对；列表可为空。其他编码 Agent 可参与批量记忆接入，但不自动进入处理候选。
- 这里单选一个；批量连接多选不是多执行者整理。登录和模型由 Agent 管理，无需为此方式再填云模型 Key。
- 选中卡片仅保留一句当前模型与账号额度说明。独立提炼会话、工具关闭、采集排除和防循环由受管适配器落实并真实验证。
- 原型可选不表示后台桥接已完成。当前 pi 的文档记录技术链路通过、qwen3:0.6b 事实质量未通过，且原始 Provider 直接复用/云认证未实测；Codex app-server 也不能借该结果宣称通过。

### 7.5 Magpie

- 选择该页签即检测本机网关并读取模型；默认 `http://127.0.0.1:3425/v1`，不是要求用户填写的主表单，也不是设备当前服务运行证据。
- 本机 loopback 请求网关自身端口无需访问凭据；未运行时提供「打开 Magpie」「重新检测」。非默认本机端口放在「连接设置」。本轮不支持远程或代理接入，不将本机免密推广到网络地址。
- 通用目录 `GET /v1/models`，推理参考 `/v1/chat/completions`；不可混用 Codex 专用 `/v1/codex/models`。使用返回的规范 ID/命名空间，不能按显示名拼接路由。
- 连接与读取模型不等于推理能力通过；空目录、访问失败、取消、Schema 失败和刷新原位表达。模型管理在 Magpie 完成，Memlane 不再提供供应商编辑或网关模式的「添加模型 ID」。
- 不读取 Magpie 私有配置/Keychain，不复制上游供应商密钥。实际路由回退由 Magpie 管理；实际模型未报告时不冒称固定命中所选模型。
- 若模型内部用 Agent/订阅桥接，仍须验证内部推理不会再次触发记忆采集。结构化输出、取消、错误、使用量及原始模型调用需实际验收。
