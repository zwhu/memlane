# Provider／Magpie Native 配置闭环 · 2026-11-11

本批由主Agent授权集中实现，复用A记忆处理页与后续设置；没有操作真实Native窗口、调用真实云模型或完整打包。实际验收仍由下一集中包执行，不将IPC／HTTP夹具描述为云端或Keychain实机已通过。

## 设计依据

读取记忆处理设计、页面复用契约及当前 `a-organize.js`；直接打开固定A图 `models.png`、`magpie-models.png`、`magpie-connect.png`。使用三页签、方式状态栏／显式启用、目录顶部搜索、左侧供应商／常用筛选、中间分组列表、底部保存／验证结构，没有移植HTML。

供应商配置目录保持DeepSeek、Kimi、Zhipu GLM、OpenAI、自定义接口五项，不复制示例模型或示例密钥。四个供应商品牌SVG来自同一设计资源，只转为currentColor单色；来源路径、原SHA256与转换记录在 `internal/desktop/assets/processing-provider-sources.json`。

## 实施行为

- 供应商编辑页显式保存独立Keychain凭据。输入为密码控件，成功回执后清空UI明文；错误不拼接上游原始响应。供应商持久元数据只包含地址、协议、不可变凭据引用和CAS代次，同一供应商多个模型复用，不读取Agent账号或网关上游密钥。
- 地址／接口格式变化时不能留空继承旧密钥；需要新独立凭据。保存只改变该供应商的独立元数据，不改变已有活动配置或任务快照。回执丢失重试复用同一不可变引用，避免创建不确定的新身份。
- 模型目录通过正式IPC读取，使用实际返回ID／显示名；Provider目录按保存的供应商命名空间绑定对应凭据，不能用上游owned_by替换另一供应商凭据。搜索、分组、常用、真实分页、空目录、失败与部分失败有独立反馈；失败保留原列表、已保存候选和当前方式。
- 手动模型ID显式标为手动添加、待验证，并按供应商命名空间去重。模型选择不会自动保存、验证或启用。原有pi／Codex候选边界保留。
- Magpie首次选择自动检测本机默认 `http://127.0.0.1:3425/v1`，不渲染凭据字段；本机非默认端口在连接设置中修改。地址限定loopback／无URL凭据；默认不读Magpie私有配置、Keychain或上游账号。打开／管理按钮仅显式打开Magpie应用。
- 已保存非默认网关地址由同一账本恢复；用户未保存的地址修改和取消保持独立。旧地址目录不能被用于新地址选择。网关实际返回的供应商信息用于模型分组，不据展示名拼接真实路由。
- Provider／Agent／Magpie各自草稿与保存修订并存，选择页签不启用。保存配置 → 真实结构化输出验证 → 明确“设为当前使用”继续分开；验证终态按原方式更新，即使已查看另一个页签也不会串写。
- HTTP请求模型、返回模型、网关报告供应商和网关报告模型分别呈现，缺失项显示未报告；本地取消不冒称上游停止或免计费。新候选保存后清理旧实时回执，不能将旧模型验证回执当成新候选“本次”成功。
- 处理方式运行态继续使用owner精确依赖投影；重验当前方式先停用增代，新验证成功仍需明确启用。HTTP相关读取／回执使用原root和独立UI epoch，旧库回调不能回填新库；ConfigureLibrary重置整个处理UI，密钥不跨库保留。

## 验证与边界

Unix IPC＋headless夹具覆盖：独立凭据引用保存、密钥清空、供应商多模型复用、实际目录ID选择、保存／验证／启用分离、Magpie免密请求／空目录／非本机拒绝、目录失败保留当前选择、失去回执的同身份重试、请求与返回模型分别展示，以及密码不进入可见文本、Magpie不渲染密钥字段。

这些测试使用明确合成模型名、假凭据和IPC回执，不代表任何供应商模型已获得真实Schema能力。真正Keychain写入、目录服务、模型推理、取消、关闭重开与普通／窄系统窗口仍需004集中包逐项取证。常用星标和未保存手动ID目前属于客户端会话状态；已保存选定模型、供应商独立配置和启用选择由正式账本持久化，未宣称整个A与125场景完成。
