## 官方集成

2026-11-18用户要求记录后续大量Agent接入方向：参考[多Agent驱动协议](../research-agent-driving-protocols-20261118.md)，按官方SDK／RPC／ACP／结构化CLI适配任务驱动与能力差异。此为后续研究入口，不代表新增支持或改变下述官方采集优先规则。

采集和召回复用目标 Agent 的 Cognee 官方集成，不新增并行采集器或第二次上下文注入。首条日常链路固定实际使用的 Codex 客户端；CLI 与 Desktop 的状态分别表达，不以一个入口替代另一个。

首版沿官方安装、信任及重载流程完成接入，允许一次性官方安装步骤，不建设通用安装管理平台。只修改明确属于本项目的连接项，保留第三方配置、账号与历史会话。

## 连接与项目

接入是电脑级连接，不以项目、工作目录或第一项任务为前置。项目关联只决定材料归属和检索分组，不能猜测无明确来源的归属。

所有有效接入指向同一个本机官方服务，每个类型与独立profile使用自己的官方子主体，管理owner留在控制侧。逐项目权限沿PA契约执行：维护包括read/write/delete，不授share。服务地址不可达时不使用owner、离线CLI或另一套日常库fallback。

## 界面状态

设置只显示已安装／待重载／服务可连接等真实连接事实。安装完成不等于产生知识；模型连接、材料接收、官方处理结果和知识产生分别表达。

Codex、pi、TraeX、Claude Code、Cursor逐项显示检测、准备、启用、重载及真实新会话事实；批量取消保留成功项，未知写入保留原编号，重开后只读核对。Cursor无工具回合当轮注入限制保留，实际IDE／CLI尚未验收。

知识处理独立保留Codex订阅桥及官方Provider直连。多个已保存配置只有一个当前使用；保存、验证及下次启动分开，验证记录实际adapter请求模式，不将Schema请求形状写成远端严格保证。配置改变通过后台正常重启生效，真实供应商与宿主证据按支持矩阵区分。

处理会话隔离项目上下文、采集插件、工具和日常历史；认证复用不等于复制全部 Agent 配置。正常编码采集与后台处理的进程各有明确所有者。

## 本机发现与设置入口

2026-11-14用户明确要求新增Agent与Provider沿用此前设计并加入设置。入口及完整行为以[方案5.1](../multi-agent-provider-technical-plan-20261114.md#51-本机检测与绑定用户补充2026-11-14)为准，复用此前多选卡片及现有设置布局，不另建向导。

- **设置 → 服务与连接 → Agent 连接**：启动及进入设置时自动检测本机安装，提供“重新检测”。Codex、pi、TraeX及其他适配使用同一列表；未安装项不可勾选，适配未就绪项如实显示状态。
- **绑定流程**：选择 Agent → 连接所选 → 同页查看具体配置变更 → 确认连接 → 按提示重新打开宿主并新建会话 → 显示“已连接”。底部只呈现当前阶段的一个主操作；准备与启用仍由后台分开执行，不能跳过配置变更确认。取消保留成功项；结果未知时核对原操作。电脑级绑定不先要求选择项目或处理模型。
- **检测与状态**：检测只读取安装事实，不读取聊天或密钥、不自动配置。卡片区分未安装、未连接、已准备、待重载／新会话、已连接及需核对；实际接入使用独立官方主体，项目权限另在项目设置配置。
- **设置 → 知识处理**：沿用当前配置、已保存配置与“添加Provider”表单，填写协议、模型、API地址及所需密钥。保存、验证和下次启动使用分开，只有一个当前使用；无需先绑定Agent，也不从Agent配置提取密钥。

当前源码已有自动检测、重新检测及批量准备／启用入口；pi／TraeX实际Native设置证据见执行记录检查点四十五，OpenCode实际Native绑定及新会话回执见检查点四十七、五十。OpenCode已接入prepare／activate／review，不再统一标为开发中；各Agent的采集、召回、知识质量与暂缓验证范围仍分别按支持矩阵表达，不因卡片存在而视为全部交付。
