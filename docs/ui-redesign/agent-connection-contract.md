# Agent 连接：电脑级配置与项目范围的边界

2026-11-09。**用户已确认归档 revision 13 的连接页与交互。** 实施先读 [A 实施交接](a-setup-handoff.md)，固定版本和截图以该文档为准。这不是电脑级适配器已经实现或验收通过的报告。

最新 revision 13：用户确认「这个应该是多选；批量连接」。连接页使用多选卡片，一次提交所选 Agent，安装、重载、验证与结果留在同一页逐项反馈；不再选择一款后进入单独连接页面。处理记忆的 Agent 仍独立选择一个 pi/Codex，不能把连接页的多选变成多个并行整理执行者。

同日最新补充：连接指参考 Cognee Web UI，为对应 Agent 安装 skill、hooks、插件或 Extension 等接入内容；不局限于添加 MCP。记忆处理独立配置，优先 LLM provider，Agent 方式仅选择已连接的 pi/Codex；[最新设计交接](memory-processing-design.md) 替代此前只以 MCP 解释连接及将 API Key 当成唯一途径的取舍。

用户原话：“这个流程不对，这里应该是线选择Agent做链接，不一定需要关联项目；链接的作用是可以配置到当前电脑中的codeagent”。

## 已确认的作用与顺序

1. 本机记忆环境准备后，多选当前电脑上需要接入的编码 Agent。
2. 「连接」将 Memlane 所需的接入配置添加到该电脑上的 Agent，按对应接入形式配置 MCP、Extension 或必要连接项。
3. 此时不要求用户选择项目或仓库，也不要求工作目录、项目访问范围、首任务内容、Cognee 提炼模型或首任务采集环境。
4. 完成必要重载后，验证该 Agent 已加载 Memlane 配置、能够连接当前电脑的 Memlane 服务。
5. 项目关联、任务工作目录和本轮材料范围在实际使用或首任务中独立处理；项目可以跳过，有有效材料后按既有规则建立或复用项目。

电脑级配置成功不代表任意项目已经获准采集，也不代表首任务、知识保存或项目检索已经验证。没有项目时，可以验证连接协议和本机服务；不能伪造仓库记忆来证明连接。

## UI 约束

- 页面标题「连接 Agent」，卡片使用方形多选标记，默认不预选。点击独立勾选/取消，不清掉其他选择。主操作为「连接所选 Agent（N）」，N 只计实际待连接项；未选中时禁用，提供「全选可连接」与重新检测。
- 已连接项只读显示成功，不重复提交；未发现、当前版本不支持的项禁用并说明状态。发现安装不代表已连接或具有处理记忆能力。
- 点击后保留卡片与滚动上下文，在卡片内显示安装、待重载、验证、成功、失败或取消。每款 Agent 独立产生状态，不能用一个批次成功替代逐项回执。需要重载时支持逐项验证或「已重载，验证连接」。
- 部分成功保留已连接项，只重试失败项；取消保留已完成结果，不回滚成功连接。重试/恢复只针对尚未完成项，批次进行中防止重复提交或改变目标集合。
- 可以继续配置记忆处理，或连接其他 Agent。初始配置不包含首任务和记忆结果；连接及处理方式边界遵循 [最新三步流程](reusable-setup.md)。
- 删除连接页的项目选择、工作目录、默认项目/全局范围勾选、首任务采集组件和提炼模型配置。
- 仅当用户在日常使用中进入具体任务时，再明确工作目录、项目归属、材料范围及所需采集环境；不增加初始化项目登记或首任务流程。
- 不因电脑级配置隐式扫描历史聊天、自动创建项目、启用日常 hook 或授予所有仓库的读写权限。日常默认记忆策略继续未定。

## 现有实现与后续开发注意

当前 `internal/agents/config.go` 的 Codex、TRAE CLI、TRAE IDE 安装路径仍有项目 `Workspace` 门禁，并写入项目配置；pi 已使用指定的用户/隔离配置目录。此前无项目 Codex 接入身份及首任务验证也不等于通用电脑级配置已实现。

后续开发应对每个 Agent 单独核对受支持的电脑级配置位置、格式与当前版本能力，使用相应用户级配置；不能凭 Agent 名称猜文件路径，也不能将本稿显示的「用户配置」当作文件接口证据。未支持的版本/渠道保持明确状态。用户并未要求本轮实现或改写真实 Agent 配置，本轮只更新产品规则与设计稿。

电脑级连接身份应与项目/任务授权分开管理。后续请求仍需要受信工作区、范围、来源与代次校验；配置层级改变不能绕过这些门禁。保持自有配置增量写入、备份、已有配置保留和自有项撤销；断开连接不删除已有知识。

批量连接只是操作入口，各 Agent 配置、重载、验证、取消与终态分别由真实任务拥有者管理。恢复使用原目标及逐项真实状态，不能因为同批另一款完成就把待重载或失败项标成已连接。共享的服务/组件检查复用已有准备，不重复创建下载或写入拥有者。正式运行方式和并发由各适配器能力确定，本稿不要求各工具同时启动，也不安装或修改本机 Agent 配置。

当前原型入口 `a-agent.html?screen=choose&state=batch-ready&revision=13`。`artifacts/batch-connection/` 与 `node verify-batch-connection.cjs` 记录多选、同页连接、部分成功、仅失败项重试、逐项重载、取消保留和成功候选供处理页使用。所有结果为设计示例，非真实批量接入验收。

真实记忆采集继续遵守官方 Cognee Integrations 路径及 Memlane 版本/来源契约。电脑级 MCP/Extension 连通不代替官方采集、持久接收或新会话读取当前知识的验收。

本规则替代上一版 A 后半段草稿中「连接前必须确认仓库目录」「连接页准备 Cognee/BGE/提炼模型」「验证当前仓库读写后才算连接」的取舍。原型上一版保留为历史记录，不能据此要求用户关联项目。


## 2026-11-11 用户最新纠正：日常自动记录

本节覆盖此前“日常默认记忆策略未定”及逐项目接入的产品预期。以下2026-11-11基线与后续实现状态分开；2026-11-12已验证范围及限制见[当前交接摘要](../engineering/codex-capture-handoff.md)。

- 用户在App首次完成所选Agent连接与采集授权后，后续正常使用这些Agent时自动记录对话，不要求每仓库重新接入/授权，也不依赖模型主动调用memory_save。仅发现安装或失败/待重载状态不算连接完成。
- 尚未登记的仓库（如item-fe）不能阻塞已授权对话的原始记录持久化；保留来源与仓库身份，App再询问是否添加/自动建立该项目，不要求先手工添加。未确认归属的承载、拒绝/暂缓后的展示与保留仍待设计，不能擅自丢弃或归入通用知识。
- 自动记录指原始记录采集，不能推导为自动调用模型整理、自动覆盖有效知识或导入全部历史。后台整理会话继续隔离采集，避免自循环。
- 用户日常不需要检查MCP工具；配置加载、必要重载和真实采集验证由App逐Agent明确反馈。MCP工具可用只证明工具接入，不证明对话自动采集。
- 当前MVP仅验证隔离Codex CLI明确提交和pi整理闭环；电脑级日常接入、自动对话采集、未登记项目先保存再询问，均须单独实现和实际验收。此前已连接显示不能冒充这些能力已交付。

### 同日补充：按安装位置定位，不限制 Codex 版本

用户明确要求不限制 Codex 版本，表达为记录实际安装位置或变量，类似 `which codex`。

- 自动发现使用 PATH 中的实际可执行文件，允许保留用户明确选择的位置；配置及会话目录优先使用实际 `CODEX_HOME`，未设置时使用用户的 `~/.codex`。App 从 Finder 启动时也须复用已保存位置或提供明确路径选择，不能假定它继承终端环境变量。
- 版本只记录为诊断与来源信息，不建立版本白名单，不因补丁升级或版本字符串不同要求重新连接。
- 是否可用由实际能力、协议回执和数据格式核对决定。路径失效、协议失败或无法理解的格式明确显示对应问题；不将未知内容静默丢弃或标记为完整。
- 项目范围、用户采集授权、原文来源及配置代次门禁继续保留；放开版本不等于放开授权。

### 2026-11-12 同一 Agent 的多客户端接入规则

本机 Work 测试已证明 Codex Desktop 与 CLI 可共用用户配置及现有 hook，但会话 originator 不同。品牌、界面外观或“本机”标签不能替代实际协议与能力证据；本次仅补齐 Codex 已观察来源，不据此宣称 Claude 等其他 Agent 已支持。

- **按实际运行入口识别**：记录 Agent 家族、客户端形态（CLI／Desktop／IDE）、执行位置（本机／云端）和实际配置目录；版本仅诊断。桌面窗口发起的任务也可能由不同执行端运行，不能从窗口位置推断。
- **按配置与所有权安装**：同一电脑、同一 Agent、同一配置目录的 CLI/Desktop 可复用一套自有接入项与授权；不同配置目录独立核对。不得为每个外壳重复安装 hook；撤除共享接入项前明确影响的客户端。采集授权与项目归属/知识读取授权仍分别核对。
- **逐客户端、逐能力验收**：工具协议、自动原文采集、记忆处理分别记录支持/已验证/待验证/不支持。CLI 验证通过不得将整个品牌或 Desktop 标为自动记录可用；真实验证需覆盖用户/助手消息、来源、恢复和实际保存结果。
- **来源与消息分开适配**：在 Agent 适配器内明确接受已观察的来源组合，并转换成现有统一原文契约；仅有 source=vscode 不能区分 CLI、Desktop 与 IDE。共同校验授权、确切会话与轮次、当前 transcript、工作目录和原文身份。来源声明是兼容信息，不是身份认证。
- **未知来源可恢复**：保留原事件与安全原因码，状态不得显示已保存；兼容修复后按原身份补送，不要求用户重复说话，也不扫描或批量导入历史。新增来源必须有明确样本和拒绝未知来源的回归，不通过删除所有来源校验来兼容。
- **跨客户端去重**：以同一 Agent 配置/会话/轮次/原生消息身份处理幂等，不能仅因从 CLI 切到 Desktop 再存一份；同一会话不同客户端继续后的来源变更需有证据，不改写既有原文回执。
- **Claude 后续接入**：先分别查验 Claude Code CLI、Desktop 中的编码入口、普通聊天入口各自的实际协议和配置；是否共享 hooks/本地会话逐项实测，不预设为同一接入。云端和普通聊天缺少本机事件时，另评估官方扩展/显式导入，不能伪造 cwd 或套用 CLI 授权。

上述是后续适配契约；多客户端能力账本与设置页逐项状态尚未实现。当前 Codex 修复继续复用原授权和原队列，不迁移连接身份或扩大知识访问。
