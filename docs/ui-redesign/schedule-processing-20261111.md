# 计划复用真实记忆处理 · 2026-11-11

本批补主线7的后台断点：原计划只接受 traex，无法使用已明确启用的 pi 记忆处理。新增计划 `processing` 执行方式，保存时由 daemon 解析当前授权和真实依赖，存储事务冻结不可变处理修订；保存和启用仍分开。旧 traex 计划保留兼容。

首次保存／明确更换执行者提交 `ScheduleDraft.Processing`（当前修订与代次）；返回 `ScheduleSpec.Processing` 保存完整快照。随后改时间、停用或明确启用保留原快照，不因用户切换记忆处理设置静默换模型。新客户端不能通过直接提交快照创建付费绑定。重复保存先恢复原回执，不重新解析运行时或重新启用旧计划。

计划到期产生同一冻结处理快照的正式整理任务，复用已有 pi 隔离执行、候选严格校验、自动新增／标签和需确认建议流程；运行前依赖复核仍由真实处理所有者执行。验证失效／撤权在到期时留下 `processing_changed` 跳过回执，不回退旧执行者；旧计划材料去重指纹保持兼容。

验证为真实 SQLite／合成验证账本定向测试：保存停用、明确启用、设置切换后冻结原模型、防伪造、失效跳过、保存回执重放。该证据不宣称真实 pi 计划推理或 Native 窗口验收通过；统一完整包与主线7实机验收由主 Agent 集中进行。Provider／Codex／Magpie 不因该分派扩展而新增已验证能力。
