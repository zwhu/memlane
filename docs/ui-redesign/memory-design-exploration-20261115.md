# 视觉温度与可读图谱候选

2026-11-15。用户反馈：“太冷淡了，看起来没有用的欲望”“图谱的部分我看不懂，重新设计并优化”。本轮完成竞品调研与可点击候选，不把尚未选择的方向直接替换当前 Native 基线。

最新反馈：用户认为首页不行，要求后面再看；首页候选未获认可，停止本轮首页迭代。用户追问图谱能否理解、能否基于现有技术实现，下面补充只读核查结论。

## 追问后的技术核查

不能保证原型一定更易懂，也不能将候选中全部交互视为现成能力。上一轮只有合成关系，未用真实日常子图证明理解效果。

只读查询现有日常 `memlane` 项目的同一官方接口（max_nodes=1000，不触发模型或索引）：本次响应有486个节点、1858条边，其中902条是 `belongs_to_set`；另有 `is_a`、`is_part_of` 及大量业务关系。`edge_class` 为semantic的1132条、structural的726条，因此不能直接把semantic分类全部视为用户关心的业务关系，仍须基于实际类型／关系细分。上述数量仅为本次加载子图，不是全库统计。

- **已证可做**：原始payload有节点、边与relation；在宿主中按ID筛一跳、查名称、列出方向与关系原文，可以不改存储或调用模型。官方Canvas有 `focusOnIds`、`selectedId` 与 `viewState` 接口，可作为局部聚焦／选择同步的基础；具体组合效果尚需实现验证。
- **不能照稿承诺**：官方Canvas当前公开点击回调是实体选择，命中结果没有边类型；候选B的固定卡片布局、边点击与整套浅色主题不是已确认的配置项。默认关系阅读可在宿主做，不能宣称只换CSS就能得到候选B。
- **语义缺口**：合成稿里的“遇到空白输入时抛出”等句子不证明真实图有同样标签。真实存在大量技术关系和长英文谓词；先降噪，保留真实标签，人工核对常见翻译，未知保持原文，不能靠AI补造解释。
- **出处缺口**：本次192个节点带document_id/data_id，但1858条边的顶层字段与edge_info键均无明确文档引用；edge_info有edge_text、关系名及端点等字段，不等于原始文档身份。当前Go的graphSource解析节点document_id/data_id/id，只能在成功定位时打开节点文档。不能承诺每条边有可点击的原始依据。

因此，下一步更有价值的验证是：用真实子图挑一个用户熟悉的问题，展示其直接业务关系、节点上下文与能证实的出处，检查能否回答“这两者有什么关系、为什么显示、从哪里来”。这一步应先于完整视觉重做；本次仅核查，没有启动实现、模型任务或验收重跑。

## 图谱为何难读

当前归档实窗 `09-graph-entities.jpg` 与源码 `web/official-graph/src/main.tsx`、`internal/simpledesktop/graph.go` 相互印证：深色全图与浅色 App 割裂；技术来源组名、抽象圆点与无直接解释的连线要求用户自行理解；Native 选中后拼接原始选择 JSON。11 月 15 日还通过 CUA 查看日常 App 的项目图谱入口及代码图谱未开启状态，没有开启索引。

这能证明存在理解负担，不能单凭截图宣称已经定位所有使用问题；未做独立用户可用性研究。

## 推荐交互与数据约束

连续流程：项目 → 图谱 → 选择／查找概念 → 一跳关系 → 点选关系 → 依据 → 原始记录 → 返回原关系与滚动位置。默认可读关系区，全图为辅助入口。

1. 区分知识关系与代码结构；代码图谱继续项目内显式开启、手动更新。浏览不触发扫描、处理或模型请求。
2. 名称显示完整标题并允许换行；代码节点区分文件、函数等真实类型。UUID、原始 JSON 与服务状态码移至展开的诊断信息。
3. 一条关系呈现起点、真实关系标签、箭头、终点。只翻译明确核对过的关系词，保留原文供核对；未知词原样显示，不生成故事或因果。
4. 节点详情与边证据分开。官方字段没有边级出处时显示“暂无关系依据”；端点有文档出处只称“节点出处”，不得冒充关系证据。来源分组不是文档身份。
5. 名称搜索仅筛当前加载子图，并标注范围；不将载入节点数写作项目全部知识数量。无匹配与空图分开。
6. 保持当前权限检查、项目／dataset／epoch 隔离、可信文档 ID 解析、迟到结果丢弃，以及返回阅读状态。
7. 初次未选择时提供概念入口；无直接关系、缺少可读名称、未知关系、缺少出处分别表达。加载失败保留可读错误与重试，不伪装为空图。
8. 在关系条目或表格中提供无需拖拽的等价操作；键盘选择、焦点、减少动态效果纳入 Native 验证。

原型关系与片段均为合成样本，只证明交互意图，不声称当前官方输出具有同样的关系字段或边级出处。B 的 SVG 不作为替换官方 renderer 的实施授权。

## 影响、依赖与实施顺序

| 部分 | 当前可复用证据 | 实施前仍需核对 | 交付证据 |
| --- | --- | --- | --- |
| 视觉主题与首页 | Native 已有统计、近期知识与热力图；品牌资源存在 | 选定方向后的 token 与 MyGo 官方控件映射；内容为空／长标题布局 | 同尺寸同内容的 Native 对照 |
| 默认关系阅读 | 官方 payload 有 nodes/links/relation；宿主已有选择事件 | 节点 stage/type、关系分类与单跳过滤，长列表分页／虚拟化是否需要 | 定向数据适配检查与实际日常子图 |
| 全图 | 固定 Cognee Canvas 已集成 | 聚焦、标签与主题支持范围；不修改 vendor 去硬凑候选 | 官方 Canvas 与列表的选择同步 |
| 来源 | Go 已按可信身份解析官方文档 | 边级出处是否存在；没有时使用明确缺失态 | 正常来源／缺失来源／错误身份拒绝 |
| 代码图谱 | 显式启用与更新流程已存在 | 函数调用、定义、导入等实际输出关系的语义与方向 | 不自动索引；已开启项目的只读浏览 |

先选定视觉与阅读方向，再核实官方字段及组件接口；随后实现宿主呈现与 Native 主题，集中执行连续流程验收。沿用官方数据，不复制正文、不另建图数据库、不变更权限，不新建或切换日常库，不做 release。当前仅新增设计资料及独立原型，未启动生产代码改造。

验收至少覆盖：熟悉概念两三步读懂关系并找到出处；选中其他关系后依据同步；缺失出处不误导；长名称／无关系／筛选无匹配；知识与代码切换；跨项目迟到回调；返回关系保留状态；1200×820 与放大窗口实际 Native 视觉。不能用原型或官方截图替代这些证据。
