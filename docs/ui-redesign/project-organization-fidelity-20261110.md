2026-11-10。设计基线为已认可 C revision 7 `35a5bad5f5398f2c9cf3073b673983f5dab0a48c`，叠加左侧项目菜单及 C①阅读交接；F–O固定候选仍为`780745fc55d71edb22e46d9c3e4f208d5ecb602f`。本批重新读取设计入口、C交接、项目整理与动效契约，并实际打开`ready`、`unbound`固定系统图。原型没有新增提交。

## 第一步：核对任务所有者

现有`organization`任务处理冻结的已保存记忆，并固定通过受限traex生成整理建议。该J链路不是C绑定Agent仓库整理：不能把其1–16项材料及128KiB限制搬进新版仓库操作，也不能用同名「整理」菜单将两种任务混同。旧首任务路径和受控导入均保留对应历史证据。

C通过绑定Agent自己的正常模型、工具和仓库上下文生成带出处的新知识；整理输出隔离日常采集，避免再次进入提炼循环。保存、索引和质量分别证明，AI合并／覆盖／删除／跨项目移动继续等待确认。历史只包含当前绑定Agent、当前项目可靠归属且已授权的会话；不凭目录名称或项目选择推断权限。

实施分为：①正式绑定与任务范围账本；②正常Agent执行、可信出处提交、取消及恢复；③Native阶段舞台与真实包闭环；④普通／窄窗、无新增、部分保存／索引失败、历史与质量矩阵。每步更新本记录及123场景账本，不把基础层完成写成C整体交付。

## 第二步：schema18正式范围契约

- `project_bindings`持久保存显式选择、连接代次和绑定修订；默认没有绑定。连接须已启用、当前代次有访问验证事实且允许本项目。绑定不修改连接原主项目、其他授权或全局记忆处理方式；清除保留修订，防止旧编辑器重写。
- `project_tasks`与J任务分表，固定项目、工作目录及Git目录／工作目录的设备和inode身份、绑定修订、Agent版本／模型／配置摘要和已授权会话标识／摘要。任务参数不接受外部指定项目路径、模型替换或历史文件路径。
- 稳定操作ID防重放；每项目最多一个活动C任务，活动任务禁止更换绑定。尚未启动的排队任务可直接取消；已经启动的任务取消只记录取消中，真实进程终态由后续所有者确认。
- 重连、范围代次变化和整库恢复不自动复活旧任务。恢复副本把活动C任务标为中断，连接退休和代次门禁继续生效；源备份与原数据库不改写。

当前`StartProjectTask`只持久化已解析的意图，不启动模型。服务只开放绑定保存与任务读取／列表，尚未开放付费执行的启动入口；版本／模型／会话参数必须由未来任务所有者从真实运行配置与来源解析，不能把测试输入当实际运行证明。

真实SQLite／Git契约验证已通过：默认不绑定、未验证连接拒绝、修订CAS与清除防旧编辑、全局处理与知识不变、并发重复操作只有一个任务、活动绑定禁止修改、取消重放不复活、跨Agent／项目历史与变化摘要拒绝、断开失效、同路径仓库替换识别、恢复授权退休、schema17原始备份保留。日志位于`build/ui-fidelity-20261110-006/project-contract-tests.log`。

首次整组测试的四个失败保留于`contract-first-check.log`：旧schema13／14／16夹具从当前数据库降版时没有移除新表，导致再次迁移重复创建。修正了测试夹具的降版范围，没有改变生产迁移为忽略已有表；`contract-recheck.log`通过。旧processing迁移断言改为当前SchemaVersion，原schema16备份仍保持16。
