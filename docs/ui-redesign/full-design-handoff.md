## 后续功能必须怎样还原

实施每个场景前，登记固定设计提交与编号，读主分支对应契约并实际打开原型和该编号截图。按现有设计还原页面入口、栏宽与密度、正文层级、字段、按钮、禁用条件、回执、焦点、列表／正文局部滚动、草稿、来源版本和返回上下文。普通操作留在栏内；历史和关系说明用已有允许弹框。窄窗口、长原文、冲突、取消／失败和减少动态效果同样是实施范围。

Native继续采用MyGo组件，几何与动效按[动效复用契约](motion-implementation.md)实施；HTML/CSS/JS示例只提供外观与状态参考。状态由真实数据／任务所有者驱动；未知、未配置或不支持如实呈现，不移植夹具数字和“推进当前示例”。不能从代码模块结构重新决定页面，不恢复用户已删入口。

状态还原重点：

- 保存冻结原条目／草稿／来源版本／库epoch，切项目不串写，整库恢复后旧回执失效；新项目不展示旧知识和实体，返回项目保留其阅读与草稿。
- 任务固定项目、执行者与材料版本，查看知识不中止；C仓库补充与J记忆材料整理分开，恢复到同一任务与尝试。
- AI合并／修改／逻辑删除／移动／全局提升确认前不改已有有效知识；过期或撤权禁用旧确认，应用失败不部分改动，恢复旧版本追加新版本。
- 全局复制和AI提炼先预览，确认适用条件后保存；源项目知识保留，全局来源链接不自动授予项目原文访问。
- 计划保存仍停用，明确启用才使用；查看历史不把手动任务改写成计划来源，停用不拒绝旧建议。
- 整库恢复前副本、恢复后停止服务／停用计划／退休授权／清除旧草稿；索引不产生知识新版本，单条与整库恢复分别承载。

每一步完成即落稿，可使用如下记录字段，不留到整批结束才补：

| 字段 | 必须记录的内容 |
| --- | --- |
| 步骤与设计依据 | 场景编号、固定原型SHA、认可／候选状态、对应截图 |
| 实施结果 | 已实现的入口、操作、状态与取消／失败行为 |
| 实际证据 | 真实数据／回执、实际窗口图、必要实际包验证 |
| 对照结论 | 与固定稿的差异、偏差原因及是否已处理 |
| 完成边界 | 已通过范围、未完成项、下一步；生产能力与设计认可分别记录 |

新增候选按其评审状态及后续独立授权推进；本交接不重述或覆盖其他工作区任务的授权。用户后续纠正高于旧稿，发生范围变化时保存新的固定设计与差异记录。
