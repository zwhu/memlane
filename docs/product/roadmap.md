## P1 · 近期缺陷与体验

### 关闭自动采集未真正停止自动采集（Bug，2026-11-25）

- **来源**：2026-11-25 用户明确反馈「关闭自动采集不是真的关闭自动采集」，记录为待修复 Bug TODO。
- [ ] 排查并修复项目/宿主关闭「自动采集」开关后仍继续产生自动采集的缺陷：沿下方技术方案逐层核对开关落盘（项目登记表）、接入网关自动写入门禁、后台补采队列选取与宿主插件缓存/hooks 上报四处是否真实生效；验证关闭后新对话/新工具调用不再写入自动采集记录、重启后保持关闭态、且不影响手动读取与主动记忆操作。
- **状态**：TODO（Bug），已记录、待定位根因与排期修复。

#### 关闭项目自动采集的技术方案（待评审）

- 将开关写入项目登记表，通过接入网关发布带版本的自动采集策略。宿主插件在缓存新材料前检查，后台补采在选取和发送前检查，网关在接收自动写入时再次检查。权限与采集策略独立计算，读取、主动记忆操作和手工补采仍按各自权限执行。先确认网关能区分所有受支持宿主的自动和手工入口，包括旧客户端使用的兼容接口。
- 关闭生效后，取消尚未发送的后台采集工作并保留此前的缓存。已发出的请求按原编号查回执。宿主在关闭期间只推进会话读取水位，重新开启后从恢复点采集，不回读关闭期间的内容。已有积压保留，按当前策略与原回执核对后继续处理。
- 验收覆盖长会话中即时关闭、关闭时写入在途、重启后仍关闭、重新开启、旧客户端及本地网关暂时不可用。关闭时分别核对新工具记录、问答和后台补采的写入回执，避免仅按界面开关或任务状态判断。

- **设计依据**：[视觉规范 V4 §7.7](../design/visual-standards-v4-20261120.md#77-首次启动向导2026-11-25-专注式向导重设计)、可交互原型 [onboarding-prototype/](../design/onboarding-prototype/)。
- [ ] 布局外壳：顶部紧凑步骤条加 `600` 单列，替换左步骤栏；接入右上角「遇到问题」菜单（环境详情、复制诊断、导出诊断包、指定已有组件路径）。
- [ ] 欢迎页：打开窗口即在后台检测 Agent 与组件；并排提供「开始设置」与「让 Agent 代我安装」，后者使用通俗说明加折叠完整指令的弹窗。
- [ ] 第 1 步：只展示已检测到的 Agent；新增「查看支持列表」弹窗；一个都没检测到时显示空态并允许先跳过。

- [ ] 新增完成页；同一宿主统一显示为「TRAE CN」。
- [ ] 产品上线后同步更新 [公测安装指南](beta-install-guide.md) 中涉及安装确认弹层的描述。

### App 记录与日志的可读性和时间（含 TRAE CLI 补丁过滤提示）

- [ ] 梳理 App 中展示的记录、状态提示和日志：用清楚的中文说明发生了什么、为何进入当前状态及下一步操作；技术错误码与操作 ID 保留在诊断详情中。
- [ ] 核对各类日志是否记录并展示事件发生时间；缺失时间字段在事件产生时补记，历史缺失显示「时间未知」（如项目管理页不能仅显示「自动采集已暂停」而不知暂停时间与触发原因）。
- [ ] **2026-11-25 item-fe 的 TRAE CLI 补丁记录过滤**：在 App 的「因采集规则未采集」提示中直接展示具体原因（如「TRAE CLI 补丁正文在命令路径检查中命中 `*.key` 规则，记录保留在本机」，同时说明规则命中本身不足以确认补丁包含密钥）。说明：2026-11-25 复查两条 `apply_patch` 记录均按 shell 命令扫描误判普通 `.key` 属性，两条摘要均已取得日常库回执、原补丁留存本机受限文件；通用摘要回退因模拟写入被拒时会覆盖原队列而暂缓，补丁结构化采集与过滤规则调整待后续排期。

## P3 · `v1.0` 正式版增量

由原公测发版规划（[v0.1.0-beta.1 发版归档](../archive/release-v0.1.0-beta.1-20261121.md)）沉淀的正式版必做增量：

- [ ] **Apple Developer ID 签名与 `notarytool` 公证装订**：消除首次打开的 Gatekeeper 拦截，同时解锁 macOS `SMAppService`「登录时静默启动」完整系统登录项体验。
- [ ] **自维护只读国内静态镜像源**：将 Cognee 上游源码与官方插件原始归档（保持原归档字节与固定 SHA256）同步至自维护国内静态存储作为一级源，公益反代（`gh-proxy.org` / `gh-proxy.com`）降级为二级备选。
- [ ] **应用内自动更新（`mygo.Updater`）**：落地 [macOS 更新调研](../research/macos-updater-20261119.md) 规划的签名兼容清单与停服/独占锁协调机制。
- [ ] **图形化卸载与依赖资源清理**：在 M2 已交付的 [CLI 安全卸载器](../../scripts/uninstall.py) 基础上补齐 GUI 卸载入口——执行前展示独占/共享/用户原有资源清单与预计释放空间，允许保留记忆库与配置，按所有权备份清理宿主接入项并严禁删除运行中或其他应用仍引用的资源（防复发规则见 [运行包误清理复盘](../engineering/runtime-package-cleanup-incident-20261111.md)）。
- [ ] **逐步开放其余编码宿主**：按真机闭环验收进度恢复开放 Claude Code、Cursor 与 OpenCode。

## P4 · 中远期方向

### 本机 Docker、远程 Cognee 与跨主机记忆管理

- **来源**：2026-11-07、2026-11-17 提出，2026-11-25 完成架构调研。
- [ ] 评估并落地本机 Docker 与远程 Cognee 部署，以及桌面端管理其他主机记忆的能力（见 [Docker 部署架构调研](../research/docker-deployment-architecture-20261125.md) 与 [历史部署方向](../archive/deployment-options-20261117.md)）。
- **边界**：坚持单人定位、不做多租户；远程管理不自动包含主机间数据同步、合并或本地/远程库自动合并；当前不提前引入多主机数据模型或远程端口。

### 大量 Agent 统一驱动适配与多客户端能力识别

- **来源**：2026-11-12（多客户端形态识别）、2026-11-18（大量 Agent 统一驱动）。
- [ ] 核对各家官方 SDK / RPC / ACP / 结构化 CLI 接口，建立覆盖 Agent 家族、CLI 与桌面形态、执行位置、实际配置目录及逐项能力证据的连接能力账本（参考 [多 Agent 驱动协议](../research/agent-driving-protocols-20261118.md) 与 [电脑级接入契约](../architecture/agent-connection-contract.md)）。任务驱动、官方采集/召回与画像导出分别验证，不由品牌外观推定覆盖。

### 基础配置集中记录（2026-11-11）

- [ ] 将 Agent 可执行文件路径、配置目录及相关环境变量解析结果集中记录至 Memlane 自有用户级配置文件（如 Application Support 下的 `config.json`），便于查看与排查；严格与采集授权、运行回执及原文数据分离，不写入仓库或真实聊天记录。

### ChatGPT 普通对话采集（2026-11-12）

- [ ] 先做入口可行性验证，再评估接入 ChatGPT 普通聊天的原文采集（与本机已通过真实 hook 适配的 Codex Desktop 编程任务分开）。复用原文队列、去重、离线重试与提炼链路，明确同名项目不自动等同本机仓库。
- **初步讨论估算（非排期）**：手动导入 1–2 人日；网页自动记录 4–7 人日；桌面 App 可行性验证 0.5–1 人日后暂估另需 5–10 人日。

### 词云与 Top-K 记忆（2026-11-08）

- [ ] 增加记忆词云（关键词与主题分布）与 Top-K 记忆展示；实施前再定权重规则、排序依据、时间窗口与范围，不预设检索命中等同实际采用。
