# Memlane 产品定义

Memlane 面向程序员，是 macOS 本地优先的**单人 Agent 记忆客户端**（不做多租户），采用 **MyGo Native 桌面端 + 固定版本官方记忆引擎（Cognee）**，让多个编码 Agent 共享同一份项目记忆，并提供独立、克制的阅读与管理界面。唯一领域词表见 [CONTEXT.md](../../CONTEXT.md)。

## 1. 产品定位与部署边界

- **本地单库闭环为主**：日常运行、桌面阅读与 Agent 接入统一连接同一官方 Cognee 单库，不复制第二份正文或独立索引。
- **后续部署方向**：本机 Docker 与远程 Cognee 记为后续演进方向（见 [Docker 部署架构调研](../research/docker-deployment-architecture-20261125.md) 与 [历史部署方向记录](../archive/deployment-options-20261117.md)）。连接远程时 App 与 Agent 共用同一远程库，不自动合并本地库。
- **明确退出范围**：内容版本与恢复、审核建议、复杂定期整理计划、旧多模型并行分派、配置历史、索引维护中心与静默自动更新器已退出当前设计，不再作为开发清单（仅在「设置 › 服务 › 版本与更新」保留轻量手动检查 GitHub Releases 更新与下载页跳转入口）。
- **事实边界**：原型与设计示例不代表实际接入或工程交付；工程状态、真机验收与缺陷证据分别登记，不从历史完成项推导当前版本通过。

## 2. 内容分层与唯一真相

### 官方数据源与内容类型

Cognee 是唯一内容数据源。Memlane 通过官方接口读取记忆条目、原始记录、会话、片段、索引结果与图谱，不保存正文副本；客户端仅保存必要配置、项目到 dataset 的关联、界面偏好及外置轻量元数据（如只读召回计数 SQLite 与本地已读状态 `.local/daily/knowledge-read-*.json`）。

- **记忆**：面向用户的整体名称（覆盖导航、统计、搜索、详情、设置与提示文案），不是与知识条目、原始记录并列的第三种类型。
- **记忆条目（知识条目）**：官方实际保存、供后续复用的明确结论。
  - 通过官方 `remember`、带 `user_context` 或现有适配 `memory` 标签直接写入的条目亦归入记忆列表与搜索，标记为「直接保存」，不伪造 `session_learnings`、接受理由或来源会话。
  - 详情展示「记忆点」（已有分类规则与学习情境，缺失如实显示「未记录」，不补生成）与已记录的 Agent 召回次数（人工搜索不计入，同次多片段按官方 ID 去重）。
- **原始记录**：官方实际保留的会话问答、工具记录、文档（`project_docs`、`agent_actions`）或片段。原始记录被检索或提炼后仍是原始记录；会话缓存取得持久化成功回执前不计作已采集记录；只有官方实际产出记忆条目，记忆列表才增加条目。
- **通用记忆**：存储于官方独立通用数据集（`ensure_common`），按「个人偏好／通用经验」分类，与项目记忆分离。Agent 仅在具备读权限时于检索与召回入口合并使用，项目明确约定优先；不自动将项目记忆提升为通用记忆。
- **用户画像**：各家 AI 来源独立保存为 Markdown 文档（存放于同一日常官方库），不传入 Memlane 共同资料、不自动合并为通用记忆。
  - 所有来源均由**用户手动触发**，不做后台自动尝试：支持本机只读调用的 Agent 提供「尝试导入」，失败或不支持走「复制提示词 → 在对应 AI 日常会话运行 → 粘贴结果保存」。
  - 导出慢任务不按固定总时长中断（区分活动、等待、退出与用户停止，保存阶段不可取消）；重开仅加载已保存文档，正文按原样 Markdown 展示不改写。

### 记忆日期与默认语言口径

- **记忆日期（零侵入方案 B）**：优先取外置 `provenance_store` 按同一项目与 `state_key` 锁定的最早日期（重提炼不漂移、不重复计数）；其次取 Cognee 原生 `session_date`；缺失时回退采用 `createdAt` 对应本地日历日（实际入库时间 `createdAt` 单独保留）。首页热力图、日期筛选与最近记忆统一采用该日期。
- **新记忆语言**：遵循应用默认语言，当前固定简体中文（`zh-CN`，在原提炼模型调用中指定，不增加额外翻译调用、不回写既有英文记忆；JSON 字段、枚举、实体标识、代码符号与文件路径保持原样）。

## 3. 核心页面与交互边界

默认与最小窗口为 `1200×820`（允许放大），首页与设置采用宽幅内容，项目、通用记忆与用户画像采用三栏阅读。完整视觉与交互规范见 [视觉规范 V4](../design/visual-standards-v4-20261120.md) 与 [首次启动向导原型](../design/onboarding-prototype/)。

| 入口 | 核心范围与边界 |
| --- | --- |
| **首页总览** | 顶部统计（已使用天数、记忆与原始记录总数）+ 记忆热力图 + 双栏「最近记忆」与「近期动态｜最近搜索」。自动召回动态整行可点击并带「本次召回」筛选进入项目；近期搜索仅记录用户在搜索面板主动回车或关闭保存的查询词，不计 Agent 自动召回。 |
| **项目页（三栏）** | 下划线标签切换「记忆／原始记录／图谱／管理」。记忆只读，支持分类/未读/时间与召回排序、复制及原位查看来源会话；原始记录采用滚动自动追加（首批 30 条）；工具记录关系图谱全局默认关闭，支持项目级「跟随全局／开启／关闭」并手动触发创建（不回扫关闭期）；「管理」置顶「消息与采集状态」三桶，含项目信息/改名、Agent 三档权限与图谱设置。 |
| **通用记忆（三栏）** | 「个人偏好／通用经验」阅读、筛选、原位新增/编辑与删除，保存与提炼状态分别表达。 |
| **用户画像（三栏）** | 按 AI 来源独立展示 Markdown 文档，提供「尝试导入 / 手动导入 / 重新导入 / 复制正文」。 |
| **全局搜索（`⌘K`）** | `640px` 单栏命令面板，统一检索已关联项目记忆、通用记忆与原始记录（无全局「全部记忆」侧栏入口）；支持「仅当前项目」范围芯片与重开恢复上下文，输入关键词显式按回车触发检索，命中结果直达对应三栏页。 |
| **全局设置** | 三标签分组列表：「记忆提炼」（来源二选一互斥激活 + 外观三态）、「Agent 与模型」（宿主接入与 Provider 管理）、「服务」（组件状态、脱敏诊断、运行环境镜像源与手动检查更新）。 |
| **首次启动向导与状态栏** | 专注式单列首次启动向导（欢迎 → 选择 Agent → 准备环境 → 接入 → 记忆提炼 → 完成，含「让 Agent 代我安装」零 Skill 入口）；macOS 顶部状态栏海獭图标与 `300px` 弹层同步外观、后台保活与静默启动开关。 |

- **侧栏与项目管理**：侧栏项目行仅保留项目切换与启用后新增记忆的未读数（人工打开正文消未读，后台预取与 Agent 召回不计已读；不放行内悬停菜单或异常圆点）。「＋」新建项目需本机源文件夹；**关联已有官方记录直接复用原数据组、原内容与原权限，无需选择本机源文件夹**。已关联项目仅支持在「管理」修改名称，既有数据组关联固定。

## 4. 自动采集、记忆提炼与权限原则

- **电脑级身份与项目级 ACL**：受管 Agent 按类型与独立 profile 各自持有独立官方子主体与 `X-Api-Key`（管理 owner 仅用于管理）；电脑级连接准备只建立身份与凭据，不自动授予任何项目、通用记忆或受保护数据集（`ml-user-profiles`）权限。项目权限分为「不可访问（`none`）」「只读（`read`）」「读写（`maintain`，含 `read/write/delete`、不授 `share`）」，修改后即时保存；自动采集与提炼写入随读写权限联动，只读或不可访问时停止写入。详见 [电脑级接入契约](../architecture/agent-connection-contract.md)。
- **复用官方采集与提炼管线**：自动采集、筛选、冷却/水位、去重、提炼与图谱优先完整复用 Cognee 官方插件与管线，不另建独立客户端提炼防抖或替代队列。已获准且确定未发送的官方 buffer 由后台自动续存，采集落盘不等待提炼完成；关闭采集时先推进无正文水位、不回扫禁用期，关闭提炼不取消已在途任务。
- **单条隔离与消息提醒**：新采集消息首发前持久保存唯一编号，官方原始记录与元数据凭证同事务提交；单条明确拒绝、原编号退避及单会话异常只约束对应材料/会话，不阻塞其他已授权健康消息（见 [队列隔离契约](../architecture/queue-isolation-20261119.md)）。缺唯一凭证的旧未知记录不自动重发，可由用户知晓/归档收进默认折叠历史区（保留原消息与失败证据，不标为已保存）；「需要你处理 / 系统异常 / 进行中与待提炼」三桶清晰分流，同类新失败或新消息重新提醒，当前异常全部解决或明确知晓后才撤下异常提醒。
- **提炼模型互斥激活**：Agent 模型代理（支持已连接宿主复用其既有登录与有效模型，不复制宿主密钥为 Provider）与直连 LLM Provider / Ollama 允许配置并存，运行期有且仅有一个 `active`。查看、编辑或保存配置均不自动启用，仅经确认后的服务回执才更新唯一 `active`（见 [有效模型契约](../architecture/agent-effective-model-contract-20261118.md)）。未配置的模型采样/输出参数保持省略，用户显式填写的 `0` 必须保留。

## 5. 依赖复用、安装确认与排障原则

- **先复用，安装前明确确认**：首次准备及后续补装统一先检测本机已有 Python、Cognee、向量模型、运行库与安装工具；兼容可用直接复用，不另装副本。缺项须列明名称、用途、版本、来源、下载体积与位置，经用户明确确认（绑定计划摘要）后才下载安装；存在但不兼容时说明原因，允许改选已有路径、手动准备后点击「重新检测」或确认补装。绝不擅自升级、删除或接管用户已有环境与模型。
- **支持用已有 Agent 排查安装异常**：安装失败时支持「用 Agent 排查」、复制脱敏排查提示词及导出脱敏诊断包，且不依赖 Python、Cognee、Memlane 服务或模型桥先就绪。诊断材料包含失败步骤、依赖检测结果、安全错误码/退出码、相关日志与已尝试动作，严格排除密钥、登录文件与记忆正文。Agent 建议不等于授权修改，修复后须经安装器重新检测通过才继续原步骤（背景调研见 [环境准备技术报告](../archive/environment-readiness-reliability-20261117.html)）。
- **开发与安装磁盘门禁分离**：50 GiB 预留 / 55 GiB 提前停止仅适用于本仓库开发态 `scripts/task.py`；已安装 `.app` 运行态不继承开发阈值，采用 2 GiB 最低 / 5 GiB 告警阈值，并保留明确占用预算与真实磁盘 I/O 错误提示。
