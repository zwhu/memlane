# F1a 检索索引重建契约

2026-11-08，F1a 本机通过，见 [验证](p4-index-recovery-validation.md)。沿用受信本机服务、原文版本与现有持久索引 jobs；不调用模型、不整理正文、不扫描项目代码。F1 helper 替换单独未通过，见 [诊断](p4-helper-replacement-validation.md)。

## 输入、授权与决定

App 设置提供「重建检索索引」，栏内说明并确认。用户选择一个已登记范围或全部本机范围；服务核对范围，不接受路径、数据库句柄或模型输入。日常 Agent 与后台整理没有此操作。每次开始使用稳定 UUID；同 UUID/同范围返回原任务，同 UUID/不同范围拒绝。拒绝或离开确认页不入队。

## 来源与原子性

确认时在短 SQLite 事务中冻结该范围全部 active 当前 memory/revision。已删除、归档及失效派生摘要排除，原始记录与有效知识均按现有原文契约重建。最多 10000 项，超限明确失败，不部分入队；更大库可按范围执行。

同事务记录任务与项目，清除目标当前 indexed_revision/generation 并将现有对应 jobs 设为 pending；正文、版本、来源、用户决定、活动、使用记录和代码图谱历史保持。索引绑定是派生信息，未得到新成功回执前不认定可检索。SQLite 失败整体回滚，不调用 Rust；网络/worker 等待不持 SQLite 写事务。

## 执行、恢复与记录

复用串行 Rust 原文索引，目标 identity 为 memory/revision，不创造新知识版本。发布仍检查当前版本/active状态；重建期间编辑、归档、来源失效使旧目标过期，不能绑定到新版本。重启重放既有 pending/failed/indexing jobs；用户明确停服后保持 stopped，只有明确 resume 后继续索引。

持久任务记录每个目标的 queued/completed/failed/expired 状态及错误。成功回执原子更新索引和对应任务项；失败保留正文、状态和最近错误，既有索引重试恢复后可完成并保留曾发生的错误。任务聚合区分进行中、完成、部分失败、失败和全部过期。已完成项目的历史状态不因后续编辑或另一重建倒退。任务状态表示索引回执，不宣称模型质量或正式分发。

本操作不删除引擎目录、不恢复数据库备份。数据损坏恢复在独立离线拥有权步骤验收；代码图谱仍由用户明确重新扫描，不能因重建原文索引自动开启代码项目。

## 迁移与验收

schema12→13 仅新增实际维护任务表。复用迁移前唯一 owner 的一致性 VACUUM INTO 备份；先用非空 WAL 临时 v12 库逐表证明原数据、来源、活动、代码配置/历史和备份保留，备份失败不迁移。旧 schema12 helper 对 v13 明确拒绝，不能冒称旧客户端可读新 schema。

真实完整 App 与 Rust 验收：保存/编辑/归档的合成知识，显式停止服务后移走该合成根的派生原文索引作为故障；当前内容与历史仍存在。实际 App 确认重建、稳定任务/离页返回、当前版本检索恢复、旧版本排除、重启持久及原代码开启状态不变。SQL 故障、版本变化、重复操作、失效摘要与旧客户端拒绝另用明确夹具。实际上查看设计图和最终系统窗口截图，正常静态原文流程不需模型。
