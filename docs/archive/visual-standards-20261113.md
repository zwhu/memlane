## 1. 依据及优先级

1. 用户已选择 A「清晰总览」。固定原型提交 `3c1c845c4af58f9afd4fcdd5c97008d1a27a3563`，目录 `build/p3-prototype/prototypes/visual-refinement-20261113/`。
2. 样式以 `style.css` 为基础，叠加 `suite.css`；首页结构取 `design.js` 的 `home`、`calendar`、`row`、`sidebar` 等函数。必须取覆盖后的最终值，不能只读第一份CSS。
3. 用户提供的 A 稿和当前 Native是本次差异复核依据。前者是设计示例，后者是实际数据；数量、标题内容及任务状态不要求相同。
4. Native 的默认字体、Button默认外观或现有代码参数不构成设计依据。实现困难须记录具体缺口，不能自行删掉星期标注、时间线、标签或变更组件层级，再写成“轻微差异”。

以下数值均为逻辑px（MyGo DIP），不是Retina图片像素；通常1 DIP对应2个截图像素。

## 2. 字体与层级

2026-11-18用户针对日常侧栏指出品牌、导航、项目名称及未读数字“不清晰”。本轮局部覆盖：侧栏采用系统原生字体平滑（`sidebarTheme.Antialiased=false`），导航／项目名显式系统字体13px、500字重、零字距、`homeInk`；品牌21px、600字重、零字距、`homeInk`；未读数字11px、600字重、`#334a5f`。正文区域仍沿原参数，不改SDK或全App字形绘制。此最新反馈覆盖下方固定稿在侧栏相应参数；不以全局加粗替代其他区域的字体角色。定向Overview／UnreadBadge检查通过，已在实际Native核对侧栏呈现；后续仍以用户可读性反馈验收。

字体使用macOS系统字体，中文采用系统对应字体；代码另用系统等宽字体。显式指定字重，避免控件继承与默认值造成整页偏粗。MyGo的`.Bold()`为700，不能用于代替稿中的500／550／600。

固定稿使用`-webkit-font-smoothing: antialiased`；Native首页主题使用等价的不加粗平滑字形绘制，不能靠降低字重或变浅字色抵消差异。固定SDK补丁及可复现开发入口见[开发说明](../architecture/development.md)；其他页面保持默认字体绘制。

常用间距采用4／8／12／16／24／28／32；稿中明确的3／9／13／17／21等组件参数按下节执行，不为凑间距档位四舍五入。

## 5. 首页组件

### 导航与顶栏

- 主导航图标17px，图标到文字11px；内边距10×12，圆角7；选中只有浅蓝填充和选中字色／字重。
- 项目导航上下内边距8，普通项目保持紧凑；同名项目显示路径，名称省略、完整路径可通过已有提示读取。不能用名称作身份。
- 通用知识使用稿中的文档／知识线框图标；设置、文件夹、搜索、箭头与刷新统一单色SVG，线宽1.65。不要用人像图标或字体字符`›`、`↻`替代不同几何的设计图标。
- 品牌资产沿用原资源，不在本次更换App图标。
- 顶栏搜索宽191、内边距7×10、圆角7；搜索图标14、文字11、快捷键10。刷新总览作为轻操作，不能成为粗体主按钮。
- 返回只在有真实返回目标时提供；不为了复制静态稿显示无效返回。搜索与Cmd+K继续接现有页面。

### 知识热力图

- 完整最近365个本地日期，真实新增知识口径不变，不能复制原型的静态日期和强度。
- 日历整体最大900宽，居中；格子为正方形，间距3、圆角2，随允许的桌面宽度均匀伸缩。
- 保留左侧星期列“一／三／五”，与实际星期行对齐；月份标注“11月／12月／1月…”而非只有数字。沿用已验日历起点，前后补位格透明。
- 月标9px、星期8px；月份与网格间距8，星期列与网格间距9。
- 期间显示`YYYY.MM — YYYY.MM`，精确日期和数量在单格提示中读取。
- 空格`#f0f3f6`；图例四档`#edf1f5`、`#d6e2ee`、`#b0c6db`、`#89a8c8`。真实数量到强度档的映射单独固定，不因视觉调整改变统计。
- 下方显示“今天新增 X 条知识”，不额外拼接一条全年统计说明。右侧少→多图例，格8×8，间距4。
- 选择日期后有明确选中边框、日期说明及清除入口，下方知识随之筛选；顶部总数保持全局。

### 最近知识

- 标题区下方一条轻边线；行与行连续排列，列表容器gap为0，行上下padding17。
- 文件图标容器28×33、圆角6、1px细边、背景`#f7f9fc`；内部图标15。图标到正文间距13。
- 标题12px／500／行高1.7，两行封顶，超过才省略；不先把可读标题硬截到一行长度。
- 元信息距标题9；“知识”为独立浅蓝标签，padding2×6、圆角4，旁边日期`11月13日 · 00:56`。不能合并成一段普通“知识 · 日期”文字。
- 右侧箭头12px，色`#a9b4bf`，不随标题挤压。
- 官方标题和可读首句保持真实；不复制示例句子，不调用模型造标题。布局验收用相同夹具，不能用两份不同长度内容证明换行一致。
- 保留现有分页能力；分页采用11px常规字重、轻按钮及24px级操作高度，不沿用大号默认Button样式。默认三项，分页只在确有更多时显示。

### 近期动态

- 内容面板内边距上18、左右18、下5；背景`#fafbfd`、边线`#eaf0f4`、圆角11。
- 每条采用17px状态列＋9px间距＋正文；圆点直径13、边线1、内部符号8，位于标题首行。
- 成功圆点：边线`#b5c8bd`、背景`#f6faf7`、符号`#749082`；处理中／受理：`#c1cede`／`#f3f6fb`／`#839bb5`；失败：`#cfb5a3`／`#faf7f2`／`#9f7f66`。
- 时间线在圆点中心下方，1px `#e4eaf0`；从圆点下沿延伸至下一条前，最后一条没有尾线。不能只留裸露的勾号或感叹号。
- 标题11px、行高18；时间10px，右对齐；项目／状态在下方，间距5；每条下padding23。
- 状态文案取真实受理、处理中、完成、失败；不同状态导致行高不同是合理的，不能为了凑示例高度改状态或制造按钮。
- 处理中／受理的“查看项目”按官方数据组稳定身份接现有项目页；无法唯一定位时不猜同名项目。入口与状态说明左边缘对齐，按钮贴合文字宽度，不居中或占满整行。
- 诊断入口为轻文字展开，复制后同页反馈；详情占用动态区内部内容高度，不扩大整个首页。
- 默认至多三条；当前知识页只有一／两条时，默认动态同步收紧到一／两条，通过“查看全部动态”读取其余；“查看全部动态”和展开后的“加载更多动态”采用轻量11px文字操作，禁止整栏宽的大号默认按钮压过正文。
- 用户最新要求：“近期动态这里展开之后太长了，定个最大高度，和最近知识的高度要对齐”；又指出“少的时候也很丑”。采用少量时自然收紧的处理，不保留初次候选强加的240 DIP最小高度：两栏内容区底边对齐，底部操作独立一行、最小24高且对齐。最大高度由当前最近知识区自然高度确定；成功空态保留100 DIP内容区用于提示，不制造知识条目。动态列表在剩余高度内滚动，标题／刷新和收起／加载更多固定可达；展开、加载更多及长诊断不得把项目区推远。内容超出时，顶部／底部分别按滚动位置使用18／24 DIP浅色渐隐，避免边缘硬截半行，滚动条保持可见。刷新保留动态内部滚动；显式收起恢复其顶部。此条覆盖原先动态不设内部滚动的规则。用户尚未回应两种布局偏好的文字选项，此处为Agent按反馈采取的默认处理，不记录为已获用户视觉认可。

### 项目卡与页脚

- 三列，gap12，卡padding15、最小高94、圆角8、边线1。
- 图标容器30×31、圆角6、背景`#edf3f8`，图标16；与名称区域间距11。
- 名称12px／500，最多两行；路径10px／400／行高1.5，可换行。同名不同路径必须看得出区别。

- 页脚10px常规字重、低对比文字；状态来自实际服务。项目少不改变其固定位置。

## 6. 实现约束

### 交互状态统一规则

| 状态 | 规范 |
| --- | --- |
| 默认／悬停 | 导航hover背景`#dee8f2`；知识行`#f7f9fb`；项目卡边线`#b4c7d9`、背景`#f8fafc`；轻操作hover字色`#345e86`。悬停不改变字号、字重、边线占位或布局 |
| 选中／焦点 | 导航选中沿用固定填充；日期选中独立于今天和强度表达。键盘焦点可见，不能只依赖hover；焦点环参数见第3节 |
| 禁用／执行中 | 禁用透明度0.5且不响应操作；执行中同一操作防重复提交，保留按钮占位，用真实状态文案反馈，不伪造完成状态 |
| 加载／空／失败 | 首次加载用占位或读取提示，不能显示为真实0；成功空结果才显示空态；刷新失败保留上次内容并明确未刷新。局部失败在所属区域反馈 |
| 展开／返回／复制 | 展开状态、日期、分页及滚动按现有契约保留；复制后在原操作附近反馈；不依赖瞬时全局提示作为唯一结果 |
| 动效 | hover颜色／背景过渡150ms，不以动效制造任务进度或结果；减少动态效果时取消非必要过渡。没有新动效设计时不自行添加入场或循环动画 |

后续修正应将上述颜色、字体角色、间距及组件外观集中为首页的视觉参数与复用函数；视图只引用这些定义。不得在每个控件处反复堆临时数值。是否扩展成全App主题，后续独立决定。

本次保留现有统计、官方客户端、权限、返回栈、取消和请求代次；只改视觉层及确有需要的首页状态接线。不改业务数据来接近截图。

## 7. 验收与不通过条件

功能通过、编译通过、UI fixture通过和视觉通过分开登记。当前Native功能证据继续保留，视觉结论为未通过；不再称“已自验完成”。

| 检查 | 验收标准 |
| --- | --- |
| 对比条件 | 同一外接显示器；同一1200×820或1440×900逻辑尺寸；同DPR、100%缩放；去掉浏览器外壳后比内容区域。不能仅凭看起来差不多的窗口尺寸比较 |
| 基准内容 | 用同一份不写日常库的13项目／同名路径／三条长标题／成功、处理中、失败三状态夹具比视觉；再用真实数据核对功能，证据分开 |
| 首屏关键位置 | 侧栏、顶栏、正文边界、欢迎区、热力图上下沿、知识／动态顶边逐项记录；固定尺寸目标误差不超过2 DIP，文字抗锯齿不作几何误差 |
| 字体 | 角色、字号、字重、颜色符合本表；相同内容应保持同样的标题行数。字体后端差异先量化，不接受整页偏粗作为平台特性略过 |
| 组件 | 星期标注、类型标签、圆点时间线、图标、边线、轻操作均齐全；漏组件或自行改变层级即不通过 |
