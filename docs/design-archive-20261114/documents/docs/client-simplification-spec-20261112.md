# Memlane 首个可用版本规格

日期：2026-11-12。状态：2026-11-13 已获明确实施授权，使用 dev 模式；交付尚未完成。

Memlane 面向程序员，让编码过程中的知识可以在后续会话中继续使用，并提供独立、美观的 macOS 阅读界面。本阶段以最短路径交付日常可用版本：记忆能力交给 Cognee，Memlane 只承担桌面呈现、必要配置和 Codex 模型适配。

配套实现方案见[最小实现技术方案](client-simplification-technical-plan-20261112.md)。两份文档共同构成本轮方案入口；旧代码和旧功能数量不构成保留理由。

## 决策依据

### 用户已确定的约束

| 决定 | 本阶段含义 |
| --- | --- |
| 项目要足够简洁，尽量复用 Cognee | 以官方接口和行为决定产品边界，不补建第二套记忆系统 |
| 不考虑之前代码和已实现功能的沉没成本 | 从用户价值和必要职责决定架构，旧实现仅是可选材料 |
| 保留 Codex 订阅推理，接受额外集成成本 | Cognee 的生成模型请求交给已登录的 Codex；不以另填云模型 Key 替代 |
| 第一版就要独立且美观的桌面界面 | 官方 Web UI 不能代替首版产品交付，允许复用官方图谱组件 |
| 开发启动器管理，helper 留到 release | 关闭窗口后后台继续；重启电脑后手动启动；不以系统 helper 修复或完整包为前置 |
| 旧内容直接删除，不迁移 | 删除旧 Memlane 正文、历史版本和独立索引，不上传 Cognee，不开展迁移或历史归档工程 |
| 本阶段先只读 | Memlane 提供知识、原始记录、搜索、出处和图浏览；手动新增、编辑、删除后续再接官方接口 |
| 移除项目与 Agent 权限管理 | 所有有效连接的 Agent 可读写；项目只用于归属和检索分组；保留官方连接认证 |
| 不重复验证已经走通的路线 | 不设置可行性实验、技术选型验证或重复模型评测阶段；直接实施，出现具体错误就修复 |
| 窄窗口不做 | 首版默认及最小窗口为 1200×820，允许放大；删除窄窗口适配、问题修复与验收要求 |
| 实施中清除昨天的问题代码 | 本次指令前已暴露问题的旧实现、临时补丁和废弃分支随相关模块替换退出，不把旧问题路径带回新架构 |
| 清代码前先打 tag | tag 指向包含相关未提交源码的可恢复快照；完成这一步才开始生产代码清理 |
| 当前进入精简版实施 | 开发前提交并打本地 tag；授权本次源码替换与日常接管，保护官方数据和运行依赖，不恢复旧全量 Goal，不打完整包 |

“迁入 Cognee 后删除旧链”的中间决定已被“旧内容直接删除，不需要迁移”替代。此前关于三个迁移数据集、历史资料转换、逐版本迁移核对的方案全部取消。

### 必须承认的成本

最省工程量的组合是官方服务、官方插件、原生模型 API 和官方 Web UI。用户已选择保留 Codex 订阅推理与独立桌面体验，因此本阶段有两项明确的自有工作：模型适配和界面。其余部分不能再借这两项要求扩大为后台平台。

已做过的功能不自动进入首版。遇到官方能力缺口，先缩小该入口的承诺；只有缺口阻断本节核心流程时才补最小适配。

## 目标与完成定义

### 核心用户流程

> 启动 Memlane → 正常使用 Codex 编码 → 官方插件采集实际材料 → Cognee 调用 Codex 完成处理 → 官方保存实际知识 → Memlane 阅读知识与出处 → 新会话由官方插件召回并使用相关知识。

第一条日常链路固定一个实际使用的 Codex 入口和一个项目。不同 Codex 客户端的行为分别记录，不把 CLI 的结果等同 Desktop。后续再接第二个实际需要且有官方集成的 Agent，使用同一个 Cognee 服务；不为首轮并行扩展四种 Agent。

### 本阶段交付结果

1. 有独立、美观、可持续阅读的 macOS 桌面窗口。
2. 有一个明确的开发启动入口，管理唯一日常 Cognee 实例。
3. 正常编码产生材料并经过官方流程形成可用知识，无需人工补写验收数据。
4. 后续真实任务实际取得并使用相关记忆。
5. 桌面内容与 Agent 使用的内容来自同一官方存储。
6. 旧自有内容链退出生产路径，不再保留双写、双读或隐式回退。

知识数量增加不是收益标准。实际收益表现为后续任务不必重复交代已保存约定，或者能使用先前解决问题的经验。官方本次没有生成知识时，显示真实结果，不制造条目。

## 界面要求

### 视觉与信息结构

独立桌面界面是本阶段硬约束。采用浅蓝连续侧栏、白色内容区、紧凑排版和单色图标。首页保持宽幅内容；项目阅读采用导航、列表、正文三栏。图谱区域允许承载官方 Web 组件。

默认及最小窗口统一为 1200×820，允许放大。窄窗口、响应式断点、窄窗专用布局和相关问题不进入设计、实现或交付检查；已有窄窗失败记录保留事实，状态记为范围取消，不再继续修复或计入本版未完成项。

保留已认可设计中仍服务于本阶段功能的布局、阅读体验和交互规则。删除退出范围的功能入口，不为保留旧页面结构重新实现后台能力。设计参考入口为[设计目录](ui-redesign/design-catalog.md)，其中被本规格删除的功能不再作为还原要求。

### 页面范围

| 页面 | 必须提供 | 交互要求 |
| --- | --- | --- |
| 首页 | 使用天数、知识／原始记录总数、知识热力图、近期动态、项目入口、最近知识和连接状态 | 全局统计不随日期筛选改变；不出现虚构统计，不以空页面掩盖服务错误 |
| 项目知识 | 当前项目知识列表、分页、搜索、选中正文 | 标题、正文、来源对应同一官方身份；搜索不局限于已加载的一页 |
| 原始记录 | 会话或文档列表、Markdown 阅读、工具信息展开 | 只呈现实际保留内容，截断或来源缺失如实说明 |
| 知识出处 | 官方关联的会话、文档、片段或来源信息 | 返回后保留搜索、选中、滚动和展开状态；不伪造逐轮关联 |
| 图谱 | 官方画布及现成面板、当前项目范围 | 节点和来源跳转使用真实 ID；部分图不称完整图 |
| 设置 | 官方服务位置、Codex 状态、必要项目关联 | 一个当前处理方案；不引入配置历史、审批和多后端调度界面 |

开发阶段后台由启动器管理。首版不另做桌面服务管理中心；设置页提供可理解的连接状态和开发入口说明即可。浏览、搜索不应因为后台状态轮询而卸载已有正文或清空数量。

首次加载可以显示加载状态。已有内容刷新时保持阅读位置；项目改变、官方对象被替换或来源确实失效时撤下不再有效的内容。官方替换旧知识 ID 后，显示内容已更新，不把旧正文继续标为当前。

### 只读的准确边界

只读限制的是 Memlane 知识界面的手动内容操作，不禁止官方插件保存材料，也不禁止 Cognee 更新其自动生成知识。代码索引开关和服务停止属于运行操作，不属于知识编辑。

不展示编辑、删除、恢复历史等尚未进入范围的按钮。不通过隐藏 UI 对所有 Agent 建立读写权限体系。

## 连接与记忆处理

### Agent 连接

优先使用对应 Agent 的官方集成。首次按官方安装和信任流程完成连接，首版允许一次性官方安装步骤，不开发通用插件安装平台。

所有接入指向同一个本地 Cognee 地址，并使用同一官方身份；不为每个 Agent 建立隔离账号。连接状态分别说明插件是否安装、宿主是否需要重载、服务是否可连接。插件安装成功不直接显示成“已产生记忆”。

项目和 dataset 仅决定材料存放位置和搜索分组。选择其他项目不需要权限申请。第一条日常流程以明确项目为范围；没有可靠归属的材料沿官方行为处理，不由客户端猜测项目。

### Codex 推理

Codex 是当前唯一处理模型入口。适配层只接收模型输入、输出结构要求和执行参数，调用 Codex 并返回结果。知识提炼、写入、更新、图谱和任务编排仍由 Cognee 负责。

处理上下文与正常编码上下文分开，不携带采集插件、项目历史、代码修改工具或记忆写入工具，避免处理结果被再次采集。复用登录状态不等于复用完整日常 Agent 配置。

首版采用一个固定处理配置。修改后通过停止并重新启动后台生效，不提供运行中切换模型、多配置并存及复杂验证账本。不能静默换到另一个供应商或另填模型 Key 的路线。

Codex 负责生成模型推理；向量模型继续使用 Cognee 支持的嵌入能力。二者分别说明，不将 Codex 登录状态描述为已提供向量模型。

### 状态与错误

材料接收、官方处理、知识产生、可检索和后续使用是不同事实。界面尽量直接使用官方状态；仅在官方确实提供对应字段时显示处理进度、结果和错误。

没有真实进度时显示正在处理，不编造百分比。结果未知时保留未知，不自动重发。官方无任务取消接口时，不提供虚假的“取消成功”；开发入口仍可停止所属进程，但要保留已经发生的部分写入。

## 图谱范围

实体关系图和代码图谱均复用官方能力。前者呈现知识、文档、片段与实体之间实际存在的关联；后者呈现官方抽取出的代码结构。两者不混成一个“所有图谱已完成”的结论。

代码图谱按项目显式开启，新项目默认关闭。首次开启调用官方索引；后续源码修改通过“更新代码图谱”调用官方更新。首版不做文件监听或自动更新调度。关闭后不再发起新扫描，已运行任务按官方实际取消能力处理，不显示虚假取消结果。开关不构成 Agent 读取权限，所有已连接 Agent 可读取已有数据。

代码图谱是记忆主线后的独立工作包。首版不用自绘算法，不增加美化或性能专项。官方组件不支持的类别明确保留缺口，不自行补造节点和边。

## 开发运行与日常切换

启动器是开发入口，不演变为后台业务服务。它负责启动本机 Codex 模型端点、官方服务及桌面进程，记录本次拥有的进程、报告启动错误和明确停止。

关闭桌面窗口后服务继续运行。开发启动器保持运行；关闭启动器或发出停止操作后收尾其拥有的进程。电脑重启后手动启动。首版不承诺无人值守、开机自启或中断任务自动续做。

原 helper 在本阶段退出日常运行职责，不继续进行同身份更新或恢复实验。新运行方式是否可用与旧 helper 是否修复分开记录。实际切换必须避免两个服务同时写同一官方库，但不要求先修好旧 helper。

只保留一份活动日常官方数据。切换时停止旧写者，在新写入之前保留一份官方数据和必要配置的一致快照；这份快照不挂载为第二个日常环境，也不包含已决定删除的旧 Memlane 内容。

## 旧链清理

### 删除范围

- 旧 Memlane 保存的知识正文、原始记录副本、全文历史版本及其专属缓存。
- 自建内容索引、搜索、重建任务、双库同步和旧内容 outbox。
- 依赖旧内容链的手动编辑、版本恢复、审核建议、复杂整理、使用统计和相关生产入口。
- 自有内容保存与召回协议、并行采集和二次注入链路。
- 项目和 Agent 读写权限产品及其专用数据、接口和页面。

不迁移正文，不转换历史，不新建归档数据集，不以旧内容备份或逐条迁移验收作为清理前置。此前已留存的缺陷证据和 Git 历史不作为活动产品内容继续挂载。

### 保留范围

- Cognee 已有知识、材料、图、向量和官方运行数据。
- Agent 自身会话、账号登录状态、第三方配置。
- 仍需使用的组件、向量模型、凭据和必要本机配置。
- 未完成任务的明确收尾信息，以及已有失败证据。

删除旧内容不等于递归删除整个工作目录或所有数据库。若同一文件同时含旧内容和需保留配置，只提取最少必要配置，再退出旧文件；这不是内容迁移。

## 实施顺序

生产代码清理前先执行 G0：保存当前源码快照并打注释 tag，包含相关未提交文件；tag 与快照清单记录到本次交接。源码 tag 与运行数据快照是两件事，旧内容仍按决定直接删除，不迁移。具体步骤见技术方案。

| 工作包 | 直接实施的结果 | 不附加的工作 |
| --- | --- | --- |
| W1 运行基线 | 固定官方版本与数据位置，准备开发入口；模型端点就绪后接管日常服务，退出旧 helper 托管 | 完整运行包、正式签名、第二套日常环境 |
| W2 官方记忆与 Codex 适配 | 官方模型调用进入 Codex，插件采集与召回使用同一服务 | 新提炼算法、代理任务平台、模型横评 |
| W3 桌面内容 | 独立美观窗口直接呈现官方知识、原文、来源和搜索 | 独立内容库、旧功能兼容、重新发明图谱 |
| W4 旧链退出 | tag 后随模块替换清除昨天的问题代码；停止旧写者后删除旧正文、版本、索引、搜索和权限业务 | 旧数据迁移、历史归档与兼容模式 |
| W5 图谱与共享扩展 | 官方图谱进入桌面；再按实际需要接第二个官方 Agent | 自绘图、全 Agent 矩阵、性能专项 |

W1 先准备运行配置，与 W2、W3 按接口并行；W1 与 W2 就绪后再由一个执行者接管日常运行，不先停旧服务再开发必需的模型端点。W4 在旧运行依赖已经退出后完成，不等于要等图谱或所有界面细节做完。不得把“清理完所有历史代码”设置为开始 W2、W3 的条件。

## 完成条件

以下是交付时必须成立的结果，不是新增一轮可行性验证计划。不重跑已完成且条件未变化的路线，不建设新的验收框架。

| 编号 | 完成条件 | 交付时保留的信息 |
| --- | --- | --- |
| D01 | 日常只有一个活动官方服务；关窗不断服务；明确停止和再启动有效 | 实际入口、数据位置、所属进程与停止结果 |
| D02 | 正常 Codex 工作的材料进入官方存储 | 对应会话与官方材料身份，不人工补写 |
| D03 | Cognee 实际通过 Codex 完成模型请求，结果由官方保存 | 模型执行结果与官方处理结果的关联 |
| D04 | 新会话实际获得并使用相关知识 | 官方召回输入及后续任务中实际采用的内容 |
| D05 | 桌面知识、原文、搜索和出处一致，阅读过程稳定 | 实际桌面操作与必要截图 |
| D06 | 旧内容和旧链已退出，新链不依赖旧全文库 | 明确删除清单、保留清单与生产入口检查 |
| D07 | 所有有效已连接 Agent 的项目访问没有自有权限门槛 | 当前连接与项目分组行为 |
| D08 | 代码图谱按项目开关运行，展示官方真实结构与来源 | 官方索引结果及桌面实际操作 |
| D09 | 代码清理前已有可恢复的源码 tag；昨天的问题实现及相关旧调用路径已退出 | tag 名称与 commit、纳入快照的源码清单、逐项代码清理结果 |

实施中只做与修改直接相关的检查和正常使用观察；遇到错误定位并修复，不先增加一套试验。已有具体问题的失败次数与停止规则仍保留，不因改方案、换路径或换 Agent 清零。

## 通用知识当前边界（2026-11-13 用户确认）

当前固定官方接口缺少个人偏好／通用经验独立内容阅读能力，保留入口并明确显示“官方暂不支持”，不拿项目摘要顶替。用户确认后续可专门建立通用知识dataset，供所有已连接Agent读取；本轮不创建该dataset、不新增权限管理。真实通用知识阅读因此移入后续，当前验收核对入口与缺口表达。

## 后续范围

手动新增、编辑、删除优先直接接官方接口。跨 Agent 共享继续扩展到真实使用且官方覆盖完整的客户端。正式安装、helper、开机自启、自动更新、签名、公证及包体积进入 release 阶段。

没有真实使用问题支撑，不提前增加全文版本系统、审批平台、复杂计划、多模型调度、跨平台、远程管理或引擎抽象。
