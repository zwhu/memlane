## 已实现

1. 详情按“定期整理／标题／当前状态→项目／执行者／频率与时区／下次执行／材料与补跑窗口→最近执行”组织。扩展恢复规则折叠展示；服务主动停止及真实运行状态保持。
2. 列表展示项目、频率、时区、启用状态和真实下次执行；读取中／读取失败不冒充空计划。新增“查看整理记录”衔接。
3. 详情和表单共用固定底栏。正文独立滚动，编辑、长规则和窄窗口不把保存／确认操作推到正文末尾。
4. 启用、停用先进入同栏范围与费用确认；只有“明确启用计划／确认停用”提交原Schedule IPC。确认冻结计划ID、generation与Spec；后台刷新计划变化后阻止继续用旧确认。取消不改变启用状态。
5. 表单补可见字段标签，普通窗口时间／时区、材料上限／补跑窗口成对排列，窄窗纵排。新计划仍不默认频率、时间、材料上限或补跑窗口。
6. 计划草稿按新计划／已保存计划隔离，返回和切换计划后可继续填写；失败重试原请求身份随草稿保留。已有计划版本变化时保留原草稿与版本基线，仅用户明确舍弃后才读取新版本重新编辑。
7. 计划处理配置冻结授权、processing_changed原因及原后端规则保留。新计划保存仍停用；启停和保存依旧为不同操作；编辑已启用计划遵循原保留启用语义。
8. 计划时区不可用与异常weekday使用只读提示，避免页面渲染崩溃。

共享App已由主Agent接入计划详情／新建／编辑／启用／停用标题和右上操作，以及普通316px／窄216px列表宽度。

## 差异与验证边界

原型有独立“名称”和执行者下拉。当前持久ScheduleSpec没有名称字段，执行者已按认可处理配置冻结；本批使用“项目 · 日常整理”派生标题并显示真实已绑定配置，不新增本机伪持久名称或模拟执行者选项。该差异保留，未改后台schema或既有计划语义。

定向测试`internal/desktop/schedule_presentation_test.go`覆盖启用须单独确认且打开确认不提交、generation变化不偷换确认范围、新计划没有默认授权参数、保留草稿重入、普通1280／窄800固定操作可见和正文滚动、时区异常只读降级。首批TestSchedule会话26237通过exit0，6张headless图位于`build/schedule-presentation-20261111/headless/`；实际打开普通详情、窄详情和窄表单，发现字段标签只作辅助文本和列表过宽后继续修正，未将首批图当最终还原完成。

最终图和定向重跑结果另补。所有headless图均为合成状态，仅证明布局与部分交互；真实后台计划执行／历史回执、Native普通窄窗、键盘与滚动整体验收仍待集中包，不据此关闭M全部场景或125场景Goal。
