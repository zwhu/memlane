# J/K 材料整理草稿与原回执恢复

本批沿用户授权的123场景推进 J07、K07/K09 与 O11。固定原型仍为 `d2e3923de31ecd4bf7288c2527a9b98578a1ef17`；对应最终普通／窄窗口、J/K/L/M交接与N/O恢复规则已复查。候选设计、SQLite／IPC检查、Native帧与真实完整包证据分别记录，整体设计尚未全部完成。

## 正式实现

- Schema23新增多材料预览、库身份／CAS代次和启动intent三表。预览只存页面与用户草稿；不改知识、版本、任务或当前处理配置。Schema22迁移先保留原始备份，已有L04独立账本与出处不变。
- 启动、继续应用、确认、拒绝、取消先通过Native持久写入barrier，再发送业务操作。保存失败保留当前内容且不发送操作；未知写入先重放同一operation，再继续后续写入。自动写只合并同一预览的相邻快照，不吞掉另一任务的草稿或请求barrier。
- 同任务重开读取原operation与任务，恢复冻结输入、原决定／拒绝理由、通用候选编辑、焦点及逐项／列表滚动。切换任务先保存当前草稿，再读取该任务独立预览；不启动或恢复模型。历史任务依据原Snapshot，不采用设置页当前执行者。
- 未知启动固定材料与执行配置，提供「核对原请求回执」「重试原整理请求」「放弃原请求，保留材料」。核对只读；明确放弃与Start在daemon的同一生命周期锁下串行，原任务已存在时拒绝放弃，没有任务时退休原intent并拒绝迟到Start。放弃回执未知时继续冻结，查询或重放取得原结果后才解除。
- 退出先等待L04与材料预览写入；失败恢复编辑，不退出。初始化真实检测完成后才读预览；晚回执不覆盖新导航或新库。整库恢复／更换库取消两组writer并退休全部旧草稿、请求及UI epoch。
