## 正式记录与页面

- 独立 OrganizationListQuery 承载来源和起始时间筛选，复用既有项目、活动状态、知识关联、稳定游标及数量边界。原 Merge 查询契约保持独立。筛选、总数与页结果在同一读事务取得，来源／项目／时间改变后不能沿用另一筛选的游标。
- 来源取自正式 organization_plan_runs 与任务的关联；停用计划和配置变化不会将历史计划任务改称手动。每行处理方式从任务最新冻结 Snapshot 读取，不用当前设置替代历史执行者。无 Processing 的旧任务仍按历史 traex 执行契约显示。
- Native 中栏增加匹配数量、来源／项目／时间筛选、清空条件和加载更多。读取失败、无匹配、无历史分开显示。筛选改变仅退休旧页数据，保留所选任务和当前审核；旧库晚回执继续被 Epoch 拒绝。
- 可选拒绝理由归于候选稳定 ID，与其他候选的理由和滚动分开。拒绝操作冻结原理由与 receipt_id；未知回执只重试原决定，拒绝与确认不能相互覆盖。理由上限为 1024 字节，确认请求不能带拒绝理由。
- 拒绝回执保存在既有决定账本 JSON，并随该候选状态读取。原候选、来源、有效知识、版本和索引不因拒绝而改变。旧 null 拒绝回执仍可读取；此批不增加 Schema 或改变既有业务内容类型。
- 下一项只切到同任务的审核候选；只有一项审核时不显示无效下一项。返回和同项重入保留个别理由、滚动和任务身份。已提交拒绝在 App 重开后可从原任务读取；未提交草稿与未知启动的完整持久恢复仍单列验收。
