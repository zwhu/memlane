## 后台与版本边界

- schema20只增加 `project_index_recoveries`，将正式索引重建操作关联到原C任务与尝试；不迁移或补造旧模型执行回执。schema19升级前保留原SQLite备份，既有知识、来源、任务和模型回执保持。
- 复用正式 `rebuild_index` 和Rust索引所有者。恢复输入固定原任务／尝试，范围从不可变保存回执推导，不接受调用者提供任意知识列表、较新版本或另一个项目。
- 恢复包含该任务实际保存的知识与仓库原文ID／版本。已成功且绑定有效的索引直接保留；失败项重新排队，待处理／运行项继续原工作；编辑、删除或失效派生版本标记过期，不替换为当前版本。
- 新索引意图和条目排队在同一事务提交，SQL失败或索引任务缺失不会留下半个恢复操作。相同操作ID只重放同任务／尝试；与全范围重建、其他任务或尝试混用时拒绝。
- 原C任务、模型execution、已保存正文和版本不被重写；`ProjectTask.index_recovery` 独立报告恢复状态。恢复不需要原Agent继续连接，不重新解析模型、不运行模型、不读取仓库或历史，也不对历史PID发送信号。
- 已保存C版本索引失败后不在后台每500ms重跑。该规则也覆盖原任务的保存／索引阶段，避免反复重试使失败始终被另一个运行项遮住；未完成的正常索引工作继续运行。用户明确恢复会将失败版本重新排队。
- 整库恢复退休C恢复关联，并将旧恢复条目标记 `expired/backup_restored`。旧恢复操作不能在恢复后的库重放；知识的当前版本由整库恢复既有索引规则处理。

## Native承载与恢复

失败右栏保留知识列表、固定项目／Agent／模型、实际保存和索引计数。底部提供「恢复索引」，并说明恢复不调用模型、不消耗整理Token。顶部「查看知识」离开面板继续阅读已保存正文；项目菜单「查看整理进度」恢复同一失败任务或活动索引恢复，不创建新的整理任务。

恢复运行中只显示本次已保存内容的索引状态，不显示Agent停止操作。关闭、切页和App重开不重发恢复；未知响应要求重新读取后复用相同恢复操作ID，真实恢复失败后的明确重试才生成新索引意图。库重配与任务／尝试不匹配时，旧异步结果不填充新面板。

舞台复用原Native索引卡片阶段，任务、尝试和恢复操作ID组成稳定身份；真实失败停循环，完成采用已保存内容的实际索引回执。时间只插值，不推进恢复。完成顶部重复的「查看知识」入口收起，底部保留「查看项目知识」。模型已完成且保存回执存在时，失败态阶段标记保留已完成的启动／整理，不冒称索引成功。普通／980×620窗口已完成本次恢复状态对照；完整C动效矩阵没有因本次复用而通过。
