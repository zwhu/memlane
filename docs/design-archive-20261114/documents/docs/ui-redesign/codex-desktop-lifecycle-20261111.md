# Codex 电脑级连接的桌面状态与授权衔接

2026-11-11，004 之后的集中源码批次。依据电脑级连接契约和 `codex-computer-connection-20261111.md`，不代表本批 Native 或新包验收通过。

## 已修正

旧 `agentStatus` 对空项目 Codex 直接返回“已连接 · 待首次任务”，且 `protocolOnlyConnection` 仅识别 pi，绕过了实际电脑级协议证明。现在空授权 Codex 必须具备真实电脑级 Installation、当前安装路径和准确受支持版本、当前 generation 的 ProtocolVerifiedAt，失败/停服/断开/代次变化不能沿用成功。旧项目 adapter 不作为电脑级证明。

电脑级详情删除旧项目范围、任务目录及首任务表单，保留独立连接说明、重载验证和断开。授权仍在各项目设置；电脑级详情只让用户明确选择已授权项目作协议验证，不隐式选择其他项目或扩大范围。仅通用范围时不要求项目。项目设置“重载与验证”直接携带用户所点击项目的真实 ID/path 到指定连接；授权外目标拒绝。该动作不自动验证、不启动模型。

授权变更继续调用原明确授权 IPC 并重装已有安装位置，使旧协议证明清除；配置失败显示未全部完成，不假称当前配置生效。连接验证对 ComputerLevel 统一走无模型 `VerifyProtocolConnection`，工作目录同步冻结。协议证明与历史读写/处理模型证明分开。

项目授权读取、保存和连接刷新同步捕获旧 client/lifetime/dispatcher/epoch，旧库迟到回执不能更新新库的连接、授权编辑或状态。

## 验证与边界

`86192` 定向状态/授权测试 Go 输出通过（0.906s）；`94208` 相关状态、授权、旧安装回归与 800×600 电脑级详情组件测试 `-race` Go 输出通过（2.092s）。组件检查确认电脑级说明与验证动作可达，无“项目与检索范围”或“开始首次任务”，渲染不默认选择项目。

`codex_connection_lifecycle_test.go` 覆盖受支持两个准确版本，空授权历史读写证明不算协议成功、当前协议成功、授权后旧 generation 拒绝、断开、旧项目 adapter 拒绝、显式项目验证上下文及跨库 Unix IPC 迟到回执。首轮测试暴露已授权 Codex 仍进入“待首次任务”分支，已修后重跑通过。

已接后台 `CodexProjectVerification`：项目 ID、当前 generation、scope digest 与真实目录 canonical path/inode 的证明须匹配。A 的证明不标记 B 项目成功，目录改变即失效；整体电脑级连接不借历史读写字段取得成功。`35954` 对接后的专项 race exit 0（2.870s）；最后 UI 重开/证明时间回归 `48440` race exit 0（2.415s），`51528` 旧回执/组件回归 race exit 0（2.087s）。断开后重开仍走电脑级批量选择，不退回旧项目安装入口。本页仅源码和隔离 IPC/组件证据，未操作 Native、真实模型或用户配置，未全量构建。
