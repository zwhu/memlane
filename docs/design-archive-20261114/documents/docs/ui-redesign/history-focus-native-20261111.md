设计依据：已认可的C①阅读与历史弹框，固定原型16bc644c799b0ec5ad8845654c2196a7ecf585aa；已实际打开docs/images/ui-redesign/c-project-reading/history.png与history-narrow.png。测试复用实际015包与c23948d5-acb7-5bff-a9d4-651d2a6fdb6c@1合成知识，不调用模型、不保存或恢复版本。

## 实际Native结果

- 普通1200×820与窄800×620均显示独立历史弹框、真实v1、当前版本、正文、时间和来源。鼠标关闭后返回同知识v1。
- Escape可关闭，但没有返回“历史”入口焦点；后续Return不能重新打开。因此键盘焦点项未通过，不能据布局截图判整个历史场景通过。
- 本轮还发现实际弹框带“预览恢复此版本”，已认可阅读交接中的历史弹框没有该按钮；它与独立恢复流程的承接仍需在集中UI对照中登记，不在本轮触发恢复或删除已有恢复能力。
- 保护五表逐行摘要与015替换前完全一致，无新版本。

## 复现、修复与边界

当时目标是验证Escape关闭并回到历史入口。已有headless用例主要通过鼠标点击取得入口焦点，隐含依赖框架恢复此前焦点，没有覆盖辅助功能调用或程序入口未先聚焦的情况；原Escape用例也只断言关闭，未断言焦点。

最小回归通过实际App View、openKnowledgeHistory、DialogBase与Escape调用链，未先点击入口，并等待下一帧，准确复现失败：56880/red.log、83933/red-settled.log。无异步数据的同样失败排除了必须依赖后台刷新的解释。

源码补明确的焦点返回请求：Escape/遮罩及按钮关闭均记录；仅原知识、范围和库代次仍匹配时聚焦原入口，请求在下一帧消费一次，跳转后不延迟抢焦点。源码回归38760通过；9135最终定向检查包含既有历史、未聚焦入口Escape→Return、选择变化和库代次变化不抢焦点，以及服务离线草稿；19976 desktop vet通过。日志在build/goal-history-focus-20261111。

这是源码和组件测试通过，尚未进入新包Native复验；015窗口仍是修复前代码。没有为此单独完整打包，也没有重试已停止的helper更新或图谱问题。

本焦点问题目前记录1轮Native验收未通过；定向红绿是同轮定位，不冒充多轮实机验收。后续实际复验累计仍按用户第4次停止规则执行。基础链路保持6/10，125整行不提升。
