# L04 提炼预览恢复与故障验收

本批承接 [真实 pi 提炼记录](experience-distill-fidelity-20261110.md)，按固定原型 `d2e3923de31ecd4bf7288c2527a9b98578a1ef17` 的 L04 与 N/O 窗口、草稿和恢复边界实施。123 场景整体目标继续，不把本批恢复路径当成所有记忆处理后端或最终分发已完成。

## 所有权与恢复规则

- schema22 在 daemon 所有的 SQLite 中增加提炼预览账本。草稿、原候选摘要、确认／拒绝请求、当前候选、返回项目／记忆、滚动位置和焦点 Key 属于预览；不会写入有效知识、索引队列或使用活动。
- 预览按自己的稳定 ID 保存，服务保存当前指针，并签发数据库身份和全局 generation。单一客户端写队列串行提交，相邻自动保存合并，明确生成、确认及退出保留精确的持久化门禁。
- 生成／确认先保存原请求，再发送正式操作。读取恢复状态只查询已有任务或原启动 operation 的回执；不调用 Start、Resume，不重新选择执行者，不自动重跑模型。
- 已知任务的来源取自后台冻结 Snapshot。没有任务回执时读取输入引用指定的不可变版本，不将当前 v2 正文标成原 v1。
- 写入回执丢失时重放原写入 operation 与 generation，不能换成新的正文。明确校验拒绝不会阻挡用户修正字段；失败保留本地编辑并显示「尚未保存草稿」。
- 普通退出先等待最后预览保存，再按原设置保留或停止服务。保存失败保留窗口；等待期间禁止新的页面编辑。停止服务失败后重新开放编辑，下一次退出再次保存。
- 整库恢复在同一事务中清空旧预览并旋转身份；旧窗口、旧 generation 与其他库的写入被拒绝。schema21 升级保留升级前副本和全部旧业务行。
- 首屏检测完成后才加载业务预览。启动后的数据刷新不当成用户导航；用户已切换页面时仅保留恢复草稿，不覆盖新页面。输入框真实取得焦点后才结束恢复，并滚入可见范围。
