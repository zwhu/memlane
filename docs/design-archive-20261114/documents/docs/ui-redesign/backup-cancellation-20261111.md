# 备份真实取消 · 2026-11-11

对应N07/N备份进行场景，保留当前维护页设计与人工发起原则。本批补后台显式取消，未新增磁盘防护等产品能力。

`BackupClient.Create(ctx,id)`仍返回完整备份回执；daemon为该ID登记独立60秒所有者、取消函数和终态通知。`Cancel(ctx,id)`发出明确取消并等待真实清理，返回`BackupOperation`，状态为creating/completed/cancelled/failed；`Status`用于读取状态，daemon重启后通过校验已发布备份恢复成功回执。未知ID不取消其他备份；成功操作重放原回执，失败／取消可用同ID明确重试。取消返回绑定请求实际观察的尝试，不能串入随后重试的状态。

SQLite分步快照和文件发布前沿用context检查；未发布的暂存目录由原有身份校验清理。文件重命名发布是提交边界，提交后若收到取消，继续校验已发布备份并返回实际回执，不能假报“已取消、未保存”。目录持久化或校验失败仍报告失败，不把取消请求本身当作成功。

证据分层：定向测试包含实际SQLite备份、精确ID取消、错误ID隔离、取消后无发布／无暂存、成功后取消真实回执、daemon新所有者发现回执、失败同ID显式重试，以及真实私有IPC确认门禁与回执。取消等待使用合成阻塞快照源；发布后取消以目录同步钩子确定边界。Native取消按钮、普通／窄窗与整体维护链路交由集中完整包验收，不以测试替代。若取消请求先于创建在daemon登记，返回未知ID失败，不声称已取消。
