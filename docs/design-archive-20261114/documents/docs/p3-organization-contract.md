# 完整整理动作契约与实施顺序

本方案收口已有产品规则的工程含义，不将未实现能力描述为通过。C1/C2 仍保留同项目两条合并链路；后续整理复用隔离 runner、私有 IPC、数据库拥有者和原文索引服务，逐切片验证。

## 来源与输出

用户明确选择登记项目与材料版本；服务冻结 ID、revision、正文、类型、实际出处、捕获时间和来源依赖。每次输出绑定 task/attempt/input_digest，item_id 由宿主允许的稳定标识规则校验；仅 JSON 结构化结果，没有批准字段、生产工具或数据库句柄。未选项目材料不进入 prompt。首批每任务最多 16 条、单条 16 KiB、整份输入 128 KiB、至多 32 项结果；沿用两分钟模型/进程时限及有界事件流。依据是先实现可重复的小批次验收，避免把完整知识库送入模型或长事务；计划批次另行记录授权上限。

每项必须至少引用一条选定来源的具体版本与非空精确 quote，声明动作及正文/标签/目标。来源不足可以返回无建议和解释，不以编造知识补数量。服务验证语法与范围，不将模型置信度视为事实证明；质量基线单独检查正文是否由出处支持。

派生摘要和同源转述保存直接来源与可追溯原始依据，不能增加独立证据。整理合并已有 C1 merge_sources 亦是派生关联，不能凭新 memory_id 把同一来源算作新的证明。依赖链有循环/缺失/范围不匹配时拒绝派生应用。项目知识与 raw 材料分别保留；不偷偷读取聊天。

## 每项决定与原子性

| 动作 | 生效权限 | 版本与来源 | 原子结果 / 恢复 / 索引 |
| --- | --- | --- | --- |
| 新增摘要 | 用户已选任务项目与材料，服务可自动应用 | 所有来源当前版本/状态仍有效；固定来源及派生标识 | 新知识/历史/依赖/回执/索引任务一次事务；原知识保留。改写已有摘要须确认 |
| 添加标签 | 服务可自动应用新增标签 | 固定目标与来源 revision，不移除既有标签 | 标签事件/合并后集合/回执一次事务；不改正文或伪造原创建时间；删除替换标签需用户明确操作或审核 |
| 重复/冲突识别 | 只登记建议 | 具体材料、冲突双方版本与引用 | 无知识副作用；不能把冲突直接标为一方真或自动删除 |
| 合并 | 用户确认 | 全部目标/来源版本和项目均匹配 | 新知识、来源归档历史、具体来源、回执、索引一次事务；单条恢复追加版本，不整次撤回 |
| 覆盖 | 用户确认 | 目标当前 revision 与全部依据匹配 | 新正文 revision/出处事件/回执/索引一次事务；旧版本保留，恢复追加新版本 |
| 删除 | 用户确认 | 目标 revision 及相关依据匹配 | 逻辑删除 revision/原因/回执一次事务，旧索引立即排除；恢复追加新版本 |
| 跨项目移动 | 用户明确授权来源与目标范围后确认 | 来源 revision、目标登记身份与授权仍匹配 | 新范围 revision/历史/回执/索引一次事务，旧范围立即排除；无隐式其他项目检索或复制 |
| AI 全局提炼 | 预览适用条件，用户确认 | 项目源具体版本与全局 experience 范围 | 新全局知识、条件/出处/回执/索引一次事务，项目源保留 |
| 原文复制全局 | 用户明确选择复制行为 | 项目源具体版本与全局 experience 范围 | 固定复制回执，新全局知识与出处一次事务，项目源保留；不调用模型 |

任务执行完成与 item 审核/应用分开。结构化输出整体校验通过后才登记；每项以独立事务提交其全部写入，避免一个无效/过期项覆盖另一个已提交结果。任务可 partial_failed，逐项准确记录自动应用、待确认、拒绝、过期、失败、取消和索引状态。取消阻止尚未提交项，已提交项保留，不能将“部分成功”表现为全回滚。

每项 operation/decision/receipt 绑定动作、输入与结果摘要；同标识异内容冲突，重放返回首次事实，不能重复知识、版本、活动或标签事件。确认前再次验证全部版本与范围；任一过期则整项无知识变更。SQL 任意中途失败该项完整回滚；索引失败保留正文与回执、用既有队列重建。

## 依赖变化

冻结出处永久保留。未应用建议来源变化立即失效；再次生成是新 task/attempt，旧结果不能通过。已应用摘要的来源变化后标记 stale，检索不将其作为当前有效知识返回，App 显示冻结依据和当前变化，重新生成或修改已有有效摘要仍走确认。标签添加记录保留来源变化标识，不自动删除用户标签。合并/覆盖的已确认知识保留确认事实与历史；来源后续变化只提示依赖变化，不静默覆盖或删除已确认正文。

服务默认列表、Resolve、索引提交/重建及应用事务检查派生有效性；日常 Agent memory_get 对 stale 返回 source_stale，memory_status 和受信 App Current 仍返回显式状态供核对历史，不能把状态查询当有效知识读取。新增必要表随实际摘要/标签功能迁移，引擎数据仍可重建。每次迁移由唯一拥有者先 VACUUM INTO 一致性备份，临时旧库逐表验证并恢复，失败关闭；旧版回退必须使用相应备份及兼容二进制。

## 切片与验证

C3 先实现来源/派生、摘要、添加标签、逐项回执和依赖失效，使用真实 App/traex/Rust 验证自动应用范围。C4 再实现其余修改建议与审核，保持 C1 已通过行为。全局经验、计划/attempt 与使用事件各按交付矩阵继续，不在 C3 预建完整平台。

质量基线固定少量合成中文、代码约定、重复同源、相反冲突、恶意嵌入指令及缺少来源样本。保存来源支持与动作正确性人工核对、实际模型版本/成功/失败和可重复输入 ID；不把 schema 合法或摘要数量当作质量提高。模型正常返回与取消必须真实，协议/故障夹具独立标记。具体证据随切片加入验证记录。


## C3 持久化切片的工程取舍

C3 已实现 schema v4、服务与 App 摘要/标签链路；真实证据和后续边界见 [C3 验证](../../../p3-c3-validation.md)。其余修改动作仍由 C4 实现。

- 增量迁移 v3→v4；v2/v3 均先由唯一拥有者 VACUUM INTO 一致性备份，失败关闭。实验入口保持 v2。新表只为实际任务/attempt/结果/逐项回执、摘要来源与标签事件引入，不预建计划、排名或代码图谱平台。
- 整体 JSON 合法后先持久保存结果，再逐项短事务应用；网络/模型全在事务外。item 稳定 ID 由 task+index 生成，应用 digest 绑定 item 内容及其冻结依据，不以 attempt 生成重复知识。后续重启恢复优先继续已有持久结果，避免再跑模型重写已应用项；lease/多 attempt 在 D2 收口。
- 新摘要通过已有 applyTx 创建 knowledge v1，另存派生标识、冻结直接来源和去重的证据根。新增标签只追加标签事件与集合，不改正文、revision、活动创建时间或原始出处；目标版本栅栏仍检查。重复标签不重复事实，失败/取消逐项保留实际已提交项。
- 未审核建议与自动摘要直接来源变更后失效；当前版本检索在 Store/Resolve 门禁排除 stale 自动摘要，并使旧索引任务失效，不能只靠 UI 标签。C1 已确认合并保持其确认事实，不因叶子来源归档就自动撤销；从该合并生成的摘要依赖合并的具体当前版本。
- 用户明确编辑或恢复摘要产生新版本，视为用户确认正文；保留派生来源和来源变化提示，不把确认修订变成独立证据。旧自动摘要历史仍保留，不自动覆盖。此规则依据用户输入即确认知识、恢复追加版本，与自动产出有效性分开。
- 冻结出处包含捕获时范围。C3 只用同项目来源；后续跨项目移动/全局经验必须在 Agent 出口按批准范围处理来源正文，不能借全局条目的历史关联泄漏未授权项目材料。可信 App 可查看本机保存的历史出处。
- 当前 DTO 只接受 summary/add_tags，其他动作拒绝；C4 定义并验证新动作后才扩展 schema。模型只回结构化数据，不注册日常写工具、数据库或批准入口。

- 无执行者的 queued/running/applying 任务由服务在列表/详情/开始/恢复读取前核对，持久化仍失败则返回错误，解除后转 interrupted 并递增 attempt。终态写入失败后全部已提交项仍可通过新 apply attempt 收尾，不重跑模型或重复事实。旧 attempt 清理仅删除匹配自身的内存拥有权；取消持久化与拥有者取消共用锁，终态取消不会取消新恢复。
- C1 开始、结果登记、详情、列表过期推导及确认同时核对 stale 自动摘要。已确认应用事实重放优先保留；不得将未确认建议的来源失效穿透成自动批准。
