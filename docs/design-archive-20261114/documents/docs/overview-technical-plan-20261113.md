## 首日存储与完成事件

在开发运行根 `.local/daily/` 下采用独立 `client-state.json`，不放在每次覆盖的 owner 文件、缓存或官方库内，不进入 Git。当前方案仅保存：

```json
{
  "schema_version": 1,
  "initialization_completed_at": "2026-11-13T03:00:00Z",
  "first_used_date": "2026-11-13",
  "first_used_timezone": "Asia/Shanghai"
}
```

以上为格式示例，不是本机已记录日期。将状态路径作为明确配置传给 Native；路径与进程运行目录解耦，清理一次运行不删除首日。

初始化完成判据为配置有效、带认证的官方只读请求成功、Codex 端点健康。复用现有启动检查，补足认证检查；不调用模型试算，不自动提炼或索引。唯一启动器持有现有运行所有权后，在进入可用总览前执行 `completeInitialization(now)`：

1. 读取并校验持久状态；已存在合法首日直接返回。
2. 无记录时，用同一个时刻生成 UTC 时间、本地日期和时区。
3. 在受保护的提交段中以同目录临时文件、同步和原子替换保存，再宣布完成；重复调用不覆盖。桌面只读此状态，不另设写者。
4. 状态格式损坏或写入失败时不覆盖旧文件、不用当前时间假装修好，保留诊断与重试入口。

既有安装无字段走相同提交，补记本次完成日期，不查最早活动、不新增迁移向导。`--no-ui` 满足相同完成判据也算初始化完成。后续关闭窗口、进程退出、升级、配置切换都不得删除或重写此文件。

日期算法使用本地年月日构造日历序数相减，禁止 `duration / 24h`；跨夏令时仍按日期计数。首日固定为保存的日期，今天取当前系统本地日期，最小结果为 1。Native 在跨日及重新激活窗口时更新天数，不需请求 Cognee。

## 只读数据聚合

所有内容请求沿现有 `Client` 的官方地址、凭据和认证方式发送，不给 WebView 凭据、不直接打开运行数据库，不改官方包。复用现有连接，不启动第二个服务。

| 内容 | 官方来源 | 处理 |
| --- | --- | --- |
| 知识及创建日期 | `/api/v1/datasets/{dataset_id}/data` 的全部分页 | 复用 `Document.knowledge()`，以官方对象身份去重，使用 `createdAt` 按本地日期分桶 |
| 原始文档 | 同一 data 列表中非知识对象 | 排除代码／派生材料；以官方来源关联与会话归并，独立文档保留官方身份 |
| 会话 | `/api/v1/sessions?range=all` 的全部分页 | 复用当前身份和可见范围，按关联 dataset 过滤；使用官方 session 身份归并材料 |
| 近期动态 | `/api/v1/activity/pipeline-runs`，支持 limit／offset | 按运行身份归并多状态，读取足够原始行凑齐 20 个事件，继续加载保留去重集合 |

范围来自项目与通用知识的配置并集，同一服务数据空间／dataset 只扫描一次，代码专用 dataset 不加入。服务地址只是连接位置，不能单凭端口变化重置内容身份或首日。全局读取完成后再发布准确总数；部分分页成功不能显示为全量。

知识分类已在当前客户端实现，并已核对当前纳入组的实际分类和 UTC 创建时间；不能把接口 data 总数直接当知识总数。当前有效知识集合同时供总数、热力图和日期结果使用，保证同口径。总数包含缺少时间的知识，日期桶不强行补齐这部分。

固定版本已核对 `user_sessions_from_cache` 为会话落盘派生材料、`agent_trace_feedbacks` 为工具反馈派生材料；总览排除这两类，不与官方会话重复相加。独立文档仍按官方 ID 计数，泛用 `session_id` 不足以把附件当作会话副本。该版本未提供两类派生材料的统一 source session 字段，不解析正文、标题或日期猜测关联。日后出现新的派生类型须按官方契约补识别，不扩建来源库。

热力图为滚动 365 天，不将活动接口的成功记录换算为知识。官方覆盖、重建和删除后仅呈现当前保留对象的创建分布，无法还原被删除的历史增量；不为此另建历史系统。

## 活动归并与跳转

官方活动表为追加记录，同一 `pipeline_run_id` 可能有开始和终态；事件键优先为官方身份加 `pipeline_run_id`，缺失时用行 ID，不能按相同时间合并独立操作。取最新状态作为显示结果，保留原始操作与流水线区别。

`background=true` 的 `outcome=succeeded` 只表达已启动，必须取得该后台运行的终态才显示完成。父操作与子流水线只有存在可靠 `parent_operation_id` 关联时才折叠为同一事件；不得重复累加 token 或把多个状态计作多次新增。失败如实展示，诊断错误不变造为产品知识。

事件时间优先实际开始／完成时间，缺失时使用行创建时间；时间解析遵守官方时区语义。项目名来自配置关联；无 dataset 的事件可显示为全局事件。只有返回了有效知识／原始记录身份才提供内容跳转；dataset 或运行 ID 本身不等于内容 ID。

## 刷新、缓存与资源

首次进入总览异步读取，每个模块独立状态；返回总览和手动刷新复用同一读取入口，知识刷新完成时同步更新数量与日期桶。沿现有刷新机制合并并发请求，不为此新增永久轮询服务。

缓存只存在本次应用内存，按服务数据空间、官方身份、数据范围和请求代次隔离。内容量较大时后台分批读取和可取消，取消／超时保留上次完整结果，不将中间累加值当总数。刷新期间官方变化导致的不一致须以同一轮复核或可用的官方快照能力解决，不声称跨接口事务快照。页边界去重，未读完不得归零。

不保存正文副本、永久事件、每日计数表或独立索引，不触发模型、索引、数据清理或服务重启。只读统计不改变 Agent 工作；保留当前原始数据和运行依赖。

## 实施与验证顺序

1. 先确认全量分页、有效知识时间和跨类型原始记录关联；形成字段映射与真实只读对照，避免先画准确数字再补统计含义。
2. 实现首日幂等提交与只读聚合，集中做必要定向检查：跨日／夏令时、首日不重写、分页／去重、失败不归零、后台状态。
3. 按旧首页结构开发 Native 模块并实际对照；本轮直接用 Native 呈现三项统计、热力图和左右并列的知识／动态，不改另一工作树的历史原型，不恢复旧审核、计划等删除功能。
4. 按规格连续场景（含用户追加失败诊断）进行统一集成验收，以真实官方数据核对统计和事件，实际打开 Native 1200×820 对照；不打完整包。

关键待证：跨类型来源映射是否完整、知识创建时间语义、全量读取在并发变动下的一致性、首日写入失败后的连续体验。它们不由一次近期活动 HTTP 200 推定通过。沿用错误索引与既有停止规则，不为写方案重跑模型、索引或启停服务。

## 本轮落地补充

已在启动器 start 及 open 路径接入首日，带认证只读检查通过后才提交。旧后台保持原 PID，通过 `open --watch-ui` 附着前台 Native watcher 完成实窗验证；该入口使用独立附着锁，只管理 UI 进程组，不接管官方服务。

统计分层保留结果：会话接口失败只使原始记录统计不可用，知识和热力图仍可更新；文档扫描不一致不发布部分总数。两次完整枚举一致是客户端一致性检查，不宣称官方跨接口事务快照。活动父操作的后台 accepted 状态不会因一页子任务都完成就升级为成功，缺少完整终态时继续显示已启动。

## 失败详情与复制诊断

`overview_diagnostics.go` 负责只读诊断文本，UI提供内联展开及复制。活动聚合保留实际失败子运行的行ID、运行ID、父ID和错误分类，不能只剩归并后的父事件；复制可帮助用户自己的AI定位原始操作。`BrokenPipeError` 显示为“连接管道已断开”，未知类型保留官方分类或明确原因缺失。

诊断文本只包含事件元数据、脱除user info／query的服务origin、固定源码版本，以及按时间／错误类型匹配的日志调用位置。`official_data`仅用于显式本机官方日志目录，最多读最新3文件各尾部512 KiB，最多24条栈帧；不导出自由日志行、异常消息载荷、源码内容、变量、凭据、请求头或会话正文。时间匹配永远标为候选，不冒充任务ID精确关联。日志缺失不阻止复制其他诊断信息。

本轮只读诊断已确认旧官方进程启动图worker前在`multiprocessing.util._flush_std_streams`的`sys.stderr.flush()`报BrokenPipeError；服务与旧launcher继承同一PIPE。用独立关闭管道夹具复现该stdlib失败点，不调用Cognee业务或模型。根因是长期服务依赖已不可写的继承stderr；具体哪个读取者何时退出未取证。建议后续将服务标准流接到生命周期独立的有界日志，并协调所属服务重启；本次未实施该修复、未重启或重试业务。健康接口可读不等于图查询／整理可执行。
