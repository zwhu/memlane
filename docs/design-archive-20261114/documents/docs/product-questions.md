## Q2 已确认的首次任务引导

2026-11-09，用户回答：“是由 App 引导完成第一项任务”。选择 Agent 并完成必要接入与真实可用验证后，由 App 承接第一项真实 Agent 任务的引导。首次使用流程需要继续带用户看到该任务产生的实际记录、知识及出处，形成可理解的完成反馈。

当前确认的顺序为：环境准备完成 → 选择本机 Agent → 电脑级配置与连接验证 → App 引导第一项任务（此时独立处理可选项目、工作目录与本轮范围）→ 查看实际记忆与出处。跳过项目时，连接后首次有效数据到达再自动建立项目，见 Q3。具体接入确认、任务内容与引导呈现仍需细化。此选择没有授权自动启用日常 hook、采集历史聊天或选择默认保存策略。

在既有隔离官方任务、同步与浏览基础上，本轮增加了无项目接入和首任务页，正常任务完成后自动衔接官方结束同步及材料接收，并实机查看记忆与完整出处。新顺序采用本轮独立包和空根验证；具体边界见 [流程](../../../agent-first-task-flow.md) 与 [结果](../../../agent-first-task-validation.md)。

## Q3 已确认的项目选择与自动建立

2026-11-09，用户确认：“提示用户自己选择项目，如果不选的话，就在链接app之后，在有数据产生之后，自动创建”。按本轮后续纠正，先完成电脑级 Agent 配置；在实际使用或首次任务时可提示选择项目，允许跳过。连接本身不要求项目且不创建空项目，连接后首次产生有效记录，再自动创建或登记对应项目并归入该记录。

项目继续承担业务归属与授权范围。自动建立依据受信接入身份及实际工作区／仓库，遵守既有同仓库身份和去重规则，已有同一仓库项目时复用。模型输出不能任意指定项目归属；来源不足以可靠判断时保留待归属状态并提示用户选择，不猜测项目，不自动归入全局。手动选择也需核对实际来源范围，不能静默把另一仓库的数据合入所选项目。

跳过项目选择只改变项目建立时机，不取消采集授权或允许隐式读取其他项目。接入身份、允许采集的范围和材料来源仍需明确；连接成功、缓冲、持久保存、知识提炼和索引可用分别反馈。此次确认没有选择日常自动记忆策略，也没有授权扫描历史对话。

schema16 以独立待接入授权保存尚未建立项目时的接入身份、受信工作目录和 Git common directory。首条有效记录与项目建立、授权提升、binding 和索引任务共用事务，失败整体回滚；已有同仓项目复用，撤权与代次变化拒绝迟到材料。无项目连接与有数据后登记已在本轮 Codex 完整包实测，幂等、失败回滚和工作区权限另有真实 SQLite/Git 测试；见 [契约](../../../agent-first-task-flow.md) 和 [验证](../../../agent-first-task-validation.md)。
