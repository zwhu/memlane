# P3-D 定期整理与执行恢复契约

2026-11-08，基于已通过 C1/C2/C3/C4/E，复用正式任务/结果/决定/回执，不重做模型写入流程。D1 的持久计划、明确启停、真实正常/取消与有限补跑已验收，见 [D1 验证](../../../p3-schedule-validation.md)；D2 租约、自动重试和崩溃恢复继续实现，不由本文契约推定通过。依据为 [产品定义](product.md) 的用户自选频率、手动/定期同规则、显式停服和有限恢复要求。

## 用户授权与计划

用户在 App 选择已登记项目、已验收执行者及频率，再明确启用。初期执行者只有真实已验证的 traex；pi RPC 接入通过独立 R 切片后才能选择。沿用执行者自己的认证，不把凭据交给 Cognee。计划显示使用执行者当前模型可能发生费用，不在首次启动、组件准备或计划草稿保存时自动调用模型。

计划记录稳定 ID、修改 operation ID、generation、项目身份、执行者、模式（摘要/标签，或同时修改建议/全局候选）、用户材料上限、时区、每日/每周时间或小时间隔、运行窗口、启用状态、下一次 UTC 时间。保存和启用是不同动作，草稿默认停用。修改使用 expected generation 与幂等请求；重放返回原事实，变更内容重用同 operation ID 冲突。

每日/每周的本地时间和时区由用户填选，间隔支持 1–720 小时。没有默认每日22:00、30条、5分钟或空闲阈值。材料上限由用户选择1–16，来自正式冻结输入的16条/128KiB上限；窗口由用户明确填写，最短1分钟、最长24小时，影响补跑期限，不代表模型费用预算。显示每次最多一次模型执行和正式输入上限；自动重试需另行明确次数/最大执行时间，其收费影响必须在启用时展示。

首次启用计算严格晚于当前时间的下一次运行，不补造此前执行。每日/每周按本地日历推导并保存实际UTC槽位；夏令时缺失时刻顺延至可达时刻，重复时刻同一本地日期只执行一次。小时间隔以明确的启用锚点计算，时区仅用于显示。时区/频率更改推进generation并重算未来槽位，旧generation不得新建或自动应用结果。

用户授权项目内按当前有效知识/原始材料选择新增或改动材料及相关旧知识，最多用户上限且不超过正式字节限制。每次冻结具体revision/出处/根来源；摘要不能成为独立证据。其他项目不读取，不依据使用频率跨项目提升。移入目的项目和全局候选必须单独明确授权，沿用 C4/E 审核；新摘要/标签按既有规则自动新增，修改已有知识必须用户确认。

## 触发、去重与并发

每次槽位有唯一 plan/generation/due 标识和稳定 operation/task ID。记录产生、跳过和实际执行结果；推进next与创建运行记录/任务应在同一受信事务，不能先模型调用再补去重。数据库网络及模型调用均在事务外。

手动与计划模型执行共用单个本机整理执行槽，涵盖旧合并入口；请求立即返回持久任务ID，等待执行的任务可取消。已执行任务不被新手动请求抢占。计划触发遇到同项目进行中的任务时记录跳过/延后，不能累计多条重复模型任务。计划任务同一输入集合与revision没有变化时记录no_changes，既有审核提案不重复生成。

服务或机器醒来后只处理每个计划最新一次过期槽位，最多补一次；超过用户窗口记录missed_window并推进至未来，不逐个补历史槽位。停用不运行；修改或停用取消尚未执行及正在执行的旧generation工作。已提交知识保留，已完成的待审核建议仍可由用户逐项决定，停用频率不冒充拒绝历史建议。

## 拥有权、重试与停止

D1先交付持久计划与单服务拥有权/执行串行和触发去重；D2交付持久attempt拥有权租约、有限恢复与故障验收，不能以D1内存拥有者宣称租约已完成。租约包含任务、attempt、服务epoch/随机owner和到期时间；续租、接收/自动应用结果同事务检查，旧owner/旧attempt/过期/取消/旧计划generation结果拒绝。租约失败先取消真实进程并等待回收，再允许下一执行者；模型不持有写事务。

区分认证/未支持模型/无授权/无效结果/源过期（不自动模型重试）、网络瞬断/超时（有限退避）、本地存储不可写（暂停持久操作，不把无法记录当成功）和索引失败（正文/回执已提交，索引独立恢复）。正式任务ID不变，重试生成新attempt；纯模型重试仅在没有持久结果时允许，有结果只继续未提交项。已提交结果、项标识、决定和活动幂等，不能因重试重复新增或计数。

主动停止服务写入既有持久stop标记，终止计划循环和全部活动执行，旧attempt失效；App重开/launchd拉起仍不运行，需用户明确启动。正常意外重启只按已启用计划和有限补跑/重试契约恢复，失败连续上限后停循环并提供诊断，不能无限失败重启。

## 迁移与验收

D1的schema v7只添加实际计划/operation/运行记录，保留v6旧表、全局条件、来源和审核决定；D2随后以独立增量迁移引入拥有权/重试记录，不提前创建无用途表。迁移前唯一数据库拥有者一致性备份；临时v6库非空WAL、旧表/决定逐项相同、回执/条件恢复、旧版本拒绝未来schema和独立备份恢复都需证明。

真实App/traex/Rust验证计划保存/明确启用、正常触发、稳定任务、取消和用户审核边界。时间/租约失效、崩溃/重启/迟到、重复触发/部分失败使用明确标记的故障/时钟夹具，不能冒充真实正常模型执行。证据分置 `build/p3-schedules/` 与 `build/p3-recovery/`；各阶段完成后review、适用test/vet/race、完整安装包、实际窗口对照、handoff和提交，再继续总Goal。
