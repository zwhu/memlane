# C2 App 手动整理与栏内审核契约

C1 的正式来源/版本/原子应用/取消规则不变。App 不打开业务库，不将日常连接可用视为后台任务授权；用户在栏内明确选同一已登记项目的两条 active 知识，并点击开始。只发送实际所选 memory/revision，重试开始复用稳定 operation_id，返回持久 task ID 后轮询；离开页面和关闭窗口不取消服务任务。

## 列表与读取

新增私有 `merge_list` / `MergeClient.List`，protocol 仍为 1；复用 schema v3，不新增表或迁移。查询可按 project、memory 关联过滤；memory 关联包含冻结来源或已应用结果，不修改来源。项目过滤必须为已登记 project；单页默认 30、上限 100，用 created_at/id 降序稳定游标，同秒任务不重复跳过。游标必须属于查询项目。列表只带状态/标题/时间，不返回全部正文或授予审核权限。

列表计算 pending 来源已变化时显示 expired，详情调用 C1 Get 持久推进过期；任何应用仍在 C1 事务中重验。任务详情只读当前任务、冻结快照和应用结果当前版本，任务 completed 不等于 applied / indexed。索引失败保留正文、应用回执和审核事实；到合并知识详情使用既有索引重试。

## App 路径

宽幅总览保留热力图，显示最近记录中的待确认建议及全部记录入口。列表/项目点立即整理或整理记录内开始，在右栏选择项目和两条知识；分页知识继续加载，冻结版本由开始事务最终判断。已有项目数据不隐式跨范围选择。

整理记录三栏显示稳定任务 ID、运行/审核状态、执行 attempt、错误、建议正文、每条冻结正文/来源元信息/精确引用/相对此来源的文字改动。审核按钮固定在右栏底部，长正文仍可滚动。确认前显式说明将新建合并并归档来源；确认和拒绝使用独立稳定 receipt_id，响应失败保留 ID 重试。

运行中可取消，取消先由 C1 持久门禁阻止未提交结果，再收口进程。queued/running、failed、interrupted、cancelled、pending、expired、rejected、applied 与独立索引状态分别呈现。失败/中断/过期允许重新选择当前版本，新 operation 重新分析，旧 attempt 不复活。

合并结果和冻结来源均可跳到知识详情/历史；从知识详情按持久关联找到整理记录。归档条目显示归档、不参与检索且编辑禁用；恢复源旧版本沿用单条恢复产生新 revision 的规则，不撤销合并结果。点击查看冻结 vN 历史展示来源历史，其中 vN 标识保留，当前版本另查。

所有 IPC 在绘制外执行，在 window.Update 边界回写；页面/任务选择代次检查阻止迟到响应覆盖新的选择。读失败保留已有内容，显示失败并可重试；不能因读失败清空列表宣称无记录。用户草稿、任务选择与未提交决定只在窗口内存，持久任务/审核由服务拥有。

## 验收

正常返回、拒绝、活动取消使用真实 App + traex，确认后的检索使用真实 Rust worker；系统窗口截图对照两张已选图。过期采用明确的实际服务编辑夹具；中断使用 App 停服重启；索引失败使用明确的引擎不可用故障。源码测试和后台 C1 已通过结果不能代替这些 App 检查。证据见后续 C2 验证记录与 build/p3-c2/。
