# Agent 优先的首次使用流程

2026-11-09 最新初始化边界以 [A 实施交接](ui-redesign/a-setup-handoff.md) 为准：仅「准备环境／连接 Agent／配置记忆处理」三步。本文记录已验证的首任务技术切片，后续在完成配置后的日常操作中承接，不将任务执行与记忆结果加入初始化门禁。

2026-11-09 后续产品纠正：电脑级 Agent 连接不以项目/工作目录/首任务模型为前置条件；项目、工作目录和本轮采集条件在实际任务阶段独立处理，见 [连接规则](ui-redesign/agent-connection-contract.md)。以下表格与验证描述保留为此前完整包的实际实现记录，不作为新电脑级连接已交付的证明。

2026-11-09，按用户最新优先级先走通本机主流程。分发、签名、升级和其他独立验收暂缓；旧失败报告保留，不把这些门槛混入本次流程完成条件。

本轮先以已有真实官方采集基础的 Codex 接入走完整链路。pi、TRAE CLI、TRAE IDE 的发现与既有适配继续保留，不把 Codex 的结果扩大为四种 Agent 官方流程全部通过。

## 用户连续流程

2026-11-09 后续产品调整：官方采集所需的 Cognee 服务、依赖与本地向量模型纳入 Memlane 基础环境初始化，连接 Codex 时复用并检查已有环境。提炼模型通过本地 Agent 桥接，复用 Agent 的登录与模型配置；电脑级连接不要求项目或提炼执行者，在首次任务准备或设置中选择并实际验证提炼 Agent。本轮已调整服务准备逻辑并先实现 pi RPC 模型桥；新包的实际结果与未覆盖项见 [pi 验证](pi-model-bridge-validation.md)。下表和旧验证记录描述此前分段准备版本，继续作为对应版本的历史证据。

| 阶段 | 用户看到与执行的动作 | 成功依据 |
| --- | --- | --- |
| 准备本机环境 | 检查缺失组件，明确确认准备 | 当前 helper、Rust 健康回执；没有预置项目或记忆 |
| 选择 Agent | 就绪主操作为“选择 Agent” | 进入真实发现的 Agent 列表，安装与接入状态分开 |
| 可选项目与连接 | 可以保留“暂不选择项目”后连接 | 仅持久确认接入身份和显式允许范围；连接本身不创建项目 |
| 确认任务工作目录 | 跳过项目后，在首任务页确认实际 Git 仓库或 worktree | 服务核对实际 Git common directory，保存受信范围；仍不登记空项目 |
| 准备官方环境与插件 | 使用独立 Cognee 模型条件，确认本轮插件准备 | 实际模型/嵌入探测、固定插件安装；准备完成不宣称已经保存记忆 |
| 首项真实任务 | 用户输入正常任务并明确确认本轮采集 | 实际 Codex 执行；官方结束同步与 App 接收自动衔接；退出码不代替持久回执 |
| 项目与记忆形成 | 第一份通过校验的有效材料进入业务库 | 项目登记、授权提升、原文/版本/索引任务共用事务；有数据后才出现项目 |
| 回看与后续使用 | 查看本次知识与完整出处；后续任务查询当前约定 | App 列表、完整原文、Rust 当前版本和真实新 Agent 会话分别取证 |

没有任务材料时不显示“已保存”。官方仍在缓冲或提炼时显示实际等待状态；失败保留已持久化回执，重试按稳定材料 ID 去重。

## 项目尚未建立时的授权

schema16 增加 `connection_intakes`，保存 App 确认的自动建立意图、工作区、Git common directory 和待建立项目身份。既有 `connections` 表保持原列结构，schema2–15 的调用与备份数据继续兼容。

- 不提供工作目录的连接只保留接入身份；默认不能保存到猜测的项目或全局。
- 确认目录之后，预留项目 UUID 不等于项目登记：`scopes`、`repositories` 和记忆列表仍为空项目状态。
- 实际 Git common directory 标识同一本地仓库及 worktree；同名目录、相同远端 URL 或模型描述不能合并独立 clone。
- 已登记的同仓项目复用其 ID；同仓多个待接入连接共享未来项目身份。手动登记也复用已预留身份，避免接收时归错项目。
- 请求仍校验连接 ID、代次、启用状态和实际工作区。Agent 的工具参数不提供随意扩大授权的工作目录字段。
- 项目身份有歧义、来源不可核对或工作区改变时返回明确错误并要求重新选择；不自动归入全局或另一个项目。

未登记项目的官方 dataset 授权暂存于 `pending_cognee_bindings`。真正的首记录写入事务同时登记项目、提升连接范围、迁入正常 binding、保存记录及索引任务。任何一步失败全部回滚；不会留下空项目或把“授权已准备”写成“记忆已保存”。合成连接验证 marker 不作为自动建立项目的首记录。

主动断开或变更代次后，旧任务的迟到导入被拒绝。官方服务已独立提交的材料保留，但不能靠旧回执恢复 Memlane 授权。首次任务页重新执行前也检查当前连接，避免已撤销接入继续发起新任务。

## 当前知识与官方历史材料

官方 Cognee 插件负责本轮采集和官方提炼。Memlane 保留这些实际材料、完整出处和原始版本；App 的用户编辑、恢复及审核继续由 Memlane 当前版本契约管理。

首任务实际接收知识后，在 App 自己的独立 Codex 配置中接入 Memlane 当前知识工具。后续任务询问项目约定时先查询当前正文、版本和范围，官方 recall 的材料继续作为历史出处。读取失败明确报告，不把旧材料冒称当前有效知识。

这条路径不自动回写或修改官方图谱，不把“官方 graph 单独查询”描述为已经跟随 App 编辑。验证分别记录实际官方采集、新会话的 Memlane 工具调用和返回版本；不能将两种召回证据混写成同一接口。

## 本轮验证边界

实现相关检查：真实 SQLite/Git 下无项目连接、明确目录后仍无空项目、首记录失败回滚、成功提交与 binding 提升、重放不重复、同仓复用和不同 clone 拒绝误归、撤权拒绝迟到材料；官方配置保留模型和插件，变更 bridge 身份拒绝静默覆盖。

实际窗口验证使用新独立 App/helper/LaunchAgent、空业务和空组件根、固定真实归档的 loopback 来源及本轮合成任务。只复用已有合成验收的独立模型授权条件；不复制业务库、历史 Agent 会话、组件缓存或用户日常配置。源、根、包、动作、回执与清理分别留在 `build/agent-first-task-validation/`。

当前运行结果以该目录新报告为准；实现和单测通过不能代替真实任务、完整出处、新会话当前版本读取及最终清理。主包、首次准备量、最终占用继续分开记录，但本轮不开展正式分发验证。
