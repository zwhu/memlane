## 1. 当前要解决的问题

后台 Agent 需要能分析已保存材料、返回有出处的建议，并在取消、并发编辑或重复回执下保持知识正确。首先证明这个工程边界，再展开“梦境整理”、引导和排名。后台执行器本轮按用户最新指令采用 **本机 traex / TRAE CLI**；Codex 的历史额度失败保留，不再作为本轮必须等待的执行条件。

| 领域 | 已确认规则 | 本轮工程范围 | 后续产品建议 |
| --- | --- | --- | --- |
| 整理 | 摘要、标签可以自动；合并、覆盖、删除、跨项目移动需要确认 | 两条合成知识的纯合并提案与显式确认事务 | 有出处的主题摘要、标签、冲突与全局经验建议 |
| 历史 | 编辑与整理保留记录，恢复产生新版本 | 新合并条目与两来源归档版本、来源快照、回执 | 栏内差异、拒绝、过期与恢复入口 |
| 来源 | 仅使用 Agent 实际提交内容，不读取完整聊天 | 冻结正文及具体 revision，quote 精确匹配 | 区分来源证据、推断与待核实内容 |
| 首次使用 | 首次打开直接进入首页；初始化采用复制 prompt | 保留已有入口，不做初始化批次 | 可跳过、可恢复的设置清单 |
| 使用记录 | 不能将检索返回当作实际采用 | 不实现统计或排名 | 读取/返回/采用分别观测，透明排序 |
| 调度 | 用户选择执行者和授权范围后启用；主动停服不运行 | 不做定期调度 | 单任务、休眠补跑、窗口与有限重试 |

## 2. 记忆形态与适用范围

“项目/全局”描述适用范围；“原始记录/知识/主题摘要”描述内容职责。不得因为条目常用或进入更高层表示而自动跨项目。

原始记录作为依据保留，不计普通知识新增。用户或 Agent 保存的知识不必等待整理，索引完成后可检索。主题摘要作为有来源的独立知识是 P3 建议；原条目保留，摘要不能成为新的独立证据。已有摘要被改写仍需要确认，来源变化后的失效传播另行设计和验证。

本次实验只合并同一范围内两条有效知识：确认后创建新条目，原两条各追加归档版本，保留旧正文、来源和活动事实。该实现是已测试的实验选择，正式归档/恢复契约仍需在生产切片前收口。

## 3. 整理与审核流程

选取授权材料 → 冻结版本和来源 → traex 返回纯提案 → 服务校验并登记待确认建议 → 展示依据与差异 → 明确确认 → 原子提交 → 既有 worker 索引。

Agent 不获得日常记忆写工具或数据库句柄。输出中的批准字段、自由动作、伪造来源和范围扩大都不能生效。取消只阻止尚未提交工作；已应用事实保留，不能宣传成撤回全部结果。建议登记后取消会保留建议记录，但不能继续应用。

任务执行状态与建议审核状态分开。真实失败、无结果、无效输出、取消、版本过期、索引失败和已保存待索引都要有独立含义。

## 4. 后续引导、档案与排序

引导建议在宽幅首页展示“组件准备—添加项目—连接 Agent—可选初始化—检查共享”。状态来自实际健康/连接/索引结果，复制 prompt 不等于导入成功。跳过和恢复是体验偏好，不能代替能力检查。

记忆档案建议展示正文、范围、原始依据、变更、使用事件与统计起始时间。成功读取、检索返回和明确采用是三类事实；App 浏览、后台整理读取与连接验证另列，不能增加日常常用排名。

首版排序建议是最近更新、近 30 天成功读取、用户重要标记，不引入综合质量分数；零使用不暗示无价值，低排名不触发删除。时间窗口、事件保留期、并列规则在相应切片前收口，本轮不创建统计表或清理数据。

## 5. 交付边界与下一阶段

本轮交付两个工程验证、最小可保留实现和测试、真实证据、重生成的 P3 文档及 prompt。完整 P3 UI、调度、排名、初始化、代码图谱和其他 Agent 不在范围。

下一步进入 P3-C 手动整理的正式快照/来源/提案决定/回执契约与服务审核切片。先制定兼容迁移、权限和错误契约，再连接栏内审核；使用事件与初始化各自在其切片前定义。补充图稿、原型点击、原型归档和文案定稿可以随后完成，不替代真实工程验收。
