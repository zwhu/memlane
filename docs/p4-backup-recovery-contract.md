# F1b/F1c 一致性备份与离线恢复契约

2026-11-08，F1b 手动备份本机通过，见 [验证](p4-backup-validation.md)；F1c 离线恢复仍为正式契约草稿，未实现。[F1a 原文检索重建](p4-index-recovery-validation.md) 已通过；本契约处理完整 SQLite 数据快照及恢复拥有权，不以进程重启或索引重建替代数据恢复。先交付 F1b 手动备份，再交付依赖它的 F1c 离线恢复；总目标不在切片处结束。

## 手动一致性备份

App 设置中明确点击创建备份，使用稳定 UUID；同 UUID 返回同一已验证快照，不再次捕获后来变化。备份由受信本机服务操作其自己持有的 SQLite 连接，日常 Agent/后台整理不获得数据库或备份操作。备份不调用模型、修改正文、版本、授权或活动。

备份包含原文、来源、具体版本、项目、决定、整理/初始化/使用及代码任务历史。它不包含模型/组件、原代码仓库、Agent 登录凭据或聊天；代码与原文索引是可重建派生物，不能宣称随 SQLite 快照一起备份。

固定 modernc SQLite 1.61.1 的在线 backup API 将一致性快照复制到私有内存连接，再序列化为普通 SQLite 文件；包含已提交 WAL。源连接在复制、校验与序列化期间串行占用，不跨网络或模型调用持 SQL 写事务。在线快照上限 64MiB，单次操作有取消/超时；提前检查页数并在每批次检查上限，超限返回明确原因，不能截断后宣称成功。该上限控制复制/序列化的数份瞬时内存，首次不创建无限备份计划。超限的大库离线备份需另行实测，不算当前在线能力。

目录为当前服务根的 `backups/manual/<operation UUID>/`，完整发布单元包含 `snapshot.sqlite` 与 `receipt.json`；staging 只在同一管理根，完成 fsync 后原子发布。记录 ID、schema、创建时间、字节数、SHA256 和本数据根的稳定 vault ID。普通文件0600、目录0700；同目录已有有效快照不覆盖，未知目录不回收。读取和写入通过固定 os.Root，拒绝管理目录/快照/回执链接，核对目录身份；不接受用户或模型传入任意输出路径。取消/崩溃后的未发布 staging 不出现在完成列表。

App 列表显示真实创建时间/schema/大小与校验结果；不存在、损坏、非本数据根或散列不符明确失败，不能以文件存在当作完整备份。备份记录保留于管理目录，不加入知识数量、使用排名或独立出处。没有新 SQL 表需求时不迁移 schema。

## 实际接口取舍

`build/p4-delivery/backup-native-fd-probe.json` 与 `backup-modernc-fd-probe.json` 为明确 IO 实验：原生 SQLite 的 VACUUM INTO FD 路径返回 output file already exists，实际 Go 驱动返回 unable to open database file(14)。不能假设普通路径 SQL 输出已被 os.Root 限定。

`backup-memory-probe.json` 使用实际固定 Go 驱动，在线复制到内存、序列化、通过固定 Root 文件句柄写出后，重新打开真实文件 integrity_check=ok、原表保留。它只证明该小型 IO 底座，非 App/生产库/完整手动备份验收；WAL、并发、失败清理、重放和目录边界另验。

## 离线恢复与决定

F1c 仅允许用户选择已验证、本数据根的备份，在栏内预览时间/schema/替换范围并确认。取消不改变数据。完整库灾难恢复与单条知识历史恢复分开；单条恢复继续产生新版本。完整恢复先保留当前库的可恢复副本/记录，说明备份之后的更改仍在恢复前副本中；不自动丢弃或覆盖唯一当前数据。损坏当前库时保留原文件与 WAL 的隔离副本，不能假称其完整性通过。

恢复先明确停止服务与 worker，等待拥有者退出，取得服务根和数据库两层排他锁；在 staging 中核对来源、散列、完整性、支持 schema 并完成必要迁移/备份，再原子替换。失败保留当前库与旧备份；旧/迟到进程不能发布或使用索引目录。恢复回执保存在本数据根独立恢复记录中，同 operation UUID 重放不再次切换数据。

恢复后服务保持 stopped。清除恢复数据的有效检索绑定，当前有效原文进入既有重建队列；只在用户明确启动后执行。代码配置全部停用，旧图排除，需用户明确重新开启；原授权与历史记录保留为恢复快照资料。

所有备份中旧连接永久撤销，不能因恢复或重新连接而复用旧 ID/代次。F1c 如需记录退休 ID，只在真实恢复实现时引入对应表；用户确认重新连接返回新 ID，保留旧连接关联的使用历史。全部模型计划停用、活动 attempt 中断、自动恢复授权取消、待审核建议失效；不因旧备份中的 enabled 或运行时间复活已撤销授权/收费任务。用户需重新选择范围、连接与计划，不提取凭据，不修改日常 Agent 配置。

## 验收与后续边界

F1b：真实 App 创建/列表/重放与 SQLite WAL 快照，临时库全部业务表逐项保留；明确 SQL/IO/链接/散列/取消/发布故障夹具，未完成目录不列成功。完整包和系统窗口分别验收。

F1c：实际 App 确认恢复合成库，恢复前副本、完整原文/来源/版本/历史、stopped、索引重建与 Rust当前检索；旧连接/旧代次/旧建议/计划/代码图排除，重放、崩溃/重启和失败回滚。涉及迁移先临时旧库证明保留；故障夹具不冒充正常 App 或 Rust。
