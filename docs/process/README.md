# 过程文档与验收媒体目录（`docs/process/`）

本目录用于统一隔离存放项目开发与验收期间产生的**过程文档及媒体产物**。除本说明文件外，目录下所有内容均被仓库根目录 [`.gitignore`](../../.gitignore) 忽略，**不提交入库**。

## 一、什么是过程文档（核心定义）

**过程文档**指在需求探索、方案讨论、调试排查、实现推进与测试验收过程中产生，**仅服务于当次任务推进或留证、不构成项目长期唯一真相或长期演进基线**的一切文档与媒体产物（不限文本、图像、视频或数据格式）。

> **一句话判定标准**：当该任务完成并合入主线后，即使删除这份产物，也不影响后续协作者理解当前系统的产品定义、设计规范、架构契约或长期防复发教训——则它属于过程文档，应放在 `docs/process/`。

## 二、明确属于过程文档（放 `docs/process/`，不入库）

- **验收与评审媒体**：原型自查截图、Native 实窗验收截图、视觉前后对比图、动效/交互录屏视频、GIF、辅助功能树导出等（含 PNG/JPG/WebP/GIF/MP4/MOV/WebM 等全部媒体格式）。
- **任务执行过程记录**：单次任务的临时实施计划、拆解草稿、多轮排查笔记、逐轮验收流水记录、临时压测/性能对比原始报告。
- **未定稿探索产物**：方案比选草稿、临时原型导出物、过渡期对照说明。
- **临时诊断转储**：局部日志片段、临时核对脚本输出（注意：严禁在本目录存放任何密钥、真实记忆库或本机 Agent 凭据，运行态真实数据一律留在 `.local/`）。

## 三、明确不属于过程文档（放正式 `docs/` 分类目录并入库 Git）

- **生效中的产品与设计基准**：`docs/product/`、`docs/design/`（含产品定义、视觉规范、动效契约、可交互原型源码与长期实施总账）。
- **稳定的系统架构与跨模块契约**：`docs/architecture/`（系统分层、开发说明、接入/模型/队列隔离等现行契约）。
- **沉淀长期结论的专题技术调研**：`docs/research/`（供后续功能选型与决策长期复用的调研报告）。
- **持续生效的工程规范、复用模板与防复发复盘**：`docs/engineering/`（工作流、门禁要求、模板与“四次失败停止”/事故防复发记录）。
- **正式引用的静态图表与历史归档**：被根目录 `README.md`、`AGENTS.md` 或正式基准文档直接长期引用的少量精选图表放 [`docs/images/`](../images/)；明确留痕以供追溯的退役基准放 [`docs/archive/`](../archive/)。

## 四、流转原则（先入过程，定稿晋升）

1. 默认将所有新生成的验收截图、录屏视频、评审草稿与排查流水放入 `docs/process/<主题或日期>/`，避免污染正式文档目录或源码树。
2. 仅当某份探索或排查沉淀出**长期生效的规范、契约、调研结论或防复发教训**时，再将精炼后的正式文档写入对应 `docs/` 分类目录；若正式文档或 `README.md` 需要直接内嵌少数关键静态图，再将该图移入 `docs/images/`。
