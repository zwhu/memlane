# 全局经验复制与提炼契约

本切片正在实施，尚未通过真实验收。以 C3/C4 的来源、版本和逐项确认规则为基础；不按排名或频率跨项目提升，不移除原项目知识。

## 入口与授权

- 项目记录详情提供「原文复制到全局」：用户明确选择当前项目条目和具体 revision，复制其当前正文为新 experience 知识，不调用模型。
- 「AI 提炼为全局经验」冻结这一条当前项目记录，由真实 traex 返回通用表述、适用条件和具体来源引用；先显示预览，再逐项确认或拒绝。
- 材料整理可显式开启全局经验候选；模型仅提出待确认的 global_experience，不直接批准。原有 v1/v2 格式保留；新增 v3 输出只随实际功能启用。

源项目及原文保留。目标固定为本机登记的 experience 范围，不能借入口任意读取其他项目。摘要或同源转述仍保留原始依据，不成为新的独立证据。日常 Agent 查询当前项目/已授权全局；项目明确约定优先于全局建议。

## 生效、版本与幂等

原文复制是明确用户动作：源当前版本/范围/有效性（包括派生失效）重验，新 knowledge、具体出处、派生关联、复制事实及索引任务同一事务。operation_id 绑定源项目/ID/revision；首次事实已提交后重放返回原回执，不重复写入、恢复删除或改写新版本。同标识异来源冲突。

AI global_experience 为审核项，保存 title/text/conditions/来源版本/quote/目标全局身份/摘要。确认前来源变化即过期；拒绝没有知识副作用；确认事务再次检查源与 experience 范围身份，新建全局知识/适用条件/冻结出处/用户确认事实/回执/索引。原项目有效知识不改。模型与网络在 SQLite 事务外，取消和多 attempt 沿用 C3/C4 栅栏，已提交保留。

当前全局正文不自动随源项目后续变化覆盖。已确认事实保留历史与来源变化提示；未确认建议过期。用户编辑/恢复全局经验仍追加新 revision，适用条件随版本保存并允许明确编辑；恢复旧版本同时恢复当时条件但产生新版本。

## 范围与原文

原文复制的全局正文由用户明确提升，可由已授权全局消费者读取。AI 提炼仅提升用户确认的通用表述和条件，不能把未提升的项目原文、旧 Original 或 SourceDetail 片段塞入全局 Agent 回执。

受信 App 可检查本机冻结来源。日常 save/get/status/search 回执和后续整理的模型快照，只有显式范围也授权初始项目时才能返回该项目旧正文；否则保留当前全局表述、来源身份及未授权说明，不泄漏项目引用原文。get 某个来源 ID 仍需其项目授权，不因全局关联自动放行。

## 持久化与验收

schema v6 增加实际全局经验 kind/conditions 版本记录及其审核/决定表，不重建 v5 固定动作 CHECK 的原表；复用既有 knowledge/operations/organization_sources/derived_memories/审核决定与回执。迁移前一致性备份，临时 v5 库核对旧数据/WAL/决定保留。复制与提炼的 SQL 中途失败整项回滚；索引失败保留正文和回执。

真实 App 验证原文复制、traex 通用提炼、适用条件预览确认/拒绝、整理候选、来源原文保留、版本过期、重放、用户编辑/恢复、真实 Rust 项目与全局范围检索。故障/协议夹具只验证边界并明确标记。证据目录 build/p3-global/；通过后再更新清单、提交并继续计划/使用/初始化/日常接入/图谱/正式交付。
