### TraeX 问答采集

TraeX 的 `Stop` 和 `SessionEnd` 回读当前会话的 rollout，复用 Cognee 的 Codex 解析与问答配对。后续采集可以补上已写入日志的中断提问及阶段回复。运行中追加的提问各自参与配对，有对应回复或中断记录时进入问答列表。工具调用仍由 TraeX 原生工具事件采集。

回读限于当前 TraeX profile 中与宿主会话 ID 匹配的日志，经过项目采集授权和暂停水位。升级后首次恢复旧会话从切换时的水位开始采集。

### Antigravity（Gemini App）接入规范

- **安装与配置目录**：宿主类型为 `antigravity`（`Gemini.app` 及原生 `agy` 辅助程序，默认扫描 `PATH`、标准用户 bin 与 `Gemini.app/Contents/Helpers/agy`）；电脑级配置目录固定为 `~/.gemini/config`（当前拒绝自定义非标准路径），配置文件为 `~/.gemini/config/config.json`，受管派生插件目录为 `~/.gemini/config/plugins/memlane-cognee`（基于固定官方 `integrations/antigravity/` 与共享 `_coding_memory.py` 构造，保留其他插件，检测到冲突旧 Cognee 插件时拒绝覆盖并要求人工复核）。
- **入口与采集范围**：`entrypoints` 为 `['desktop']`，自动采集面向 Gemini App task / CodeMode 的**新会话**（不自动回采启用前的历史会话，普通聊天未核验）；通过 `antigravity_hook_policy.py` 执行实时策略门禁、采集与召回，并在 `~/.cognee-plugin/antigravity-<instance_id>/last-hook-error.json` 只读暴露最近一次有效 hook 错误供诊断。
- **身份与升级保护**：遵循独立官方子主体与电脑级零项目授权原则（`prepare()` 不向任何项目、通用记忆或 `ml-user-profiles` 授予访问权限）；对已激活实例重新准备升级时必须核对 `upgrade_review_sha`，未经确认不得覆写活动代次插件。

## 连接与项目

接入是电脑级连接，不以项目、工作目录或第一项任务为前置。**电脑级身份准备（`prepare()`）仅建立独立官方子主体与私有凭据，不得据此向任何已有项目、通用记忆或受保护数据集（如 `ml-user-profiles`）自动授予访问权限**；项目关联只决定材料归属和检索分组，不能猜测无明确来源的归属。

所有有效接入指向同一个本机服务，每个类型与独立 profile 使用自己的官方子主体与独立 `X-Api-Key`，管理 owner 留在接入网关控制侧。逐项目权限沿 PA 契约执行：`none` / `read` / `maintain`（`maintain` 包括 `read/write/delete`，不授 `share`）。服务地址不可达时不使用 owner、离线 CLI 或另一套日常库 fallback。

## 界面状态

设置只显示已安装／待重载／服务可连接等真实连接事实。安装完成不等于生成记忆；模型连接、材料采集、采集/提炼队列状态和记忆生成分别表达。

Codex、Antigravity（Gemini App）、pi、TraeX（以及保留兼容的 OpenCode、Claude Code、Cursor）逐项显示检测、准备、启用、重载及真实新会话事实；批量取消保留成功项，未知写入保留原编号，重开后只读核对。Cursor 无工具回合当轮注入限制保留，实际 IDE／CLI 尚未验收。

记忆提炼独立支持 Agent 模型代理（Codex、Antigravity `agy`、pi、TraeX）及直连 LLM Provider / Ollama。多个已保存配置只有一个当前使用（唯一 `active`）；保存、验证及下次启动/热切换分开，验证记录实际 adapter 请求模式，不将 Schema 请求形状写成远端严格保证。真实供应商与宿主证据按支持矩阵区分。

后台记忆提炼会话隔离项目上下文、采集插件、工具和日常历史；认证复用不等于复制全部 Agent 配置。日常编码采集与后台提炼的进程各有明确所有者。

## 本机发现与设置入口

2026-11-14用户明确要求新增Agent与Provider沿用此前设计并加入设置（V4 设置已收敛为「记忆提炼 / Agent 与模型 / 服务」三标签，不另建独立连接向导）：

- **设置 → Agent 与模型（原「服务与连接 → Agent 连接」）**：启动及进入设置时自动检测本机安装，提供“重新检测”。Codex、Antigravity（Gemini App）、pi、TraeX 及其他兼容适配使用同一列表；未安装项不可勾选，适配未就绪项如实显示状态。
- **绑定流程**：选择 Agent → 连接所选 → 同页查看具体配置变更 → 确认连接 → 按提示重新打开宿主并新建会话 → 显示“已连接”。底部只呈现当前阶段的一个主操作；准备与启用仍由后台分开执行，不能跳过配置变更确认。取消保留成功项；结果未知时核对原操作。电脑级绑定不先要求选择项目或提炼模型，也不自动授予项目权限。
- **检测与状态**：检测只读取安装事实，不读取聊天或密钥、不自动配置。卡片区分未安装、未连接、已准备、待重载／新会话、已连接及需核对；实际接入使用独立官方子主体，项目权限另在项目「管理」页配置。
- **设置 → 记忆提炼 / Agent 与模型（Provider 配置）**：沿用唯一 `active` 提炼来源选择（「用已连接的 Agent 提炼」与「直接调用模型 API」）及“添加 Provider”弹窗表单，填写协议、模型、API 地址及所需密钥。保存、验证和启用分开，只有一个当前使用；无需先绑定 Agent，也不从 Agent 配置提取密钥。

当前源码已有自动检测、重新检测及批量准备／启用入口；Codex、Antigravity（Gemini App）、pi、TraeX 已纳入 `v0.1.0-beta.1` 首发四宿主，pi／TraeX 实际 Native 设置证据见执行记录检查点四十五，OpenCode 实际 Native 绑定及新会话回执见检查点四十七、五十。各 Agent 的采集、召回、记忆提炼质量与暂缓验证范围仍分别按支持矩阵与发版边界表达，不因列表项存在而视为全部交付。

Agent 连接分别显示 TRAE CLI 和 TRAE IDE，项目权限按连接身份设置。TRAE CLI 使用既有 `traex` 身份并可选为记忆提炼处理器。TRAE CN IDE 使用独立的 `trae_ide` 采集身份。用户确认后，Memlane 在 `~/.trae-cn/hooks.json` 合并受管命令组。先在 Memlane 授权对应项目，再在 TRAE 打开该单根工作区并新建会话。适配器使用 IDE 的提问、工具完成和回复结束事件进行实时采集，在提问时按项目权限自动召回。Hook 在默认沙箱内经回环接口转发，由接入网关按 IDE 身份鉴权并保存。多根窗口无法从全局 Hook 的工作目录确认会话对应的项目时跳过。提炼继续使用已配置的 Agent 模型代理或直连 Provider。
