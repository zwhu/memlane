# 下一步 P3-C1 Goal prompt

2026-11-08。P3 两个最小实验已通过；本文件用于下一步正式服务端切片，不重复执行已完成的实验 Goal。[实验复查 prompt](p3-experiment-goal-prompt.md) 保留原指令，[验证记录](p3-validation.md) 是当前工程证据。

## 可复制执行内容

```text
/goal

推进 Memlane P3-C1：将已验证的 traex 纯提案和原子合并接入正式服务端闭环，完成正式契约、兼容迁移/备份、持久任务、确认/拒绝/取消与私有 IPC。此切片不实现 P3 UI，不展开摘要/标签、调度、排名、初始化、代码图谱或其他 Agent。

先阅读 AGENTS.md、docs/product.md、docs/design.md、docs/technical-plan.md、docs/implementation-plan.md，以及全部 P3 产品/交互/技术/架构/研究/验证文档。核对分支、HEAD、远端、工作区和实际 schema；保留用户无关修改。已确认产品规则优先，实验参数、表和接口不能直接升级为正式 API。

一、收口最小正式契约
- 只支持用户触发、同一授权项目内两条有效知识的合并建议；后台执行器用本机 traex / TRAE CLI，保持现有认证和模型选择。
- 明确冻结输入/来源、task/attempt 栅栏、输出、任务状态与审核状态、确认/拒绝/取消、过期、幂等回执、合并归档/恢复和错误类型；将决定依据写入 P3 技术/架构文档。
- 区分开始时的快照检查和提交时的重新校验。拒绝不等于任务失败；取消不隐式撤销已应用事实。来源关联具体版本，不补造旧来源。
- 工程取舍在已确认规则内自主完成；确实缺少产品决定时提出具体选项，同时继续不依赖该答案的工作。

二、实现正式持久化与服务规则
- 从实际 P2 schema v2 增量迁移，由唯一数据库拥有者进行一致性备份；用临时库证明旧正文、历史、来源、活动、operations、索引 jobs/bindings 和连接全部保留。测试新 schema 拒绝不安全的旧写入。
- 不把 p3_experiment_* 附加表直接当作正式迁移，不清理或迁移真实用户库。
- 复用 Store.Apply/applyTx、版本和索引机制，集中实现原子两来源合并；新正文、两条归档历史、来源、回执及索引任务一次事务提交。
- 持久化最小任务/attempt、固定快照、结果与取消；服务重启时识别中断并失效旧 attempt，拒绝旧进程的迟到结果。完整租约和自动重试不在此切片，除非是保证该闭环正确性必需的最小机制。

三、接入真实 Runner 和私有 IPC
- 将已有受控 Runner 复用于正式服务，不把 P2 日常连接验证器改成整理器。后台 Agent 不持有生产写工具或 DB 句柄。
- 分别隔离 TRAE_HOME/TRAECLI_HOME、任务目录和 ephemeral 会话；限制全局 .agents/skills、plugins/hooks/memories 与工具，保留本机协议所需 code-mode host。不能仅凭 CLI 参数声称已隔离。
- 定义类型化开始/查询/取消/确认/拒绝 IPC，按已有服务身份和范围校验，长任务立即返回稳定 task ID。审核入口由受信宿主触发，不向日常 Agent 暴露直接确认写工具。
- 网络执行不持有写事务；服务停止必须取消并收口其进程组，已提交知识和回执保留，重启不重复应用。

四、必要验收
- 从 P2 临时库迁移、重开及备份恢复验证；验证旧数据与索引绑定不丢。
- 正式服务/IPC 经真实 traex 产生建议：确认前正文不变；明确确认后，真实 Rust 检索只返回新合并版本；拒绝后知识不变。
- 任一目标被编辑时整项过期，无部分归档/覆盖；同提案或回执重放仅一次，异内容/异提案重用标识冲突。
- 取消先提交拒绝迟到结果，应用先提交保留事实；服务停止/重启和旧 attempt 迟到仍安全。
- SQL 中途失败完整回滚；索引失败保留正文与回执，既有 Requeue 重试恢复检索。
- 必需真实正常与取消不能由协议夹具代替；故障夹具明确标注。认证/额度/协议阻塞保留原始错误，继续模型无关工作，不宣称全部通过。
- 执行 sh scripts/go.sh test ./...、vet 及受影响的 race/服务检查。没有 UI/打包变化时不重跑无关的整套 P0/P1 验收。

五、每阶段 handoff 与交付
- 开始时读取 .trae/skills/handoff/SKILL.md。每个验收切片结束、重大阻塞、上下文或会话切换前，以及最终交付时，都实际生成交接，不只承诺稍后生成。
- 当前技能标记 disable-model-invocation: true，不要求 Agent 自动调用被禁止的 Skill。用 scripts/p3-handoff.py 直接按其格式生成系统临时交接，并注明“脚本生成，未通过 Skill 工具调用”；不修改技能配置，不假称执行了 /handoff。只有用户显式调用或工具契约允许时才真正调用技能。
- 命令：python3 scripts/p3-handoff.py <阶段> --result '<结论及证据路径>' --next '<下一步具体任务或阻塞解除条件>'。
- 交接至少包含目标、阶段、分支/HEAD/未提交状态、证据、剩余工作、下一步、约束和 suggested skills。只引用规范/代码/日志，脱敏，不复制凭据、聊天、真实记忆或完整模型输入。保存 TMPDIR（否则 /tmp），不提交临时交接。
- 创建阶段 handoff 后继续下一阶段，不因生成交接而停止 Goal。必须确认文件实际存在、内容与本阶段一致，并在验证记录中记录路径。
- 更新 docs/p3-validation.md、实施清单及对应正式契约，只勾选有证据的项，检查本地链接。
- 每个验收切片通过后提交相关实现/文档；最终推送当前授权开发分支并核对远端 SHA。不强推，不提交用户无关改动、密钥、真实数据库、聊天或本机 Agent 配置。

完成标准：正式服务端真实“开始→纯建议→确认/拒绝→原子应用→检索”，以及迁移、取消、重启、过期、幂等、回滚和索引失败都有可重复证据。编译、按钮、自然语言成功或退出码 0 单独不算通过。最终说明改动、真实通过项、阻塞、下一 P3 切片、提交/远端及最后 handoff 路径。
```

## handoff 的执行方式

[本地 handoff 技能](../.trae/skills/handoff/SKILL.md) 明确禁止自动模型调用，且要求写系统临时目录。本 prompt 使用 [P3 交接脚本](../scripts/p3-handoff.py) 直接生成同类文档；这不是调用被禁止的 Skill，不需要修改用户 Agent 配置。用户主动调用 `/handoff <下一会话用途>` 时仍按技能契约执行。

完整 P3 UI、主题摘要/标签与自动产出策略在后续切片完成；本轮正式化优先保证知识正确性和持久服务生命周期。
