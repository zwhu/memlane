## 2. 手动整理与审核路径

首页/记忆页“立即整理” → 整理记录右栏选择项目和执行者 → 开始 → 进行中 → 完成/失败/取消 → 查看依据和建议 → 确认/拒绝/过期。

正式 UI 使用“立即整理”和“编辑”等已确认名称。“梦境”作为整理页面表述仍待评审。本轮执行器为 traex，但界面不能因为 P2 日常连接可用就直接标记后台执行已验证；后台能力须有独立真实证据。

右栏确认前展示全部目标与具体版本、建议正文、来源引用、适用范围及合并保留方式。提交时重新检查所有目标，过期时展示当前内容与原建议，提供重新整理；不能部分覆盖仍匹配的来源。

| 状态 | 用户应看到的含义 | 本轮证据边界 |
| --- | --- | --- |
| 进行中 | 任务正在执行，可取消、可离页 | 后台进程与任务门禁已实验；UI 未实现 |
| 待确认 | 只有建议，已有知识未改变 | 实验真实结果登记；UI 未实现 |
| 已应用待索引 | 正文与回执已保存 | 原子事务已实验；UI 未实现 |
| 索引失败 | 知识仍在，可重试 | 既有 service/worker 重试已验证；UI 未实现 |
| 过期 | 任一来源变化，整项不能应用 | 临时数据库并发/编辑实验；UI 未实现 |
| 取消 | 未提交工作停止，已提交事实保留 | 真实进程与协议夹具分别记录；UI 未实现 |
| 失败/无结果/无效输出 | 保留输入与错误，不显示成功 | Runner 协议门禁；UI 未实现 |
| 拒绝 | 单项建议未采用，任务并非因此失败 | 正式决定契约与 UI 后续完成 |

## 3. 引导、档案与计划建议

引导在首页进行，可跳过并从设置继续；组件、项目、连接和索引完成度来自实际状态。初始化保留复制 prompt 方式，批次回执、关闭/过期和热力图区分后续实现。

档案中的读取、返回和采用分开，未采集时明确说明；不把内存示例次数当作真实排名。最近更新、常用与重要优先的排序仍待服务口径收口。

计划需先选执行者、范围并启用，首次不自动调用收费模型。每日 22:00、30 条、五分钟和空闲阈值都是原型建议，不能成为实验或产品的默认授权。睡眠、主动停止、重启和窗口限制另验。
