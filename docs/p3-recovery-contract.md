# P3-D2 执行拥有权与有限恢复契约

2026-11-08，D1 已通过并推送。D2a 租约与进程保护已按 [验证记录](p3-recovery-validation.md) 通过；D2b 的有限自动重试和完整恢复必需项尚未验收，不能据本文勾选完整 D2。依赖 [D 计划契约](p3-schedule-contract.md)、C3/C4/E 已持久任务/结果/项/决定与独立索引规则。

## 分片与授权

D2a 增量交付全部正式 organization model/apply attempt 的持久拥有权租约与服务崩溃后的进程保护；D2b 再交付有限重试/退避/错误分类、已有结果继续应用、重启与迟到/部分提交故障验收。D2a 不会改变已有计划的模型次数：旧计划和手动任务仍不自动模型重试，收费重试必须由用户选择次数和总窗口后启用。

后台执行保持 traex 自己的模型和认证；来源、范围和原子结果契约不变。网络/模型不持有 SQLite 写事务。持久表按实际功能分次引入，每次迁移前由唯一数据库拥有者一致性备份，临时旧库全表保留证明。

## D2a 租约与进程保护

每个正在执行 attempt 保存随机 owner、到期 UTC 毫秒、进程组标识与回收状态；owner 不提供给日常 Agent。TTL 45 秒、每 10 秒续租为本机拥有权工程参数，不是运行频率或费用预算。串行执行槽获取后才建立租约；未进入执行的 queued 任务不占用租约，不累计模型调用。

续租要求 task 当前 attempt、未取消、进行中、相同 owner 且未到期；过期租约不能通过续租复活。Claim、Stage、自动 Apply/失败标记/Finish 在自己的短事务内核对 owner/attempt/到期和计划 generation。旧 owner、迟到结果、停用/取消和租约失效均不能提交新事实。已提交项回执先重放，不被后续租约撤销；用户审核完成的建议使用既有确认边界。

续租失败立即取消真实进程，等待进程与组回收后才释放本机执行槽。到期不能直接占用同 attempt 的旧租约；下一执行需要明确新 attempt，旧 owner 行作为执行记录保留。服务查询协调/退出和下次启动使旧租约失效，已提交结果保留，不在 D2a 自动重跑模型。

正式 helper 增加仅供内部执行的进程保护入口。保护进程与 Agent 在同一个独立进程组，持有仅服务保留写端的控制管道；服务意外退出或被 kill 后读取 EOF，立即终止该组。Agent 不继承控制文件描述符、不获得生产数据库或配置。正常取消仍由服务杀组并等待回收。重启先确认已登记的旧进程组消失，未消失时拒绝自动恢复，不盲目 kill 可能已复用的 PID。

模型执行当前已有两分钟上限保持；对其他后台执行器按独立适配验收。保护进程并不是 OS 全面沙箱声明，工具/配置/根隔离仍独立验收。

## D2b 有限恢复

计划重试设置默认 0，用户明确填写额外次数（0–2）和总恢复窗口（不超过 24 小时），界面展示最多调用总次数和当前单次执行上限；新增重试设置的启用/修改推进 generation。没有明确收费授权时只允许已有持久结果的无模型收尾。

认证、执行者/模型不支持、范围拒绝、来源过期、协议/结构化结果不合法不自动模型重试；明确瞬时网络错误或超时可在授权窗口内有限退避，其他错误默认不可重试。持久 task ID 不变，新 attempt 重新 seal 冻结来源版本和结果 ID；源发生变化时终止恢复，不借重试扩大范围。退避记录 next_retry 和实际 reason，不把 waiting 当新模型已运行。

已存在持久结果时只创建 apply attempt，重用已有项标识/结果/决定/回执；已应用项不重复新增活动或标签事件，取消保留已提交部分。重启根据当前计划和窗口恢复，旧 generation/主动停服不得恢复。持久恢复次数用唯一事务消费，重复触发和旧 owner 不重复扣次或执行。
