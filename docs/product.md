## 1. 已确定的产品规则

| 领域 | 第一版决定 |
| --- | --- |
| 首页 | 全局总览，以最近积累的知识、待确认的整理建议为主；Agent 和服务状态处于次要位置 |
| 每日记忆 | 用类似 GitHub 提交日历的热力图，展示每天产生多少记忆 |
| 默认内容 | 记忆包含原始记录与可复用知识；默认知识，原始记录单独页签。Agent明确调用保存工具提交、取得持久化回执的知识，以及用户手动保存的知识，不必等待整理；工具能力不代表日常默认自动提交，具体定义见[内容分层](ui-redesign/content-model.md) |
| 接收原则 | 遵循 Cognee skill 和 Agent 的实际提交；Agent 存什么就接收，不由客户端先做重要性筛选 |
| 手动新增 | 用户输入视为用户确认的知识，保存并建立索引后可被检索，不必等待定期整理 |
| 操作名称 | 「立即整理」由用户触发 AI 整理；「编辑」由用户亲自改知识 |
| 整理内容 | 提炼、清理、归类都需要；包括摘要、标签、重复与冲突的处理建议 |
| 自动执行 | 新增摘要、添加标签可以自动完成 |
| 待确认执行 | AI 提出的合并、覆盖、删除、跨项目移动需用户确认；确认前不改变已有有效知识 |
| 定期整理 | 用户自行设置运行频率，同时保留「立即整理」 |
| 编辑与整理历史 | 每次编辑、每次整理都记录；可以查看修改差异，恢复单条知识的旧版本；恢复也产生一条新记录 |
| 项目 | 一个项目对应一个代码仓库，多个 Agent 共用记忆；提示用户选择项目，可跳过，连接后有有效数据再自动建立或复用对应项目 |
| 检索范围 | 默认当前项目＋全局个人偏好＋全局经验；其他项目需要明确指定 |
| 冲突优先级 | 同一事项上，当前项目的明确约定优先于全局建议；保留两者的来源与适用范围 |
| 全局经验 | 支持「AI 提炼为通用表述，预览确认后保存」和「原文复制」两条路径；保留原项目记录、来源关联及历史 |
| 全局经验建议 | 整理时可以发现候选经验，列入待确认；全局经验保留适用条件 |
| 代码图谱 | 2026-11-09 确认首版隐藏入口；原设计与工程记录保留，记忆实体／关系图继续展示 |
| 首批 Agent | 目标接入 Codex、pi、TRAE、traex；适配能力逐一验证 |
| 整理执行者 | 第一版统一指定一个具备后台执行能力的 Agent；以后再支持按项目指定 |
| 提炼模型 | 默认通过本地 Agent 桥接，由用户选择已验证的后台执行者，复用其登录与模型配置；无需为 Cognee 另填云模型 API Key。采集与提炼会话隔离，能力逐 Agent 验证 |
| 初始配置 | 仅准备环境、连接 Agent、配置记忆处理三步，之后进入日常首页 |
| 建立项目知识 | 项目整理可跳过，不阻塞日常提交；空知识页签提供「整理项目」，后续在项目菜单补充。绑定Agent、Token提示及可选历史会话共用；真实回补能力待验证 |
| 关闭窗口 | 收起到菜单栏，后台记忆服务继续运行 |
| 退出 App | 「退出 App 后继续运行记忆服务」默认开启，可关闭；始终保留明确的「停止服务并退出」 |
| 服务异常 | 意外退出自动尝试恢复；未送达写入本地暂存，恢复后补发；读取失败与无结果区分；持续失败给出诊断入口 |
| 主动停止 | 用户主动停止服务时，不触发故障自动重启 |
| 下载与首次准备 | 主安装包保持轻量；本地引擎、原生依赖和模型独立下载，由 App 自动准备，展示下载大小、进度和失败重试；用户无须手工安装依赖 |
| 自动更新 | 主客户端具备自动更新能力；客户端、引擎与模型按兼容版本分别管理，更新 UI 时复用未变化的组件和模型，保留用户知识与设置 |
| 平台与风格 | 第一版 macOS；紧凑、克制、单色图标和按钮、白色内容区、完整连续的浅蓝侧边栏 |
| 页面布局 | 首页是侧边栏＋宽幅总览；列表详情页是导航—列表—详情与操作三栏；侧边栏覆盖顶部窗口控制区并与正文边界连续对齐 |
| 交互承载 | 查看、新增、编辑、历史、整理结果和建议确认在右栏完成；不把普通操作随意做成弹框 |

## 2. 信息架构

```text
主窗口
├─ 总览（首页）
│  ├─ 每日记忆热力图
│  ├─ 最近新增／选定日期的知识
│  ├─ 待确认的整理建议
│  └─ 整理计划与运行状态
├─ 全部记忆
│  ├─ 知识列表（可按项目、来源、类别、时间筛选）
│  ├─ 未整理的记录
│  └─ 知识详情
│     ├─ 当前内容、范围、来源
│     ├─ 原始记录
│     ├─ 编辑、提取为全局经验
│     └─ 历史、差异、恢复版本
├─ 全局记忆
│  ├─ 个人偏好
│  └─ 通用经验
├─ 整理记录
│  ├─ 手动／定期整理的执行记录
│  ├─ 本次新增、已执行修改、待确认建议
│  └─ 建议处理结果、失败与重试
├─ 项目
│  └─ 每个仓库
│     ├─ 记忆
│     ├─ 整理项目（仅空知识列表显示；绑定 Agent、Token提示与可选历史会话）
│     └─ 项目设置
└─ 设置
   ├─ 环境与组件
   ├─ Agent 连接（发现、连接、验证、访问范围、使用记录）
   ├─ 记忆处理
   ├─ 定期整理计划
   ├─ 本地数据与服务状态
   ├─ 退出及后台运行
   └─ 关于与诊断
```

侧边栏切换范围和页面。首页保留宽幅总览：每日热力图在上，最近新增和待确认建议在下，不额外拆成三个固定栏。点击记忆后进入「导航—列表—详情与操作」三栏页面；点击整理建议或立即整理后进入整理记录页，在右栏查看与处理。新增、编辑、历史记录、整理结果和建议确认使用右栏，保留中间列表与选中上下文。普通操作不使用模态弹框；需要确认的修改优先在当前栏内明确展示内容和确认按钮。首版隐藏代码图谱入口，项目记忆中的实体与关系图继续保留。

首次打开仍直接进入主界面，不要求注册客户端账户。空首页展示已发现的 Agent、连接入口、添加本地项目和初始化入口。有数据后显示正常总览。连接状态必须区分已发现、待连接、待重载、可用和异常。

2026-11-09 首次使用入口补充：用户确认环境准备完成后先选择 Agent，提示选择项目并允许跳过，再进入接入流程；完成必要接入与真实验证后，由 App 引导完成第一项真实 Agent 任务，并查看产生的记忆与出处。跳过项目时，连接后首次有效数据到达再依据受信工作区／仓库自动建立或复用项目；连接本身不创建空项目，来源不明确时提示归属。接入契约见 [首任务流程](agent-first-task-flow.md)。本轮新完整配置包已实测 Codex 的无项目连接、明确工作目录、官方准备与真实任务、有数据后登记项目、完整出处及编辑后新会话当前版本读取，见 [验证记录](agent-first-task-validation.md)。其他 Agent 通道与正式分发不由这一切片结果代替；旧项目优先包保留为历史证据。

2026-11-09 用户确认统一环境初始化：官方采集所需的 Cognee 服务、运行依赖与本地向量模型，应与 Memlane 基础服务和 Rust 索引组件一起准备；连接 Codex 时复用已有环境并检查可用性。服务在技术上可以使用独立进程和目录，用户流程统一为一次环境初始化。随后用户确认通过本地 Agent 桥接提供提炼模型：复用 Agent 自己的登录与模型配置，不要求用户为 Cognee 另填模型 API Key。电脑级连接继续不要求项目或提炼执行者；在首次任务准备或设置中明确选择并验证提炼 Agent，采集范围独立授权。本轮已实现服务与模型验证解耦、统一组件准备和首个 pi RPC 模型桥，实际验证和限制单列于 [pi 模型桥验证记录](pi-model-bridge-validation.md)；新 UI 设计和其他 Agent 不继承该结果。既有分段准备验收保留为对应版本的证据。完整要求见 [本地 Agent 模型桥接需求](agent-model-bridge-requirements.md)。

缺少本地组件时，主界面仍可打开，栏内显示准备进度与重试入口；需要索引或模型的能力显示准备中。已经由业务服务持久化的内容可以显示已保存，但组件尚未就绪时不能显示为可检索或 Agent 已可用。首次离线且没有组件缓存时明确说明需要联网准备；准备完成后的本地索引与检索支持离线使用。主安装包大小、首次准备的额外下载量、最终磁盘占用分别统计，具体体积上限尚未确定。

## 3. 首页热力图

用户确认的要求：像 GitHub 提交记录一样，能看到每天产生多少记忆。

以下是本次原型采用的默认细节，后续可在视觉和接口验证中调整：

- 默认展示最近一年，按本机日期划分；每个格子代表一天，颜色深浅代表数量。
- 悬停显示日期和新增数量，点击某天查看当天新增的知识。
- 统计单位是独立的知识条目，不是对话轮次、图谱节点或检索命中数。
- 手动新增、Agent 直接保存的知识、整理产生的新知识，在首次可用时计一次；等待确认的建议不计入。
- 原始对话、工具轨迹和作为出处的片段不计入；编辑、恢复版本、重复同步和整理任务本身不增加数量。
- 把项目经验提炼或复制成一条独立全局知识，算新增；单纯移动已有条目不算新增。
- 搬入已有记忆单独显示导入数量，不回填未经核实的历史日期；默认不把批量搬入的旧记忆计作当天新产生的知识。绑定 Agent 分析仓库后正常保存的新知识遵循普通新增规则，不套用旧受控导入批次口径。
- 历史活动按创建事件记录。之后删除或合并条目时保留活动事实，并在日期详情中标明现状。
- 热力图使用克制的浅蓝色阶表达数据；图标、按钮、普通状态继续保持单色。

原型中的统计和记录均为示例数据，不能视为四款 Agent 已经完成真实接入。

## 4. 关键流程

### Agent 接入与项目知识库初始化

发现本地 Agent → 用户连接 → 配置共享记忆接入 → 实际验证读写 → 可用。

当前项目知识建立：空知识列表 → 整理项目 → 明确绑定与Token消耗 → 选择是否同时整理历史会话 → 用户启动 → 保存带出处的知识 → 建立索引 → 查看知识。已有知识不显示空态大按钮，二级菜单保留补充；知识与原始记录分开展示，记忆为总称。当前任务通过「查看整理进度」恢复。动画跟随真实阶段，取消／失败不播放成功。名称、空态和会话选项按已认可的 [C revision 7 交接](ui-redesign/c-agent-handoff.md) 实施，真实 Agent 启动和历史会话读取待验证。

旧 P3-I 受控导入的历史实现：用户明确选择项目、已验证连接、工作目录和1–16个文件，客户端准备最多128KiB的冻结SHA256/原文快照并复制prompt。用户到自己的Agent执行，初始化工具只查询已批准材料/状态并提交新增项，服务原子校验具体文件版本/精确摘录、项目内稳定ID、连接代次与工作区。取消/过期拒绝迟到提交，复制仍等待实际回执；整批重放不重复导入，重复既有ID不覆盖。导入单列，不补造历史日期，也不计当天新知识；保存/索引分开。已准备来源和导入出处保留，普通新增/连接不被可选初始化阻塞。正式契约见 [I契约](p3-onboarding-contract.md)。

### 手动新增与编辑

用户输入 → 保存当前正文和版本记录 → 建立检索索引 → 显示可用。

保存成功与可检索分开显示。手动内容标明用户确认；自动整理可以补标签和提出修改建议，覆盖正文需确认。恢复旧版本会产生一个新的当前版本，保留完整修改历史。

### 整理

手动点击／计划触发 → 按项目选取新增或改动内容及相关旧知识 → 提炼、归类、提出清理建议 → 允许自动执行的内容落库 → 其他建议等待确认 → 记录实际执行结果。

用户直接编辑与 AI 提议的修改区分：前者由用户的保存动作生效，后者遵守待确认规则。计划运行与手动运行共用同一套规则和历史。

### 全局经验

在项目知识详情中选择「AI 提炼为全局经验」或「原文复制到全局」；新建全局条目，关联原项目记录。AI 提炼需要预览确认。检索时保留适用条件；项目的明确约定优先。

### 代码图谱

2026-11-09，用户确认首版隐藏入口。以下为保留的原设计，不作为首版可见流程；隐藏入口不会删除已有代码索引或调整既有任务。

关联仓库 → 用户手动启用 → 建立索引 → 后续变化自动更新。

显示索引状态和最后成功更新时间。搜索结果围绕函数、文件、调用关系、依赖和影响范围展示。影响结果作为排查参考，不承诺覆盖所有运行时行为。第一版不要求完整可缩放的全仓库图谱画布。

### 故障与退出

- 窗口关闭、界面退出、后台服务停止是三个需要明确表达的状态。
- 用户允许保留服务时，界面退出后服务仍运行；明确停止时，守护机制也停止拉起。
- 服务意外停止时有限重试；连续失败停止循环并提供诊断。
- 已接收但未送达的写入需要独立于 Cognee 进程的持久队列；补发以记录标识去重。
- 整理中断保留已提交结果，未完成部分可追踪、可重试。
- 服务不可用时，Agent 接口返回明确错误，不能伪装成空搜索结果。
- 进程恢复不能代替数据损坏修复或备份恢复。
