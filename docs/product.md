# Memlane：第一版产品定义与信息架构

范围于 2026-11-07 确认。首页增加 GitHub 贡献日历风格的每日记忆热力图，本轮产品访谈收口。

同日补充分发要求：优先缩小用户下载的主安装包，主客户端提供 UI、自动更新和组件管理等轻量能力；本地引擎与模型由 App 自动准备。该要求约束分发方式，现有记忆功能继续按本文范围实现。

这是一个面向程序员的 macOS 桌面记忆客户端：多个编码 Agent 共用项目知识，减少重复交代背景。使用 Cognee 作为记忆引擎，把主要精力放在好看、简单和方便管理上。这是练手的 side project。

本文中的「已确定」代表产品决策得到确认，不代表底层接口已经完成接入验证。当前 P0 客户端/服务/组件链路和 P1 手动记忆管理/实际窗口设计对照已通过；P2 已通过隔离配置下真实 Codex 保存 → App 编辑 → pi 读取当前版本，以及 App Agent 管理与系统窗口对照。未覆盖真实 Agent 的用户配置或导入聊天。实际能力见 [P0](p0-validation.md)、[P1](p1-validation.md) 和 [P2 验证记录](p2-validation.md)。

2026-11-08：P3-C1 正式服务和 [C2 App 手动合并审核](p3-c2-validation.md) 已通过。C3/C4 完整手动整理、E 全局经验与 [D1 持久计划](p3-schedule-validation.md) 已通过；D2a 租约/进程保护与D2b有限自动恢复见 [验证](p3-recovery-validation.md)；[U使用记录与排序](p3-usage-validation.md)已通过；[I 引导与初始化](p3-onboarding-validation.md)本机已通过；[A1a traex日常接入](p3-agent-validation.md)已通过；Codex新工具与TRAE IDE、pi RPC、代码图谱与正式分发继续按 [交付矩阵](p3-delivery-plan.md) 推进；本机技术通过不代表正式分发完成。

2026-11-07 本轮工程验证按用户最新要求以主流程走通收口：P0 核心链路、后台更新和体积数据已通过；旁白等旁支停止并保留未通过结果。P1 手动记忆管理及 P2 Codex/pi 互通已实现；整理、代码图谱与其余 Agent 按实施清单继续，不把原型示例当成接入成果。

视觉方案已选定：采用V3 首页设计稿的浅色风格。首页保留宽幅总览，不使用三栏；记忆、Agent、整理记录等列表与详情页采用三栏。此前深灰玻璃方案保留作探索记录，不继续作为主方案。最新 [浅色交互原型](https://github.com/zwhu/memlane/tree/prototype/selected-ui/prototypes/selected-ui) 使用栏内详情和操作。

2026-11-08 接入产品梳理：当前优先完善四种本地 Agent 的自动发现与连接说明，复用已实现的增量配置和受控记忆桥接。安装升级与剩余工程验收暂缓；本期流程、Cognee 复用依据和真实发现边界见 [Agent 接入](agent-integrations.md)。

## 1. 已确定的产品规则

| 领域 | 第一版决定 |
| --- | --- |
| 首页 | 全局总览，以最近积累的知识、待确认的整理建议为主；Agent 和服务状态处于次要位置 |
| 每日记忆 | 用类似 GitHub 提交日历的热力图，展示每天产生多少记忆 |
| 默认内容 | 主要展示整理后的知识，每条都能追溯原始记录；未整理内容单独显示 |
| 接收原则 | 遵循 Cognee skill 和 Agent 的实际提交；Agent 存什么就接收，不由客户端先做重要性筛选 |
| 手动新增 | 用户输入视为用户确认的知识，保存并建立索引后可被检索，不必等待定期整理 |
| 操作名称 | 「立即整理」由用户触发 AI 整理；「编辑」由用户亲自改知识 |
| 整理内容 | 提炼、清理、归类都需要；包括摘要、标签、重复与冲突的处理建议 |
| 自动执行 | 新增摘要、添加标签可以自动完成 |
| 待确认执行 | AI 提出的合并、覆盖、删除、跨项目移动需用户确认；确认前不改变已有有效知识 |
| 定期整理 | 用户自行设置运行频率，同时保留「立即整理」 |
| 编辑与整理历史 | 每次编辑、每次整理都记录；可以查看修改差异，恢复单条知识的旧版本；恢复也产生一条新记录 |
| 项目 | 一个项目对应一个代码仓库，多个 Agent 共用这个项目的记忆 |
| 检索范围 | 默认当前项目＋全局个人偏好＋全局经验；其他项目需要明确指定 |
| 冲突优先级 | 同一事项上，当前项目的明确约定优先于全局建议；保留两者的来源与适用范围 |
| 全局经验 | 支持「AI 提炼为通用表述，预览确认后保存」和「原文复制」两条路径；保留原项目记录、来源关联及历史 |
| 全局经验建议 | 整理时可以发现候选经验，列入待确认；全局经验保留适用条件 |
| 代码图谱 | 手动启用一次，之后自动更新；用户和 Agent 都可以搜索函数、文件，查看调用、依赖和可能影响范围 |
| 首批 Agent | 目标接入 Codex、pi、TRAE、traex；适配能力逐一验证 |
| 整理执行者 | 第一版统一指定一个具备后台执行能力的 Agent；以后再支持按项目指定 |
| 初始化 | 可跳过/恢复的指引；选择项目、已验证连接和明确文件，复制 prompt 到自己 Agent 执行；持久批次/具体版本来源/稳定ID/实际提交/索引状态，复制不等于成功 |
| 关闭窗口 | 收起到菜单栏，后台记忆服务继续运行 |
| 退出 App | 「退出 App 后继续运行记忆服务」默认开启，可关闭；始终保留明确的「停止服务并退出」 |
| 服务异常 | 意外退出自动尝试恢复；未送达写入本地暂存，恢复后补发；读取失败与无结果区分；持续失败给出诊断入口 |
| 主动停止 | 用户主动停止服务时，不触发故障自动重启 |
| 下载与首次准备 | 主安装包保持轻量；本地引擎、原生依赖和模型独立下载，由 App 自动准备，展示下载大小、进度和失败重试；用户无须手工安装依赖 |
| 自动更新 | 主客户端具备自动更新能力；客户端、引擎与模型按兼容版本分别管理，更新 UI 时复用未变化的组件和模型，保留用户知识与设置 |
| 平台与风格 | 第一版 macOS；紧凑、克制、单色图标和按钮、白色内容区、完整连续的浅蓝侧边栏 |
| 页面布局 | 首页是侧边栏＋宽幅总览；列表详情页是导航—列表—详情与操作三栏；侧边栏覆盖顶部窗口控制区并与正文边界连续对齐 |
| 交互承载 | 查看、新增、编辑、历史、整理结果和建议确认在右栏完成；不把普通操作随意做成弹框 |

## 2. 信息架构

```text
主窗口
├─ 总览（首页）
│  ├─ 每日记忆热力图
│  ├─ 最近新增／选定日期的知识
│  ├─ 待确认的整理建议
│  └─ 整理计划与运行状态
├─ 全部记忆
│  ├─ 知识列表（可按项目、来源、类别、时间筛选）
│  ├─ 未整理的记录
│  └─ 知识详情
│     ├─ 当前内容、范围、来源
│     ├─ 原始记录
│     ├─ 编辑、提取为全局经验
│     └─ 历史、差异、恢复版本
├─ 全局记忆
│  ├─ 个人偏好
│  └─ 通用经验
├─ Agent
│  ├─ 自动发现／手动添加
│  ├─ 连接、验证、范围管理
│  └─ 初始化记忆库（复制 prompt）
├─ 整理记录
│  ├─ 手动／定期整理的执行记录
│  ├─ 本次新增、已执行修改、待确认建议
│  └─ 建议处理结果、失败与重试
├─ 项目
│  └─ 每个仓库
│     ├─ 记忆
│     ├─ 代码图谱
│     └─ 项目设置
└─ 设置
   ├─ 整理 Agent
   ├─ 定期整理计划
   ├─ 本地数据与服务状态
   ├─ 退出及后台运行
   └─ 关于与诊断
```

侧边栏切换范围和页面。首页保留宽幅总览：每日热力图在上，最近新增和待确认建议在下，不额外拆成三个固定栏。点击记忆后进入「导航—列表—详情与操作」三栏页面；点击整理建议或立即整理后进入整理记录页，在右栏查看与处理。新增、编辑、历史记录、整理结果和建议确认使用右栏，保留中间列表与选中上下文。普通操作不使用模态弹框；需要确认的修改优先在当前栏内明确展示内容和确认按钮。代码图谱入口归属具体项目，避免用户在多个仓库之间混淆。

首次打开仍直接进入主界面，不要求注册客户端账户。空首页展示已发现的 Agent、连接入口、添加本地项目和初始化入口。有数据后显示正常总览。连接状态必须区分已发现、待连接、待重载、可用和异常。

缺少本地组件时，主界面仍可打开，栏内显示准备进度与重试入口；需要索引或模型的能力显示准备中。已经由业务服务持久化的内容可以显示已保存，但组件尚未就绪时不能显示为可检索或 Agent 已可用。首次离线且没有组件缓存时明确说明需要联网准备；准备完成后的本地索引与检索支持离线使用。主安装包大小、首次准备的额外下载量、最终磁盘占用分别统计，具体体积上限尚未确定。

## 3. 首页热力图

用户确认的要求：像 GitHub 提交记录一样，能看到每天产生多少记忆。

以下是本次原型采用的默认细节，后续可在视觉和接口验证中调整：

- 默认展示最近一年，按本机日期划分；每个格子代表一天，颜色深浅代表数量。
- 悬停显示日期和新增数量，点击某天查看当天新增的知识。
- 统计单位是独立的知识条目，不是对话轮次、图谱节点或检索命中数。
- 手动新增、Agent 直接保存的知识、整理产生的新知识，在首次可用时计一次；等待确认的建议不计入。
- 原始对话、工具轨迹和作为出处的片段不计入；编辑、恢复版本、重复同步和整理任务本身不增加数量。
- 把项目经验提炼或复制成一条独立全局知识，算新增；单纯移动已有条目不算新增。
- 初始化导入已有记忆单独显示导入数量，不回填未经核实的历史日期；默认不把批量搬入的旧记忆计作当天新产生的知识。
- 历史活动按创建事件记录。之后删除或合并条目时保留活动事实，并在日期详情中标明现状。
- 热力图使用克制的浅蓝色阶表达数据；图标、按钮、普通状态继续保持单色。

原型中的统计和记录均为示例数据，不能视为四款 Agent 已经完成真实接入。

## 4. 关键流程

### Agent 接入与初始化

发现本地 Agent → 用户连接 → 配置共享记忆接入 → 实际验证读写 → 可用。

初始化是独立可选入口：用户明确选择项目、已验证连接、工作目录和1–16个文件，客户端准备最多128KiB的冻结SHA256/原文快照并复制prompt。用户到自己的Agent执行，初始化工具只查询已批准材料/状态并提交新增项，服务原子校验具体文件版本/精确摘录、项目内稳定ID、连接代次与工作区。取消/过期拒绝迟到提交，复制仍等待实际回执；整批重放不重复导入，重复既有ID不覆盖。导入单列，不补造历史日期，也不计当天新知识；保存/索引分开。已准备来源和导入出处保留，普通新增/连接不被可选初始化阻塞。正式契约见 [I契约](p3-onboarding-contract.md)。

### 手动新增与编辑

用户输入 → 保存当前正文和版本记录 → 建立检索索引 → 显示可用。

保存成功与可检索分开显示。手动内容标明用户确认；自动整理可以补标签和提出修改建议，覆盖正文需确认。恢复旧版本会产生一个新的当前版本，保留完整修改历史。

### 整理

手动点击／计划触发 → 按项目选取新增或改动内容及相关旧知识 → 提炼、归类、提出清理建议 → 允许自动执行的内容落库 → 其他建议等待确认 → 记录实际执行结果。

用户直接编辑与 AI 提议的修改区分：前者由用户的保存动作生效，后者遵守待确认规则。计划运行与手动运行共用同一套规则和历史。

### 全局经验

在项目知识详情中选择「AI 提炼为全局经验」或「原文复制到全局」；新建全局条目，关联原项目记录。AI 提炼需要预览确认。检索时保留适用条件；项目的明确约定优先。

### 代码图谱

关联仓库 → 用户手动启用 → 建立索引 → 后续变化自动更新。

显示索引状态和最后成功更新时间。搜索结果围绕函数、文件、调用关系、依赖和影响范围展示。影响结果作为排查参考，不承诺覆盖所有运行时行为。第一版不要求完整可缩放的全仓库图谱画布。

### 故障与退出

- 窗口关闭、界面退出、后台服务停止是三个需要明确表达的状态。
- 用户允许保留服务时，界面退出后服务仍运行；明确停止时，守护机制也停止拉起。
- 服务意外停止时有限重试；连续失败停止循环并提供诊断。
- 已接收但未送达的写入需要独立于 Cognee 进程的持久队列；补发以记录标识去重。
- 整理中断保留已提交结果，未完成部分可追踪、可重试。
- 服务不可用时，Agent 接口返回明确错误，不能伪装成空搜索结果。
- 进程恢复不能代替数据损坏修复或备份恢复。

## 5. Cognee 对应能力与待验证事项

本轮核对了官方源码和文档，未完成以下产品链路的实机验证。具体版本、配置和适配接口需要在技术方案阶段固定。

下表的接口证据主要来自 Python Cognee；官方另有 [Cognee-RS](research-cognee-rust.md)。选择 Cognee 作为记忆引擎不等于已选定 Python 实现，Rust 与 Python 按同一产品规则验证，不能把一侧的接口或功能视为另一侧已通过验收。

| 产品需求 | 可复用基础 | 产品侧仍需落实 |
| --- | --- | --- |
| 保存、检索、更新、删除 | [官方 skill](https://github.com/topoteretes/cognee/blob/main/cognee/skill.md) 中的 `remember`、`recall`、`update`、`forget` | 原始记录和知识条目的映射、状态处理 |
| 项目与范围 | Dataset、[数据元信息](https://github.com/topoteretes/cognee/blob/main/cognee/api/v1/datasets/dto.py)、[权限接口](https://github.com/topoteretes/cognee/blob/main/cognee/api/v1/permissions/routers/get_permissions_router.py) | 仓库映射、当前项目识别、全局经验检索、身份和权限落实 |
| 整理 | [`improve`](https://github.com/topoteretes/cognee/blob/main/cognee/api/v1/improve/improve.py) 的会话提炼、偏好和冲突相关步骤 | 逐项核对写入副作用，确保待确认改动在确认前不生效；自定义分类及清理流程 |
| 手动知识立即可用 | 原文入库、[文本索引和片段检索](https://github.com/topoteretes/cognee/blob/main/cognee/api/v1/cognify/cognify.py) | 当前版本映射、用户确认标记、接入端返回原文及正确范围 |
| 版本与整理历史 | 已有操作状态可作参考 | 完整前后版本、建议审批记录、单条恢复与当前索引一致性 |
| 代码图谱 | [仓库索引、结构查询、重新索引](https://github.com/topoteretes/cognee-integrations/blob/main/integrations/claude-code/skills/cognee-code/SKILL.md) | 适配所选版本；手动启用开关必须约束插件已有自动索引行为 |

| 每日记忆热力图 | 客户端知识创建事件 | 稳定标识、去重、日期口径、初始化导入与日常新增的区分 |
